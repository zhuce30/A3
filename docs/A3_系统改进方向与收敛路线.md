# A3 系统改进方向与收敛路线

本文档用于记录当前 A3“智学引擎”后续改进方向。目标不是继续堆页面或静态内容，而是把系统收敛成一条清晰、可演示、可验证的学习软件主线：围绕一门完整高校课程，完成画像、诊断、路径、计划、今日任务、知识库、资源生成、辅导、测评、报告和教师干预闭环。

## 1. 课程主线不统一

### 当前问题

系统架构本身是通用的，但当前 demo 数据、知识图谱、诊断、计划、推荐中仍混有“自动控制原理”的内容。如果后续切换为“计算机网络原理”，不能只改页面标题，否则会出现页面显示计算机网络、底层知识点和图谱仍是自动控制的割裂问题。

### 改进目标

把系统默认演示主线统一切换为“计算机网络原理”，让学生端、教师端和真实学习流程都围绕同一门课运行。能力页和 demo flow 只作为开发验收、自检和技术追问证据，不作为评委理解产品的主入口。

### 可执行任务

- 替换课程章节、知识点和先修关系。
- 替换入学诊断题、测评题、错题样例。
- 替换学习路径、7/14/30 天计划、今日任务种子数据。
- 替换资源推荐主题和资源生成默认提示词。
- 上传或构造计算机网络课程资料，重建资料知识图谱。
- 清理或隔离旧自动控制演示资料，避免出现在默认演示账号中。
- 更新真实学习页面、demo flow 和能力页中的课程断言。真实页面优先，demo flow 和能力页只做验证证据。

### 验收标准

- 默认演示账号中不再出现“根轨迹、闭环极点、传递函数”等自动控制主线内容。
- `/a3/today`、`/a3/study-plan`、`/a3/learning-path`、`/a3/knowledge-graph`、`/a3/recommendations` 均展示计算机网络相关内容。
- `validate_demo_flow --skip-seed --strict` 能验证计算机网络课程闭环。

## 2. 多智能体可解释证据不足

### 当前问题

系统已经具备 AgentKernel、workflow、trace、schema version 和降级记录，但答辩视角下还需要更直观地证明多智能体确实在协作，而不是文档中写了多个 agent 名称。

这里的问题与 `docs/superpowers/plans/2026-07-06-agent-spec-tool-registry-trace.md` 是同一条主线，但层级不同：

- `2026-07-06-agent-spec-tool-registry-trace.md` 解决底层工程证据：AgentSpec、ToolRegistry、PromptRegistry、AgentSpan、provider/tool nested spans、schema version、prompt hash、fallback metadata。
- 本节解决答辩展示证据：评委能否在真实业务页面中自然看懂系统为什么这样推荐、哪个 agent 参与了处理、输出了什么结构化结果、失败时如何降级，以及多个 agent 如何共同生成一个资源包。能力页只用于追问完整 trace。

因此后续实施时不能只做 trace 存储，也不能只做单独的展示页。正确顺序是：先把底层 agent/runtime/tool/provider 证据打牢，再把轻量证据嵌入真实业务页面，把完整 trace 留给能力页追问。

### 改进目标

让真实业务页面能自然展示多智能体协作结果：每个关键学习动作背后由哪个 agent 处理、为什么这样推荐、输出了什么结构化结果、失败时如何降级。能力页和 demo flow 只用于开发验收和技术追问，不承担主演示入口。

### 与 AgentSpec ToolRegistry Trace 计划的对应关系

| 本节答辩问题 | 对应工程底座 | 需要额外补的展示能力 |
|---|---|---|
| 哪个 agent 接收了什么输入 | AgentSpec.input_schema、AgentStep.metadata、AgentSpan.inputSummary | 真实页面展示中文输入摘要，能力页展示完整 trace，隐藏隐私和原始 prompt |
| 输出了什么结构化结果 | AgentSpec.output_schema、AgentStep.output、schemaVersion | 展示输出 JSON 摘要、资源类型、关键字段完整性 |
| 失败时怎么降级 | AgentSpec.fallback、ToolRegistry fallbackReason、span.status | 用中文说明降级原因、影响范围和替代结果 |
| 多个 agent 如何协作 | AgentKernel workflow、AgentStep sequence、nested spans | trace waterfall / timeline 可视化 |
| 资源包里的内容由谁生成 | resource pack artifact + AgentStep/Span 关联 | 在资源详情页显示“生成 agent、工具、耗时、验证状态” |
| 使用了哪些外部能力 | ToolRegistry、LLM/RAG/VLM/OCR/realtime spans | 展示 provider 类型、模型、耗时、token、是否降级 |

### 可执行任务

#### A. 先完成工程底座

- 执行 `docs/superpowers/plans/2026-07-06-agent-spec-tool-registry-trace.md` 中 Task 1-3：`AgentSpan`、`AgentSpec`、`ToolRegistry`。
- 为核心 agent 补齐 `role`、`promptVersion`、`inputSchema`、`outputSchema`、`allowedTools`、`timeoutMs`、`maxRetries`、`fallback`。
- 将 RAG、Verifier、QuestionGenerator、LLM 调用迁移到 ToolRegistry，并记录 nested span。
- 将 OCR、VLM、visual embedding、realtime provider 调用记录为 provider span。
- Trace 导出只包含 promptId、promptVersion、promptHash、输入输出摘要，不暴露 raw prompt、API key、signed URL、本地绝对路径。

#### B. 再把证据嵌入真实业务页面

- 画像页：展示 ProfileAgent 从对话中抽取出的画像字段、置信度和可编辑项。
- 诊断页：展示 DiagnosticAgent 输出的 level、weakPoints、nextAction，以及路径调整原因。
- 学习计划页：展示 PlannerAgent / StudyPlanAgent 为什么这样安排路径、周期计划和今日任务。
- 今日学习页：展示完成任务后写回了哪些对象，例如 path progress、plan progress、report insight。
- 资源中心：展示讲解文档、练习题、视频脚本、代码实验、拓展阅读分别由哪个 agent 生成。
- 资源包详情页：显示每个 artifact 的生成 agent、traceId、schemaVersion、verified、citations、fallbackReason。
- 知识库页：展示 RetrieverAgent / GraphExtractionAgent 的来源证据、图谱构建状态和降级原因。
- AI 学习/辅导页：展示 RetrieverAgent、TeacherAgent、VerifierAgent、SafetyAgent 的协作结果，重点是引用和验证状态。
- 测评/练习复盘页：展示 AssessmentAgent 的判分、错因、错题写回和复习队列。
- 报告页：展示 ReportAgent 的下一步行动建议，以及建议来自哪些学习数据。
- 教师工作台：展示 TeacherWorkbenchAgent 如何生成干预任务，任务如何写回学生通知和今日任务。

#### C. 能力页和 demo flow 的降级定位

- `/a3/capabilities` 保留为技术证据页，用于评委追问“你们的 agent trace 在哪里、schema 在哪里、降级证据在哪里”时打开。
- `/a3/demo-flow` 保留为开发验收/回归页，用于自动检查闭环是否跑通，不作为主演示页面。
- 如果后续做“答辩中心”，也只能作为备用证据入口，不能替代真实学生流程。
- 在 `/a3/capabilities` 中按 workflow 过滤 trace waterfall，默认展示最近真实页面触发的 workflow，而不是孤立演示数据。
- trace waterfall 视图结构为：真实页面动作 -> workflow -> agent step -> tool/provider span。
- 补充失败降级案例，例如无视频 provider key 时如何记录 failed/degraded artifact，但展示入口应优先出现在资源中心和资源包详情页。

#### C. 重点覆盖的 workflow

- `profile_interview`：证明画像不是表单硬编码，而是由 ProfileAgent 从对话中抽取并更新。
- `diagnostic_assessment`：证明诊断结果会输出 level、weakPoints、nextAction。
- `learning_path_plan`：证明路径和计划由 PlannerAgent / StudyPlanAgent 基于画像、诊断和先修关系生成。
- `resource_generate`：证明至少 5 类资源由多个 agent 协作生成。
- `qa_interact` / `coaching`：证明 RetrieverAgent、TeacherAgent、VerifierAgent、SafetyAgent 协作完成有引用的辅导回答。
- `material_knowledge_graph`：证明资料图谱来自真实知识库解析、抽取和持久化 workflow。
- `assessment_review`：证明测评结果会写回错题、画像弱点和复习队列。

### 验收标准

- 技术追问时可以打开能力页，筛选 `resource_generate` workflow，看到完整 agent 协作链路。
- 每个核心 agent 输出都有 `outputSchema`、`schemaVersion`、`status`、`latencyMs` 和 `degradation` 信息。
- 无 key、超时或 provider 失败时，页面显示明确降级证据，不伪造成成功。
- Trace waterfall 至少能展示三层结构：workflow、agent step、tool/provider span。
- 资源包详情能回答“这个文档/题目/视频脚本/代码实验由哪个 agent 生成，引用了什么资料，是否验证，是否降级”。
- `/api/demo/status/` 暴露 agent architecture maturity：AgentSpec 覆盖率、ToolRegistry 覆盖率、nested span 数、prompt version 覆盖率、最近 traceId。
- trace 导出和前端页面不暴露 API key、raw prompt、signed URL、本地绝对路径。
- 主演示不依赖 `/a3/demo-flow` 或 `/a3/capabilities`。评委从学生登录开始操作真实页面，也能看懂每一步发生了什么。

## 3. 个性化资源生成类型需要产品化

### 当前问题

赛题要求不同角色智能体协作完成至少 5 种个性化资源生成。当前系统覆盖了多类资源，但部分类型还不够独立、稳定和可证据化，尤其“代码类实操案例”不应只藏在 `case_study` 中。

### 改进目标

形成清晰的资源类型体系，并在前端、后端、agent trace、资源包详情中统一展示。

### 建议资源类型

- `lecture_doc`：专业课程讲解文档。
- `mind_map`：知识点思维导图。
- `practice_set`：不同类型练习题。
- `extended_reading`：拓展阅读材料。
- `micro_video_script`：多模态教学视频/动画脚本。
- `code_lab`：代码类实操案例。
- `project_task`：实践项目学习材料。

### 计算机网络方向示例

- Python Socket TCP/UDP 通信实验。
- HTTP 请求与响应报文分析。
- DNS 查询与递归解析过程实验。
- 子网划分与 CIDR 计算练习。
- TCP 三次握手和拥塞控制动画脚本。
- Wireshark 报文抓取与分析任务。

### 验收标准

- 资源生成接口能返回至少 5 种资源类型。
- `code_lab` 作为独立类型出现，并包含目标、步骤、代码、运行说明和检查点。
- `/a3/resources/[packId]` 能展示资源类型、生成 agent、引用来源和 artifact 历史。

## 4. 知识图谱需要更有学习价值

### 当前问题

资料知识图谱已经不是纯静态图，但还存在 PPT 抽取质量不稳定、公式和符号清洗不完整、节点类型偏粗、证据片段过长或重复、图谱和学习路径联动不足等问题。

### 改进目标

让知识图谱从“能显示节点关系”升级为“能帮助学生学习和行动”的知识导航工具。

### 可执行任务

- 继续增强 PPTX 解析：标题、文本框、项目符号、表格、图片说明、备注分块入库。
- 对公式、表格、符号、Markdown 做后端派生清洗，同时保留原始文本。
- 优化图谱节点类型：Concept、Protocol、Layer、Algorithm、Metric、Tool、Lab、Formula。
- 限制证据片段长度，去重重复片段。
- 节点详情增加“下一步学习”“生成练习”“进入辅导”“加入今日任务”等动作。
- 将资料图谱节点和学习路径知识点建立映射。

### 验收标准

- 学生点击一个图谱节点，可以看到定义、来源页码、关联节点、推荐学习动作。
- 资料图谱来源能追溯到知识库资源、页码、块类型和证据片段。
- 默认计算机网络资料能生成真实实体关系，例如 TCP、UDP、IP、DNS、HTTP、子网划分、路由协议。

## 5. 学习闭环需要更像真实学习软件

### 当前问题

系统已经具备今日任务、学习计划、学习路径、报告、错题本等模块，但还需要更强的因果关系和数据回流。评委需要看到学生行为如何真正影响路径、计划、推荐和报告。

当前最大的风险是：页面之间“看起来相关”，但评委追问时不一定能证明某个学生动作真的改变了后续学习安排。学习软件的可信度来自闭环证据，而不是页面数量。

需要重点证明以下 6 条链路：

- 诊断结果如何改变路径。
- 完成今日任务如何改变计划进度。
- 错题如何进入复习队列。
- 报告如何给出下一步行动建议。
- 推荐资源如何根据薄弱点刷新。
- 教师推送如何影响学生今日任务。

### 改进目标

打通“诊断 -> 路径 -> 计划 -> 今日任务 -> 完成反馈 -> 测评 -> 错题 -> 复习 -> 报告 -> 推荐刷新”的闭环。

闭环不只要求页面跳转，也不应该依赖单独的演示页解释。每个关键动作都要在真实业务页面里完成，并具备：

- 前端按钮入口。
- 后端真实接口。
- 数据库写回。
- 后续页面可见变化。
- 自动测试、按钮级巡检或 demo flow 可复现验证。demo flow 只作为开发验收工具，不作为主演示页面。

### 六条核心闭环链路

#### 1. 诊断结果改变学习路径

目标：学生完成入学诊断后，系统不只是显示分数，而是写回画像弱点，并重新生成学习路径和学习计划。

建议数据流：

```text
/a3/admission-diagnostic 提交答案
-> POST /api/assessments/admission/submit/
-> DiagnosticAgent 输出 score、level、weakPoints、nextAction
-> ProfileAgent 写回 weakPoints / mastery
-> PlannerAgent 重排 learning path
-> StudyPlanAgent 重排 7/14/30 天计划
-> /a3/today 展示新的今日任务
```

需要页面证据：

- 诊断完成页展示“本次诊断发现的薄弱点”。
- 学习路径页标出“由诊断刷新”的节点。
- 学习计划页展示“调整原因”。
- 今日学习页展示新的优先任务。

验收标准：

- 同一个演示账号完成诊断前后，`weakPoints`、学习路径当前节点、今日任务至少一项发生变化。
- 真实诊断完成页输出 traceId、写回画像字段、重排计划 schema version；demo flow 只做回归断言。

#### 2. 今日任务完成改变计划进度

目标：学生完成今日任务后，计划完成度、路径节点掌握度和报告指标同步变化。

建议数据流：

```text
/a3/today 点击完成任务
-> POST /api/learning/tasks/<task_id>/complete/
-> 写入 task completion
-> 更新 StudyPlanDay.progress
-> 更新 LearningPathNode.progress/mastery
-> 生成报告 insight / notification
-> /a3/study-plan、/a3/learning-path、/a3/report 可见变化
```

需要页面证据：

- 今日学习页显示完成反馈和下一步按钮。
- 学习计划页当天任务变为已完成。
- 学习路径对应节点进度提升。
- 报告页新增“今日完成影响”或计划完成度变化。

验收标准：

- 按钮级巡检能从 `/a3/today` 完成任务后跳到 `/a3/study-plan` 和 `/a3/report`，看到同一任务的写回结果。
- 不能只在前端本地改变状态，刷新页面后结果仍应存在。

#### 3. 错题进入复习队列

目标：测评错题不只是出现在错题列表，还要进入间隔复习队列，并影响画像和推荐。

建议数据流：

```text
/a3/assessment 提交答案
-> POST /api/assessments/sessions/<id>/submit/
-> AssessmentAgent 判分
-> 写入 WrongQuestion、errorCause、explanation
-> 更新 weakPoints/mastery
-> 创建 reviewQueue item
-> /a3/wrong-notebook 展示错题和下次复习时间
-> /a3/today 出现复习任务
```

需要页面证据：

- 测评结果页展示错因、解析、关联知识点。
- 错题本展示掌握状态和下次复习时间。
- 今日学习页能出现“复习错题”任务。
- 推荐页根据错题知识点推荐资源。

验收标准：

- 做错一道题后，错题本新增记录，画像弱点变化，今日任务或复习队列出现对应项。
- 测评结果页和错题本展示错题 id、weakPoint 更新、reviewQueue 更新；demo flow 只做回归断言。

#### 4. 报告给出下一步行动建议

目标：报告不是静态总结，而是根据学习数据给出可执行建议，并能跳回今日任务、计划、错题或资源。

建议数据流：

```text
task completion / assessment / wrong notebook / resource usage
-> ReportAgent 汇总
-> 生成 progress、weaknessTrend、planAdherence、nextActions
-> /a3/report 展示趋势和行动建议
-> 点击建议跳转到对应任务或资源
```

需要页面证据：

- 报告页展示“本周进步”“薄弱趋势”“计划完成度”“下一步行动”。
- 行动建议不只是文字，应带按钮和目标页面。
- 建议应引用具体原因，例如“TCP 可靠传输错题 3 次，因此建议复习拥塞控制”。

验收标准：

- 报告行动建议中的每个按钮都有真实 href 或 API action。
- 至少一条建议能追溯到测评结果、错题、计划进度或资源使用记录。

#### 5. 推荐资源根据薄弱点刷新

目标：推荐资源不是固定列表，而是基于画像、诊断、路径、错题、知识库证据动态排序。

建议数据流：

```text
profile weakPoints + diagnostic level + path currentNode + wrongQuestions + kb sources
-> RecommendAgent
-> 输出 recommendation reason、score、source、targetKnowledgePoint
-> /a3/recommendations 展示排序理由
-> 生成 resource pack
```

需要页面证据：

- 推荐卡片展示“为什么推荐给你”。
- 展示匹配分或排序依据。
- 标注关联薄弱点和来源资料。
- 完成测评或诊断后，推荐列表能刷新。

验收标准：

- 改变学生 weakPoints 后，推荐排序或推荐理由发生变化。
- 推荐结果包含 `reason`、`score`、`source` 或 `rankingBasis`，不能只有通用资源标题。

#### 6. 教师推送影响学生今日任务

目标：教师端不是只看数据，还能推送任务，学生端收到通知并进入今日任务。

建议数据流：

```text
/a3/teacher 选择学生和干预任务
-> POST /api/learning/teacher/tasks/execute/
-> TeacherWorkbenchAgent 生成 task payload
-> 写入 StudentTask / Notification
-> /a3/notifications 收到提醒
-> /a3/today 出现教师推送任务
```

需要页面证据：

- 教师端能看到风险学生、薄弱点、建议干预。
- 教师点击推送后显示成功反馈。
- 学生通知中心出现对应消息。
- 今日学习页出现教师推送任务，并标记来源。

验收标准：

- 教师端推送后，学生刷新今日学习页能看到同一任务。
- 教师端、通知中心和今日学习页能展示 teacher task id、notification id、student task id 的关联证据；demo flow 只做回归断言。

### 可执行任务

- 诊断结果写回画像弱点，并触发学习路径刷新。
- 今日任务完成后写回路径节点进度、计划完成度和报告指标。
- 测评判分后写入错题本、错因、掌握度和复习队列。
- 报告页展示本周进步、薄弱趋势、计划完成度和下一步建议。
- 推荐页根据薄弱点、路径节点、知识库资料动态刷新资源。
- 教师推送任务后，学生通知和今日任务能收到对应任务。
- 给以上 6 条链路补真实页面上的 traceId、写回摘要和下一步动作。
- 给以上 6 条链路补按钮级巡检脚本或 Playwright 场景。
- 在真实页面内展示闭环状态，例如诊断完成页、今日学习页、测评结果页、报告页、教师端。
- 在 `/a3/capabilities` 或 `/a3/demo-flow` 仅保留闭环状态汇总，用于开发验收和追问。

### 建议新增闭环状态表

优先在真实页面展示，能力页或 demo flow 只汇总：

| 闭环链路 | 触发按钮 | 写回对象 | 后续页面 | 验证证据 |
|---|---|---|---|---|
| 诊断刷新路径 | 提交诊断 | Profile、LearningPath、StudyPlan | 今日学习、学习计划 | diagnostic traceId |
| 今日任务完成 | 完成任务 | TaskCompletion、PathProgress、ReportInsight | 学习计划、报告 | taskId、planDayId |
| 错题复习 | 提交测评 | WrongQuestion、ReviewQueue、WeakPoint | 错题本、今日学习 | questionId、reviewId |
| 报告建议 | 查看报告 | LearningReport.nextActions | 今日学习、错题本、资源中心 | reportId |
| 推荐刷新 | 重新推荐 | ResourceRecommendation、ResourcePack | 资源中心 | recommendationRunId |
| 教师推送 | 推送任务 | TeacherTask、Notification、StudentTask | 通知、今日学习 | teacherTaskId |

### 验收标准

- 完成一个今日任务后，学习路径和报告能看到变化。
- 做错一道测评题后，错题本、画像弱点和推荐资源同步更新。
- 从学生登录开始操作真实页面，能完成至少一条完整学习闭环。
- 六条核心链路至少四条能通过按钮级巡检验证。
- 真实页面至少展示或可追踪 6 个关键 id：diagnosticRunId、pathId、taskId、wrongQuestionId、recommendationRunId、teacherTaskId。demo flow 只做自动验收。
- 刷新页面后闭环结果仍存在，不能只依赖前端临时状态。
- 每条链路失败时有中文错误提示和可恢复动作，例如“重试提交”“稍后刷新”“查看原始记录”。

## 6. 防幻觉和引用验证需要继续加强

### 当前问题

系统已有 VerifierAgent 和 citation 展示，但教育场景对准确性要求很高。生成内容必须区分教材依据、知识库引用、模型推断和未验证建议。

### 改进目标

所有关键学习内容都要有可追溯证据；没有证据时不能标记为已验证。

### 可执行任务

- 对辅导回答、资源生成、练习解析、报告建议增加 `verified`、`claims`、`citations`、`safety` 字段。
- 引用来源必须能追到资源、页码、块类型和片段。
- 前端明确展示“已验证 / 未验证 / 降级证据”。
- 无知识库证据时，回答应标注为模型推断或建议，不能伪造页码和教材来源。
- 对作弊、隐私、越权、危险内容和不确定内容进行安全过滤。

### 验收标准

- 课堂/辅导回答中有引用证据时显示来源，无证据时不显示“已验证”。
- 资源包详情能展示每个生成资源的引用来源和验证状态。
- 安全测试能覆盖作弊请求、隐私泄露请求和无证据编造引用场景。

## 7. 前端体验需要收敛主任务

### 当前问题

系统页面多、能力多，但部分页面信息密度较高，主任务不够突出；有些文案更像系统说明，不像学生真实使用的学习软件。部分按钮状态、空状态、错误状态和生成中状态还需要统一。

当前 A3 已存在约 29 个一级路由，其中侧边栏直接展示约 20 个入口。学生日常学习、课程资料、资源生成、答辩证据、教师端、设置类入口混在同一层，导致用户和评委都难以判断主线。

需要注意：这里的“合并/删除”不等于删除后端能力。更稳妥的做法是保留深链接和 API，把低频页面从一级导航移除，合并到更少的产品主任务中。

### 改进目标

每个一级菜单都必须代表一个学生能理解的核心学习功能域，而不是简单暴露页面名。一级菜单减少后，隐藏页面不能变成“找不到”，必须在所属一级页面的显眼位置出现，作为 tab、二级菜单、快捷卡片、下一步按钮或顶部动作入口。

学生侧边栏建议固定为 6 个一级入口：

1. 今日学习
2. 学习规划
3. 练习复盘
4. AI 学习
5. 知识库
6. 学习报告

这 6 个入口覆盖 A3 的核心理念：每天执行、长期规划、测评复习、智能辅导与资源生成、本地知识库、阶段报告。教师、开发验收、设置类入口不应和学生日常学习入口混排。

### 一级菜单定位

| 一级菜单 | 核心问题 | 应承载的二级能力 | 不应混入的内容 |
|---|---|---|---|
| 今日学习 | 今天具体学什么，完成后去哪 | 今日任务、教师推送任务、通知提醒、继续课堂、写复盘、查看报告 | 长篇系统看板、开发验收、课程总目录 |
| 学习规划 | 为什么按这个顺序学，几天完成 | 入学诊断、学习路径、学习计划、课程结构、计划重排、画像入口 | 题库刷题、资源包生成、知识库上传 |
| 练习复盘 | 练什么，错在哪里，什么时候复习 | 题库练习、专项测评、错题本、复习队列、变式训练 | AI 课堂、资源生成、资料管理 |
| AI 学习 | 需要 AI 讲解、辅导、生成资源时去哪 | AI 课堂、面对面辅导、个性化推荐、资源包、资源生成、收藏 | 课程目录、错题队列、系统设置 |
| 知识库 | 我的资料如何入库、检索、形成图谱 | 上传资料、资料列表、语义检索、本地知识图谱、解析状态、图谱证据 | 通用资源推荐、教师干预、报告统计 |
| 学习报告 | 学得怎么样，下一步做什么 | 周报、薄弱趋势、计划完成度、资源效果、下一步行动建议 | 每日任务执行、资料上传、开发 trace |

### 关键概念边界

课程学习、学习路径、学习计划不能继续混在一起讲，三者边界应固定：

- **课程学习**：回答“这门课有哪些章节、知识点和先修关系”。它是课程结构，不是个性化安排。
- **学习路径**：回答“对这个学生来说，知识点应该按什么顺序学”。它由画像、诊断、先修关系和薄弱点决定。
- **学习计划**：回答“这些路径节点具体排到哪几天、每天做什么”。它把路径、错题复习、资源包和教师任务落到日期。

因此 `/a3/study-plan` 建议改成“学习规划”功能域，内部至少有 4 个显眼 tab 或二级入口：

```text
入学诊断
学习路径
周期计划
课程结构
```

`/a3/today` 只负责执行今天的任务，不承担解释完整课程结构；`/a3/learning-path` 和 `/a3/courses` 保留深链路，但从侧边栏移除，并在学习规划页显眼露出。

3. 入口文案说明它为什么属于当前功能域。

## 8. 文档和演示材料需要变成评委可读证据

### 当前问题

项目已有不少功能和文档，但最终评审不仅看页面，还看系统设计、技术路线、测试结果和演示表达。需要把系统能力整理成评委容易理解的证据链。

### 改进目标

形成“真实系统页面操作 + 页面内证据 + 能力页 trace + demo flow 回归输出 + 文档 + 演示视频”互相印证的答辩材料。主演示必须从真实学生流程开始，不能让评委先读一个单独的演示闭环页面。

### 可执行任务

- 更新系统架构图、多智能体协作流程图、资源生成链路图。
- 编写计算机网络课程知识库构建说明。
- 编写防幻觉、引用验证和内容安全机制说明。
- 编写测试说明书，列出后端、前端、demo flow、检索评测和按钮级巡检命令。
- 准备 7 分钟以内演示视频脚本，脚本按真实用户操作顺序组织，不以 `/a3/demo-flow` 作为主入口。
- 文档中标注使用的开源项目、AI 工具、协议和用途。
- 如使用 AI Coding 工具，按赛题要求给出说明。

### 验收标准

- 演示 PPT 能清楚展示应用价值、AI 技术融合、多智能体协作、核心功能和创新点。
- 演示视频能在 7 分钟内从登录/画像开始，跑完一条完整学生学习闭环和资源生成链路。
- 文档中有充分数据、流程图、架构图和测试结果支撑。

## 推荐优先级

### 第一优先级：课程收敛

先完成“计算机网络原理课程包迁移”。这是当前最重要的主线工作，能直接解决系统显得混乱的问题。

### 第二优先级：闭环验证

围绕计算机网络跑通一条完整真实产品流程：画像采集、诊断、路径、计划、今日任务、知识库、资源生成、测评、报告。demo flow 只用于自动回归验证这条流程是否仍然可用。

### 第三优先级：答辩证据

把真实业务页面中的轻量证据、能力页 trace、schema version、降级证据、测试结果和文档统一起来，让多智能体能力可看、可解释、可复现。

本脚本用于现场答辩和录屏。目标是在 6 分钟内证明系统不是静态 demo，而是具备画像、诊断、计划、推荐、资源生成、AI 辅导、引用验证、测评、复习、报告、教师干预和评测证据的完整学习闭环。

## 2. 可照读讲稿

开场：

```text
我们做的是 A3 智学引擎，目标不是一次性问答或课件生成器，而是面向学习软件场景的个性化学习资源生成系统。核心闭环是画像采集、入学诊断、学习路径、周期计划、今日任务、知识库检索、资源生成、AI 辅导、引用验证、测评、错题复习、报告提醒和教师干预。
```

资源生成与 OpenMAIC 接入：

```text
这里的 A3 资源包一次生成七类资源：讲解文档、知识卡片、思维导图、练习题、案例、代码实操和短视频脚本。资源包不是只存在前端，它会写入后端，并带有 traceId、引用来源、验证状态和个性化理由。

OpenMAIC 不作为独立产品页面暴露给学生，而是作为 A3 的多模态课堂底座。推荐页负责触发 OpenMAIC 课堂/PPT 和视频任务，资源包详情页展示所有 artifact 历史，课堂页负责打开来自 A3 资源包的 OpenMAIC 课堂，教师页负责查看课堂和视频资源效果，能力页展示 trace、RAG 和页面分工证据。
```

AI 辅导与防幻觉：

```text
AI 课堂回答会先结合当前目标和本地知识库证据生成，再进入 VerifierAgent。只有有证据支持时才标记 verified=true，并展示 citations 和 claims。没有证据时不会伪造教材页码或来源。
```

教师干预：

```text
教师工作台可以看到学生进度、风险、薄弱点、资源包转化和 OpenMAIC artifact 效果。课堂生成成功、视频 provider 未配置或生成失败都会写回资源包，教师端能看到成功和降级统计，并据此下发提醒任务。
```

收尾：

```text
因此，这个系统已经覆盖 A3 赛题要求的个性化画像、资源生成、知识库引用、防幻觉验证、安全过滤、测评闭环和教师管理能力。后续可以继续扩大真实课程知识库、评测集和真实视频 provider 的稳定性测试。
```

## 4. 常见追问口径

问题：OpenMAIC 和 A3 是什么关系？

```text
A3 是主产品和赛题闭环，负责画像、诊断、计划、资源包、评测、报告和教师端。OpenMAIC 是可借鉴和接入的多智能体互动课堂底座，负责把 A3 资源包升级成课堂、PPT 和视频产物。所有入口仍在 A3 页面，产物通过 bridge API 写回 A3 后端。
```

问题：个性化是大模型分配，还是系统内置规则？

```text
当前是规则、画像、错题、路径和知识库检索共同驱动。大模型可作为增强层，但最终推荐、计划和落库必须经过后端规则校验，保证可解释和可复现。
```

问题：如何证明不是 mock？

```text
演示页按钮调用真实 API；validate_demo_flow 会检查账号、画像、路径、推荐、验证、报告和教师干预；evaluate_demo_retrieval 会生成真实评测指标文件；资源包 artifact 会写回后端并在教师端和能力页展示。
```

问题：视频 provider 没 key 怎么办？

```text
没有 key 时不会假装生成成功。/api/generate/video 会返回 provider 未配置，A3 bridge 会把 failed/degraded artifact 写回资源包，教师端、资源包详情页和能力页都能看到降级原因。
```

# A3 首页上市展示深度审计与优化路线图

> 审计对象：`/a3` 公开产品首页
>
> 审计日期：2026-07-14
>
> 当前基线分支：`codex/a3-latest-integration`
>
> 本文定位：产品、内容、设计与工程联合审计，不直接修改首页实现。

## 1. 执行摘要

当前首页已经不是静态概念稿：它使用真实产品截图，完整呈现了学习画像、入学诊断、本地知识库、多模态资源、AI 课堂、实时辅导、引用证据和教师工作台，暗色加荧光绿的视觉方向也形成了初步识别度。桌面端和移动端实测均没有明显布局崩坏，图片资源可用，累计布局偏移为 0。

但它还没有达到“可上市展示的产品介绍首页”标准。核心问题不是再增加视觉装饰，而是首页叙事与实际产品能力不对齐：项目已经具备今日任务、7/14/30 天计划、学习路径、测评、错题复习、报告、通知和收藏等完整闭环能力，首页却主要停留在“AI 能生成什么资源、能提供什么互动”的能力展览。用户看得到生成和辅导，看不到学习完成后如何测评、复习、更新画像和调整计划，因此“闭环”尚未被证明。

上线前最需要解决的四件事是：

1. 把首页从竞赛演示语境切换为正式产品语境。
2. 以学生的一天和持续学习闭环重组内容，而不是继续横向堆能力模块。
3. 用可复现评测、真实界面和安全边界构成可信证据。
4. 补齐 SEO、分享、可访问性和首屏性能基础设施。

审计综合评分为 **14/20（Good）**。页面已经具备继续精修的基础，但“上市信任”和“完整闭环表达”仍是阻止其进入正式发布状态的主要差距。

## 3. 当前首页与完整产品的覆盖差距

| 产品阶段 | 项目当前能力 | 首页表达 | 判断 |
|---|---|---|---|
| 注册与首启 | 登录、注册、手机绑定、隐私授权、画像采集 | 仅有登录/注册入口 | 可接受，但缺少隐私信任提示 |
| 学习起点 | 学习画像、入学诊断 | 已用真实截图重点展示 | 覆盖较好 |
| 个性化路径 | 学习路径、先修关系、薄弱点定位 | 只有抽象描述 | 表达不足 |
| 周期计划 | 7/14/30 天计划、每日时长、复习队列 | 未展示 | 关键缺口 |
| 今日执行 | 今日任务、进度、下一步动作 | 未展示 | 关键缺口 |
| 本地证据 | 上传、索引、检索、引用 | 已展示知识库和引用逻辑 | 覆盖较好 |
| 多模态资源 | 六类基础资源及课堂、PPTX、视频 artifact | 已展示七类资源索引 | 覆盖较好 |
| 学习互动 | AI 课堂、面对面辅导、数字教师 | 已重点展示 | 覆盖较好，但数字教师权重偏高 |
| 学习验证 | 测评判分、解释、错因 | 未展示 | 关键缺口 |
| 持续掌握 | 错题本、重练、间隔复习 | 未展示 | 关键缺口 |
| 数据回流 | 薄弱点、画像、推荐、计划刷新 | 只用“结果会写回”概括 | 缺少可视证据 |
| 学习结果 | 阶段报告、通知提醒、收藏 | 未展示 | 表达不足 |
| 教师干预 | 学情、风险、薄弱点、任务推送 | 已展示教师工作台 | 覆盖较好 |

结论：项目能力完成度高于首页表达完成度。下一版首页不应继续增加新的概念功能，而应优先把已经存在的学习闭环讲完整。

## 5. P1：上市前必须完成

### 5.1 从竞赛演示切换为正式产品语境

当前公开页面仍出现“评审体验”、比赛名称、非正式团队名和个人 QQ 邮箱。这会让访问者把页面判断为比赛作品，而不是可以持续使用和采购的产品。

需要调整：

- 将“评审体验”改为“体验产品”或“查看演示”。
- Footer 使用正式产品主体、产品域名邮箱和清晰的联系渠道。
- 补充隐私政策、用户协议、内容安全说明和适用时的备案信息。
- 比赛背景可以进入“关于项目”或案例页，不作为公开首页默认身份。
- 上线前确认产品主体和支持渠道，不在代码中硬写个人身份信息。

验收标准：首次访问者无需了解赛题，也能判断产品服务对象、核心价值、使用入口和责任主体。

### 5.2 重写首屏定位

当前主标题“每一步学习，都更懂你”情绪友好，但缺少品牌名、产品类别和差异点。“懂你”是通用 AI 表述，无法独立建立智学引擎的定位。

建议结构：

```text
品牌名：智学引擎
类别/结果：把诊断、资源、辅导和复习连成一条学习闭环
支持文案：说明面向大学生，基于个人目标与本地资料组织每日学习
主要 CTA：开始体验
次要 CTA：查看完整学习闭环
信任提示：资料来源可追溯、学习结果会回流、教师可干预
```

最终文案应在实现阶段做一次中文语气校准，避免空泛的“赋能、重塑、颠覆”等营销词。

### 5.3 用“学习闭环”重组首页

首页主叙事应从能力清单改为一个学生可以理解的连续过程：

```text
诊断起点
→ 今日任务与周期计划
→ 本地资料和证据
→ 个性化多模态资源
→ AI 课堂与辅导
→ 测评和错题复习
→ 画像与计划更新
→ 报告和教师干预
```

需要新增的不是更多卡片，而是三类真实界面证据：

- 今日任务或学习计划：回答“打开产品后今天学什么”。
- 测评与错题复习：回答“系统如何确认真的学会”。
- 报告或计划刷新：回答“学习结果如何影响下一步”。

可以合并或压缩部分现有故事段，避免首页从约 9500 px 继续增长。

### 5.4 重做证据区

当前“资料可检索、来源可验证、结果会写回”仍然是主张，不是证据。项目已有可复现评测结果，可以构建一个公开安全的证据摘要。

2026-07-14 本地评测快照包括：

| 评测 | 当前快照 | 首页可公开表达 |
|---|---|---|
| 检索与安全 | 53 条用例；Top1 85%，Top3/Top5 100%；安全与缺证拒答覆盖 100% | “53 条可复现检索与安全回归用例”，详细比率需标注日期和数据集 |
| Agent 工作流 | 18 条工作流；契约、trace、证据 schema、API 入口覆盖 100%；存在 9 次预算超限和 9 个超时步骤 | 可表达“18 条工作流有契约和 trace”；延迟问题不能隐藏 |
| 多模态 RAG | 2 份资源，文本覆盖 100%，视觉覆盖 50%，混合检索就绪率 100% | 样本过小，只适合作为工程状态，不作营销结论 |
| 题库 | 15 道已批准题目，证据覆盖 100% | 可表达“正式测评题目经过证据校验”，不夸大题库规模 |
| 资源生成 | 六类要求资源全部生成并通过当前回归 | 可表达“六类资源生成链路可复现” |

实现原则：

- 生成 public-safe 的构建时证据摘要，不匿名开放包含用户、trace 或内部状态的接口。
- 每个数字标注评测日期、样本范围和“查看方法”入口。
- 只呈现能被命令或测试复现的结论。
- 不把当前快照中的 100% 写成无条件、长期不变的产品承诺。
- 同时公开主要限制，例如多模态 RAG 样本规模和工作流超时情况。

### 5.5 补齐 SEO 与分享基础

当前线上原始 HTML 缺少 Open Graph、Twitter Card、canonical 和 JSON-LD，根文档初始语言为 `en`，也未形成完整的 robots、sitemap、manifest 和 favicon 体系。

需要完成：

- 根 HTML 输出正确的 `lang="zh-CN"`，不能只依赖 hydration 后修改。
- 为首页设置唯一 title、description、canonical 和可分享的 OG 图片。
- 增加 `og:title`、`og:description`、`og:image`、`twitter:card`。
- 增加 `SoftwareApplication` 或与真实业务一致的 JSON-LD，不虚构评分、价格和客户。
- 提供 `robots.ts`、`sitemap.ts`、favicon 与 web manifest。
- 明确哪些 A3 业务页面允许索引；登录后页面、个人报告和教师页面应禁止索引。

### 5.6 降低首屏客户端成本

首页目前以完整 Client Component 树运行，同时根布局初始化 OpenMAIC provider、access-code 和登录态相关请求，并预取多个深层业务路由。这些行为对公开营销首屏价值有限，却增加了脚本和网络成本。

建议：

- 将静态首页主体拆为 Server Components。
- 只保留认证 CTA、课堂切换和数字教师等必要客户端岛。
- A3 公开首页不初始化 OpenMAIC provider/access-code 状态。
- 仅预取主要 CTA；对 recommendations、coaching、teacher 等深层入口按需设置 `prefetch={false}`。
- 保留数字教师 Three.js 的动态导入，并确认未进入首屏关键路径。
- 复核 Inter、Geist、Geist Mono 三套字体的实际必要性，压缩字体请求和字重。

验收预算：移动网络条件下 LCP ≤ 2.5 秒、CLS ≤ 0.1、初始传输 ≤ 650 KB，并通过持续化 Lighthouse 检查。

## 6. P2：增强产品说服力

### 6.1 增加学生与教师双角色入口

首页当前同时讲学生和教师，但没有清晰分流。建议在完成主学习闭环后提供角色切换：

- 学生视角：今天学什么、为什么推荐、如何确认掌握。
- 教师视角：谁有风险、薄弱点在哪里、如何推送干预。

不要在 Hero 中放两个同权的复杂角色选择。默认以学生价值为主，在后半页切换教师/机构价值。

### 6.2 建立隐私与内容安全信任

产品涉及学习画像、本地资料、对话和测评数据，公开首页必须回答：

- 上传资料如何使用和隔离。
- 引用不足时系统如何拒答或标记未验证。
- 学生数据和教师权限如何划分。
- 用户如何管理或删除自己的数据。
- 视频、PPTX 和外部 provider 处于何种数据边界。

首页只需要简明摘要，详细内容进入正式隐私与安全页面。

### 6.3 增加方法与 FAQ

建议 FAQ 聚焦真实决策问题，而不是重复卖点：

- 智学引擎与普通 AI 对话工具有什么不同？
- 是否必须上传自己的资料？
- 推荐和引用如何验证？
- 学习计划会如何调整？
- 教师能看到哪些数据？
- 哪些能力依赖 OpenMAIC 或外部视频 provider？

### 6.4 建立转化漏斗

至少记录以下匿名事件：

```text
homepage_view
hero_primary_cta_click
hero_secondary_cta_click
learning_loop_section_view
student_role_click
teacher_role_click
signup_start
signup_complete
demo_login_start
```

埋点必须遵循隐私授权，不记录用户输入、资料内容、问题正文或敏感身份字段。

### 6.5 统一品牌与设计 token

当前样式文件体量较大，颜色存在较多硬编码。建议建立 `PRODUCT.md` 和 `DESIGN.md`，并逐步沉淀：

- 品牌定位、目标人群、语气、禁用表达。
- 语义颜色、字体层级、间距、圆角、边框、动效时长。
- 深色营销页与浅色产品页之间的品牌一致性。
- 截图选取、脱敏、裁切和更新规则。

颜色 token 可使用 OKLCH 统一管理，但不应为了换技术格式而一次性重写全部 CSS。

## 7. P3：品牌深化与发布工程

- 用两到三种不同的内容节奏替代连续“标题加截图”，例如步骤流、前后状态对比和可展开证据。
- 为核心截图建立自动脱敏和版本检查，避免产品更新后首页展示过期界面。
- 对数字教师段落做价值校准：明确它如何改善讲解、陪练或注意力反馈，避免成为与学习闭环无关的展示特效。
- 增加轻量、可关闭且尊重 `prefers-reduced-motion` 的滚动叙事，不用大范围视差和持续动画拖慢页面。
- 建立首页视觉回归、链接巡检、SEO 检查和 Lighthouse 阈值。
- 当拥有真实用户和合规授权后，再加入案例、学习成效或机构评价；当前不要虚构客户 Logo、评价和增长数字。

## 8. 推荐首页信息架构

### 1. Header

保留品牌、产品能力、适用角色、证据/安全、登录和主要 CTA。移动菜单需要焦点管理、滚动锁和不低于 44×44 px 的触控目标。

### 2. Hero

第一视口直接出现“智学引擎”和产品类别；使用真实产品主场景，主要 CTA 指向开始体验，次要 CTA 滚动到完整闭环。

### 3. 今天该学什么

展示今日任务、周期计划和预计时长。这一段负责把产品从“功能集合”变成“每天可执行的学习工具”。

### 4. 为什么是你的计划

合并画像、入学诊断、薄弱点和学习路径，解释推荐依据。

### 5. 资料如何变成学习资源

串联本地知识库、检索证据和七类多模态资源。继续使用真实、脱敏截图与资源类型索引。

### 6. 如何学会

展示 AI 课堂、实时辅导、来源引用和安全降级，数字教师作为辅导形态之一，而不是独立产品主角。

### 7. 如何形成闭环

用测评、错题本、间隔复习、画像更新、计划刷新和阶段报告证明“学完之后发生什么”。这是下一版最重要的新段落。

### 8. 教师和机构价值

展示风险识别、薄弱点、资源效果与任务推送，提供教师工作台入口。

### 9. 可复现证据

展示带日期、样本范围和复现方式的评测摘要，同时说明当前限制。

### 10. 隐私与安全

简要说明资料隔离、引用验证、内容安全、权限和数据管理，链接到详细政策。

### 11. FAQ

回答产品差异、资料要求、计划调整、教师权限和 provider 边界。

### 12. 最终 CTA

只保留一个明确的下一步，避免重复出现多个同权入口。

### 13. 正式 Footer

包含产品主体、联系渠道、隐私政策、用户协议、安全说明、适用备案和版本信息。

## 9. 可访问性修复清单

| 优先级 | 问题 | 修复要求 |
|---|---|---|
| P1 | 原始 HTML 为 `lang="en"` | 服务端输出 `zh-CN` |
| P1 | Hero 非交互截图容器具有 `tabIndex={0}` | 移除无意义 Tab 停留；若可操作则改成真实按钮/链接 |
| P1 | 缺少跳到主内容 | 增加 skip link 和稳定的 `main` 锚点 |
| P1 | 移动触控目标偏小 | 菜单、CTA 和 segmented control 达到至少 44×44 px |
| P2 | 移动菜单焦点管理不足 | 打开后移动焦点、关闭后归还焦点、支持 Escape、锁定背景滚动 |
| P2 | 锚点跳转后的标题焦点不明确 | 确保键盘和读屏用户能感知当前位置 |
| P2 | `teacherPrompt` 使用侧边色条 | 改为更中性的边框、底色或图标语义，保持视觉一致性 |

现有优势应保留：正文对比度充足、图片 alt 完整、`focus-visible` 可见、支持 reduced motion、布局无明显 CLS。

## 12. 明确不做什么

- 不再增加一排排等尺寸能力卡片来制造“功能很多”的感觉。
- 不用虚构客户 Logo、用户评价、学习增长率或媒体背书填补信任区。
- 不把内部 Agent 名称作为普通用户的主要卖点。
- 不匿名暴露 demo status、用户数据、trace 或内部文件路径。
- 不把某次回归中的 100% 指标写成永久产品承诺。
- 不为追求视觉效果引入首屏 Three.js、自动播放视频或重型滚动动画。
- 不让比赛、评审和临时演示账号继续成为正式首页的默认语境。
- 不切回旧首页，也不破坏现有 A3 路由和 OpenMAIC artifact 写回链路。

## 13. 完成定义

首页达到“可上市展示”应同时满足：

1. 新用户在首屏能说出产品名称、服务对象、核心结果和下一步动作。
2. 页面完整证明“诊断—计划—学习—测评—复习—更新—报告/干预”闭环。
3. 每个关键主张都对应真实界面、真实接口或带范围的可复现评测。
4. 页面不再使用比赛与临时团队语境，法务和联系信息完整。
5. 原始 HTML、搜索与分享元数据正确，受保护页面不被索引。
6. 桌面与移动端可访问，键盘路径完整，触控目标合格。
7. LCP、CLS 和初始传输达到既定预算。
8. CTA 转化可观测，且埋点不采集学习内容和敏感数据。
9. 首页截图与当前产品一致，并有自动化回归防止过期或破损。

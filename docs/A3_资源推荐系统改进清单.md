# A3 资源推荐系统改进清单

> 记录本轮对 `/a3/recommendations` 资源推荐系统（7 种资源类型）的诊断与改进。
> 改动共 12 个文件（11 改 + 1 新增），约 +884 / −178 行。

## 背景

诊断覆盖三个维度：①每种资源类型的 prompt 是否到位 ②多 Agent 协同实效 ③前端呈现。
7 种资源类型：`lecture_doc`（课程讲解文档）、`knowledge_card`（知识点速记卡）、
`mind_map`（思维导图）、`practice_set`（专项练习题）、`case_study`（工程实践案例）、
`code_lab`（代码实操案例）、`micro_video_script`（短视频脚本）。

核心发现：7 种资源明显分成「强 3 / 弱 4」——练习/案例/代码拿到了「专属人设 + 严格门禁 +
repair」三件套，明显强；讲义/知识卡/思维导图/视频脚本共用通用 default、走宽松门禁，明显弱。
根因是同一个：requirements 写了约束，但质量门禁对弱 4 类不做强制、只数数量就放行。

## 未做项（P3，评估为低性价比）

| 项 | 不做的原因 |
|---|---|
| 跨 workflow 同名 Agent 策略串味（`ResourceVerifierAgent.name == "VerifierAgent"` 命中推荐流水线策略） | 实测无错误行为：ResourceVerifierAgent 是毫秒级纯内存操作，串味来的 3000ms 超时永远碰不到。属代码异味而非 active bug |
| 超时事后检测无法中断卡死 Agent | 仅在「整包默认开 LLM」时才有实际意义，当前默认不开 |
| 共享 state 无命名空间、后写覆盖先写 | 资源流水线内键名当前不冲突，属未来隐患 |
| 熔断基于用户历史可能连坐整条流水线 | 边缘场景（用户连续失败才触发） |

## 遗留验证限制

1. 受 C 盘 MySQL 临时目录空间限制，后端未能一次跑完整个 60 测试的模块（会耗尽临时表空间导致
   连锁 DB 错误，`errno 28` / `1114 table is full`）。跑的是各项相关子集。要完整跑全模块，
   建议把 MySQL 的 `tmpdir` 迁到空间充足的盘（如 D 盘）后重试。
2. 前端仅做了 `tsc` 类型检查，未做浏览器实测。翻卡动画、语法高亮显示、引用溯源跳转的实际视觉
   效果，建议启动 dev server 确认。

# 后续：AI 课堂 × 资源生成融合（通用意图识别层 + 课堂 A+B）

> 独立于上面 10 项改进的一次功能扩展。详细设计见
> `docs/superpowers/plans/2026-07-27-a3-classroom-intent-router-and-resource-generation.md`。

## 背景与目标

AI 课堂与资源推荐此前各自独立，唯一连接是一个跳转链接——课堂已有明确学习目标
（`target.title`），用户却要跳到另一页重新输入需求才能生成资源，操作割裂。

本次做两件事：
1. **通用意图识别层**（surface 无关、可复用，不只服务资源生成）
2. **课堂 A+B 闭环**——A：课堂内资源类型 chips，用当前目标一键生成；
   B：对话触发（"生成一个讲解视频" → 识别 → 生成 → 结果作为消息渲染进对话流）

已确认决策：意图识别用**混合架构**（显式操作直接分发 / 自由文字先前端规则、命中不了再调
后端 LLM / 任何不确定兜底问答）；B 生成结果**作为消息插进对话流**；范围**先做课堂 A+B**。

## 后端

| 文件 | 改动 |
|---|---|
| `backend/apps/compat/intent_router.py`（**新增**） | 通用意图识别：`classify_intent(text, context)` → `{intent, confidence, params, source}`。规则快判高频意图（0 延迟）+ `chat_completion` LLM 兜底；6 类意图 `ask_question`/`generate_resource`/`start_practice`/`explain_concept`/`navigate`/`review_wrong`，能从文本识别 7 种资源类型；LLM 不可用或低置信一律回退 `ask_question` |
| `backend/apps/compat/views.py` | 新增 `intent_classify` 视图 → `POST /api/intent/classify/`（surface 无关，语音/首页等均可调用） |
| `backend/apps/compat/urls.py` | 注册 `intent/classify/` 路由 |
| `backend/apps/compat/tests/test_intent_router.py`（**新增**） | 13 个测试：规则层各意图识别 + 低置信回退 + 端点分类/空输入/超长输入/鉴权 |

## 前端

| 文件 | 改动 |
|---|---|
| `lib/a3/intent-router.ts`（**新增**） | 前端混合意图路由：`ruleClassify`（本地规则）、`classifyIntent`（规则→后端→兜底）、`dispatchIntent`（意图映射到调用方注入的 handlers）。surface 无关，课堂/语音/首页各注入自己的 handlers |
| `lib/a3/use-resource-generation.ts`（**新增**） | 自包含资源生成 hook：`useResourceGeneration()` → `{generate, generating, activeType, progress, error}`。复用后端 `/api/a3/resources/jobs` 真实 job 轮询（超时/瞬时失败容忍/终态检测），课堂 A/B 共用 |
| `resource-standalone-view.tsx` | 导出 `ResourceInlineBody`：对话内联渲染——讲义/卡片/导图直接展示正文，练习/案例/代码/视频给"打开完整页"入口（交互式工作台不塞进气泡） |
| `classroom-view-redesign.tsx` | ①`ChatMessage` 加 `kind:'text'\|'resource'` + `resourcePack`/`resourceType`；②`generateResourceInClassroom` 课堂内生成（A/B 共用）；③`askQuestion` 先过 `classifyIntent`——generate_resource 走生成、navigate 走路由跳转、其余（含 explain/兜底）继续问答；④`ClassroomResourceChips` 对话区顶部 7 类型 chips（用 `target.title` 生成）；⑤`ChatBubble` 渲染 `kind:'resource'` 消息（内联 `ResourceInlineBody`）|

## 提交前审查补充修复

- 意图分类接口限制输入不超过 2000 字符；LLM 置信度低于 0.6 时回退普通问答，避免模糊输入误触发资源生成。
- 系统资料库的 URL 初始搜索与可变筛选状态解耦，重试和搜索显式使用当前筛选条件，避免搜索词被 URL 参数覆盖。
- 代码高亮预览支持 Enter / Space 进入编辑，补齐键盘可访问性。
- 前端相关契约测试 15 个文件、90 个用例通过；意图路由 13 个后端测试和资源质量 4 个针对性测试通过。

## 与 plan 的偏差（如实记录）

1. **端点路径**：plan 写 `/api/a3/intent/classify`，实际 `/api/intent/classify/`（compat 挂 `/api/`，前端直连 Django，无需 a3 前缀）。功能一致。
2. **阶段 1「抽 hook」变体**：plan 要从 `recommendations-view.tsx` 抽生成逻辑并让该页改用；实际**新建独立 hook、recommendations 页未重构**（避免动 1600 行工作组件的风险、且无法可视化验证）。代价：课堂与推荐页目前各有一套生成逻辑，未达成隐含的"去重"。

## 遗留验证限制（本次）

- **课堂前端集成未做浏览器实测**：意图规则层用独立脚本验过、后端端点有单测，但"在真实课堂页面输入触发生成 / 点 chips / 资源消息渲染 / 导航跳转"的端到端效果**未在 dev server 验证**。需手动确认：
  - 输入"生成一个讲解视频" → 出现资源消息
  - 点资源 chip → 用当前目标生成
  - 输入"打开学习报告" → 路由跳转
  - 输入"什么是死锁" → 正常走问答（不被误判为生成）

- 方案 C（把资源工作台抽成共享 context 的架构级重构 / recommendations 与课堂去重）

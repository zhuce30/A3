# A3 实时视频通话式面对面辅导设计方案

日期：2026-07-06

适用范围：`/a3/coaching` 面对面辅导页、A3 知识库、课堂问答 Agent、能力总览页、教师工作台。

本文档用于指导 A3“智学引擎”把当前 turn-based 文本/录音问答升级为接近豆包视频通话体验的实时辅导系统。目标不是做一个看起来像视频通话的静态界面，而是形成真实的低延迟语音交互、按需视觉理解、混合 RAG 证据、会话持久化、学习画像回流和教师可管理的完整闭环。

## 1. 背景与问题

当前 `/a3/coaching` 已具备以下基础能力：

- 文本提问和普通 HTTP 问答。
- 录音、转写、发送给问答接口。
- 基于本地知识库的检索增强回答。
- `SafetyAgent`、`VerifierAgent`、`FollowUpAgent` 参与回答后验证和追问。
- `CoachingSession`、`CoachingMessage` 会话记录和总结。
- 教师端和能力总览页可以看到部分学习过程证据。

但它还不是“视频通话式辅导”：

- 语音交互是“录完再发”，不是低延迟、可打断的实时对话。
- 摄像头目前主要是本地预览，模型没有真正理解画面。
- 屏幕共享、图片帧、课件截图还没有进入实时辅导链路。
- RAG 证据和视觉证据尚未作为实时模型的工具结果稳定注入。
- 通话结束后的薄弱点更新、计划调整、教师可见摘要还需要强化。

## 2. 产品目标

升级后的 `/a3/coaching` 应提供以下体验：

```text
学生进入面对面辅导
-> 创建实时辅导会话
-> 授权麦克风、摄像头或屏幕共享
-> 与 AI 助教进行低延迟语音对话
-> 学生可随时说“看这里”触发摄像头/屏幕/图片理解
-> 系统检索文本知识库和 visual_vector 视觉证据
-> AI 基于证据进行讲解，展示引用、缩略图和验证状态
-> 通话中实时生成字幕、追问建议和下一步动作
-> 通话结束后写回会话、薄弱点、学习计划和教师端摘要
```

核心原则：

- 先保证实时语音可用，再扩展连续视频理解。
- 视觉理解采用按需截图和低频抽帧，不默认把所有视频帧送给 VLM。
- 所有回答必须保留 A3 的知识库引用、验证、安全过滤和学习闭环。
- provider 可替换，不能把系统锁死在单一厂商。
- provider API key 只能保存在服务端，前端只拿短期凭证或内部会话 ID。

## 3. 技术依据

### 3.1 OpenAI Realtime

OpenAI Realtime 支持面向浏览器的 WebRTC 接入。官方建议浏览器端使用服务端签发的短期 client secret 或 ephemeral token，正式 API key 只保存在服务端。Realtime 可用于低延迟语音对话，并支持服务端控制、安全标识和工具调用设计。

参考：

- https://developers.openai.com/api/docs/guides/realtime-webrtc
- https://developers.openai.com/api/docs/guides/realtime

### 3.2 DashScope Qwen-Omni-Realtime

项目当前倾向使用阿里云能力，因此必须保留 DashScope provider。阿里云文档说明 Qwen-Omni-Realtime 支持 WebSocket 和 WebRTC：WebSocket 适合服务端集成，WebRTC 适合浏览器低延迟语音场景；模型可理解流式音频和图像输入，并输出文本或音频。

参考：

- https://help.aliyun.com/zh/model-studio/realtime
- https://help.aliyun.com/zh/model-studio/client-events
- https://help.aliyun.com/zh/model-studio/omni-realtime-java-sdk

### 3.3 A3 项目的技术选择

A3 应抽象一层 `RealtimeCoachingProvider`：

```text
RealtimeCoachingProvider
├── openai_realtime_webrtc
├── dashscope_qwen_omni_realtime
└── local_fallback_record_then_respond
```

首选：

- 用户已经配置 `DASHSCOPE_API_KEY` 时，优先走 `dashscope_qwen_omni_realtime`。
- 配置 `OPENAI_API_KEY` 且选择 OpenAI provider 时，走 `openai_realtime_webrtc`。
- 没有实时 provider 或 provider 失败时，明确降级到现有录音转写 + `/api/a3/coaching/respond`，不得伪装成实时成功。

## 4. 用户体验设计

### 4.1 页面结构

`/a3/coaching` 从普通问答页升级为通话工作台：

```text
顶部状态栏
  当前学习目标 | provider | 网络状态 | RAG 命中 | 验证状态 | 通话时长

主工作区
  左侧：视频/屏幕/AI 助教区域
    - 学生摄像头预览
    - 屏幕共享预览
    - AI 语音波形或助教头像
    - “看这里”截图提问入口

  右侧：学习证据与辅导上下文
    - 当前知识点
    - 文本引用
    - 视觉证据缩略图 previewUrl
    - 安全和验证状态
    - 薄弱点和下一步任务

下方区域
  实时字幕 | 追问建议 | 保存笔记 | 加入错题/复习

底部控制栏
  开始/结束 | 麦克风 | 摄像头 | 屏幕共享 | 截图提问 | 静音 | 降级提示
```

### 4.2 状态机

| 状态 | 用户感知 | 系统行为 |
|---|---|---|
| `idle` | 尚未开始通话 | 展示当前学习目标、历史会话和设备检测 |
| `requesting_permission` | 请求设备权限 | 请求麦克风、摄像头或屏幕共享权限 |
| `connecting` | 正在连接 | 创建 A3 会话和 provider 实时会话 |
| `live` | 通话中 | 实时语音输入输出、字幕和证据展示 |
| `visual_focus` | 正在看图/看屏幕 | 发送截图或低频帧到 VLM 和视觉检索 |
| `degraded` | 已降级 | 回退到录音转写 + 普通问答，并明确提示原因 |
| `ending` | 正在总结 | 写入消息、生成摘要、刷新学习画像 |
| `ended` | 通话结束 | 展示辅导报告、复习入口和下一步任务 |
| `error` | 连接失败 | 中文错误、诊断项、重试和降级入口 |

### 4.3 降级体验

降级不能只是报错，应提供可继续学习的路径：

- 麦克风不可用：保留文本提问、图片上传和知识库引用。
- 摄像头不可用：保留语音通话、屏幕共享和图片上传。
- 实时 provider 不可用：回到现有录音转写 + `coaching/respond`。
- RAG 超时：回答标记为“未验证”，引导用户补充资料或改问法。
- VLM 超时：基于用户描述继续回答，提示截图理解失败。

## 6. 关键接口设计

### 6.1 创建实时会话

接口：

```text
POST /api/a3/coaching/realtime/session
```

职责：

- 校验登录态。
- 读取当前学生画像、学习路径节点、今日任务和课堂上下文。
- 创建或复用 `CoachingSession`。
- 调用 provider adapter 创建实时会话。
- 返回浏览器可用的短期凭证或降级信息。
- 不返回正式 API key。

请求字段：

```json
{
  "targetId": "optional-learning-target-id",
  "mode": "voice_video",
  "preferredProvider": "dashscope_qwen_omni_realtime"
}
```

响应字段：

```json
{
  "success": true,
  "provider": "dashscope_qwen_omni_realtime",
  "model": "qwen3.5-omni-plus-realtime",
  "connection": {
    "type": "webrtc",
    "clientSecret": "short-lived-token",
    "expiresAt": 1783333333
  },
  "coachingSessionId": "123",
  "instructions": {
    "targetTitle": "根轨迹基础",
    "safetyPolicyVersion": "a3.realtime-safety.v1",
    "retrievalPolicyVersion": "a3.hybrid-rag.v1"
  }
}
```

降级响应：

```json
{
  "success": true,
  "provider": "local_fallback_record_then_respond",
  "model": "a3-local-fallback",
  "coachingSessionId": "123",
  "fallbackReason": "未配置实时 provider，已降级到录音转写问答"
}
```

### 6.2 实时工具桥接

接口：

```text
POST /api/a3/coaching/realtime/tool
```

工具名称：

- `retrieve_learning_evidence`
- `verify_realtime_answer`
- `generate_follow_up_questions`
- `write_learning_event`

RAG 请求示例：

```json
{
  "coachingSessionId": "123",
  "toolName": "retrieve_learning_evidence",
  "query": "根轨迹规则怎么判断渐近线？",
  "topK": 5,
  "includeVisualEvidence": true
}
```

响应示例：

```json
{
  "success": true,
  "evidence": [
    {
      "title": "自动控制原理课件",
      "location": "第 4 章 / 幻灯片 12",
      "snippet": "根轨迹渐近线由极点数与零点数之差决定。",
      "score": 0.82,
      "sourceType": "mixed",
      "previewUrl": "/api/kb/assets/visual/abc.png"
    }
  ],
  "safety": {
    "safe": true,
    "category": "learning"
  }
}
```

### 6.3 视觉帧理解

接口：

```text
POST /api/a3/coaching/realtime/frame
```

触发方式：

- 用户点击“看这里”。
- 用户上传图片。
- 用户共享屏幕后低频抽帧。

请求字段：

```json
{
  "coachingSessionId": "123",
  "source": "screen",
  "imageDataUrl": "data:image/jpeg;base64,...",
  "prompt": "请看这道题的图像部分，解释下一步怎么做"
}
```

处理流程：

```text
接收图片帧
-> 做大小、格式和权限校验
-> 调用 VLM 识别题目、公式、图表或板书
-> 调用 visual_vector 检索相关课件页/截图证据
-> 返回视觉摘要、证据缩略图和建议回答
-> 写入 CoachingMessage.metadata.visualEvidence
```

### 6.4 保存实时消息

接口：

```text
POST /api/a3/coaching/realtime/message
```

只保存 final 事件，不保存未稳定的 partial 字幕：

```text
student_audio_transcript.partial  -> 只显示，不入库
student_audio_transcript.final    -> user message
assistant_audio_transcript.final  -> assistant message
tool_result                       -> message.metadata.evidence
visual_frame_summary              -> message.metadata.visualEvidence
session_end_summary               -> session.metadata.summary
```

### 6.5 结束通话

接口：

```text
POST /api/a3/coaching/realtime/end
```

职责：

- 关闭前端连接。
- 汇总通话时长、provider、延迟、RAG 命中和降级次数。
- 调用 `summarize_coaching_session`。
- 更新薄弱点、复习队列、今日任务建议。
- 在教师工作台展示摘要。
- 在 `/a3/capabilities` 展示指标。

## 7. 多模态 RAG 策略

实时辅导不是单纯“把摄像头给模型看”。A3 应采用混合多模态 RAG：

```text
文本资料
  -> 文本抽取/OCR
  -> chunk
  -> text embedding
  -> text vector index

PPTX/PDF/图片资料
  -> 页面/幻灯片渲染为图片
  -> OCR 抽取文字
  -> VLM 生成页面摘要、图表摘要、公式摘要
  -> visual embedding
  -> visual_vector index

实时通话问题
  -> ASR 文本
  -> 查询重写
  -> text retrieval + visual retrieval + BM25
  -> rerank
  -> evidence pack
  -> VLM/LLM 回答
  -> VerifierAgent 验证 citations
```

关键要求：

- PPTX 幻灯片即使没有可提取文本，也必须通过渲染图和视觉摘要进入知识库。
- 图片和视觉证据要返回 `previewUrl`，前端 citation UI 展示缩略图。
- 回答没有证据时不能标记为 verified。
- 对实时帧只保存必要摘要和证据引用，默认不保存原始视频。

## 8. Agent 分工

| Agent | 职责 |
|---|---|
| `RealtimeTutorAgent` | 维护实时辅导提示词、教学策略、打断和转场 |
| `RealtimeTurnAgent` | 判断学生语音是否形成完整问题 |
| `RealtimeRetrievalAgent` | 根据语音转写触发 hybrid retrieval |
| `VisualFrameAgent` | 解析摄像头、屏幕、上传图片和课件帧 |
| `RealtimeVerifierAgent` | 将语音回答绑定到 citations 和 claims |
| `RealtimeSafetyAgent` | 拦截作弊、隐私、危险、越权和高不确定请求 |
| `SessionSummaryAgent` | 通话结束后生成摘要、薄弱点和下一步任务 |

复用已有 Agent：

- `SafetyAgent`
- `RetrieverAgent`
- `VerifierAgent`
- `FollowUpAgent`
- `ProfileAgent`
- `StudyPlanAgent`
- `TeacherWorkbenchAgent`

## 10. 环境变量

放置位置：

- `D:\Download\A3\backend\.env`：Django 后端需要的 provider key、VLM、embedding、OCR、知识库任务配置。
- `D:\Download\A3\OpenMAIC\.env.local`：Next server 需要读取的代理配置和 provider 选择；不要使用 `NEXT_PUBLIC_*` 暴露密钥。

示例：

## 11. 安全与隐私

- 首次进入实时辅导前必须说明麦克风、摄像头、屏幕共享用途。
- 默认不保存原始音频和视频，只保存转写、摘要、引用和必要视觉证据。
- 图片、截图和缩略图必须走知识库资产访问控制，不暴露本地绝对路径。
- provider API key 只存在服务端。
- 短期 client secret 必须绑定用户、会话和过期时间。
- 教师端只展示学习相关摘要、证据和风险，不展示超出授权范围的隐私内容。
- 未经 RAG 或视觉证据验证的回答必须显示“未验证”。

## 13. 验收标准

第一阶段：实时语音闭环

- `/a3/coaching` 可创建真实实时会话。
- 未配置 provider 时显示明确降级，而不是假成功。
- 配置 DashScope 或 OpenAI provider 后，浏览器能建立实时连接。
- 学生语音能产生字幕，AI 能语音或文本回复。
- 至少一次回答能调用 RAG 工具并展示 citation。
- 通话结束后写入 `CoachingSession` 和 `CoachingMessage`。

第二阶段：视觉理解闭环

- 可通过摄像头、屏幕或上传图片发送视觉帧。
- VLM 能识别题目、公式、图表或课件页面。
- visual_vector evidence 能进入回答上下文。
- citation UI 展示 `previewUrl` 缩略图。
- 视觉帧摘要写入 message metadata。

第三阶段：学习闭环

- 通话结束后生成辅导摘要。
- 薄弱点写回学习画像。
- 今日任务或学习计划出现“本次辅导后的下一步”。
- 教师工作台展示该学生的辅导摘要和风险信号。
- `/a3/capabilities` 展示实时 provider、会话数、RAG 命中、视觉帧和降级指标。

## 14. 风险与控制

| 风险 | 控制方式 |
|---|---|
| 实时 provider 文档或模型变化 | provider adapter 隔离，执行前检查官方文档 |
| WebRTC 复杂度高 | 先实现 provider session 和 fallback，再接真实媒体流 |
| 连续视频成本高 | 默认按需截图，自动抽帧设频率和时长限制 |
| RAG 超时影响通话 | 工具调用设置超时，超时回答标记未验证 |
| 前端误暴露 key | contract test 禁止 `NEXT_PUBLIC_*_API_KEY` |
| 中文乱码 | 所有新增文档和 UI 文案使用 UTF-8，避免复制乱码 |
| 假成功 | provider 不可用必须返回 degraded/fallbackReason |

## 15. 推荐实施顺序

1. 先实现实时会话 API、provider adapter 和 UI 状态机。
2. 接入 fallback，保证没有 provider key 时也能继续辅导。
3. 接入 RAG tool bridge，让实时回答拿到文本和视觉证据。
4. 接入视觉帧端点，支持截图、屏幕、上传图片理解。
5. 做消息持久化、会话总结、薄弱点回流。
6. 更新教师端和 `/a3/capabilities` 指标。
7. 做端到端验证和手工验收。

该路线能最快得到可用的“视频通话式辅导”核心体验，同时不牺牲 A3 项目最重要的知识库引用、个性化学习闭环和可验证性。

不是从头搭建。你现在的方向应该是：**基于 THU-MAIC/OpenMAIC 开源底座做 A3 赛题化改造**。

我刚核对了本地仓库：

- `OpenMAIC` 的 git remote 是 `https://github.com/THU-MAIC/OpenMAIC.git`
- 原项目已经有：
  - 多智能体课堂：`components/agent/`、`lib/chat/agent-loop.ts`、`app/api/generate/agent-profiles`
  - 课件/幻灯片生成：`app/generation-preview/`、`lib/generation/`
  - PPTX 导出：`lib/export/use-export-pptx.ts`、`packages/pptxgenjs`
  - 视频生成 provider：`lib/media/video-providers.ts`
  - 视频接口：`app/api/generate/video/route.ts`
  - 支持 Seedance、Kling、Veo、MiniMax、Grok、HappyHorse 等视频模型
  - 图片生成、TTS、白板、PBL、互动课堂等多模态能力

所以结论很明确：

**你不是自己从零搭建，而是在 OpenMAIC 的多智能体互动课堂和多模态生成能力上，加了一套 A3 个性化学习闭环。**

现在项目大概是两层：

```text
OpenMAIC 原能力：
多智能体课堂 / 课件生成 / slide 渲染 / PPTX 导出 / 视频生成 / TTS / PBL

你新增的 A3 能力：
登录注册 / 画像 / 诊断 / 学习路径 / 学习计划 / 推荐 / RAG / 测评 / 错题本 / 报告 / 教师工作台
```

但这里有一个关键问题：**原 OpenMAIC 的视频、PPT、多模态能力存在，不等于 A3 赛题已经完整接入。**

目前 A3 资源包更像是：

```text
个性化资源推荐
讲解文档
知识卡
思维导图
专项练习
工程案例
短视频脚本
```

这还不够。题目如果要求“生成视频和 PPT”，答辩时最好能做到：

```text
学生画像 + 薄弱点 + 当前知识点
-> 生成个性化资源包
-> 调用 OpenMAIC 课件生成 pipeline
-> 生成 slide/课堂场景
-> 可导出 PPTX
-> 调用 video provider 生成短视频或视频素材
-> 回写 A3 资源包、引用、trace、反馈
```

也就是说，正确路线不是重写视频/PPT系统，而是做一个 **A3 -> OpenMAIC 生成管线的桥接层**。

建议下一步优先做这三件：

1. 在 A3 推荐/资源页加“生成个性化课件/PPT”
   - 输入来自学习画像、薄弱点、知识库引用、当前路径节点
   - 调用现有 `generation-preview` / `lib/generation` 能力
   - 生成后支持 PPTX 导出

2. 在 A3 资源包里把“短视频脚本”升级为“视频生成任务”
   - 复用 `app/api/generate/video/route.ts`
   - provider 可先用已有 HappyHorse / Seedance / Kling
   - 没配置 key 时显示“脚本已生成，视频 provider 未配置”，不能假装生成成功

3. 把生成结果回写 A3 后端
   - resourcePack 记录 PPT、视频、脚本、引用、verified 状态
   - 资源卡支持打开、收藏、完成、跳过
   - 能力页展示“PPT 已生成 / 视频 provider / traceId / 生成耗时”

一句话：**继续基于 OpenMAIC 做，不要推倒重来；但要把 OpenMAIC 的多模态生成真正接进 A3 个性化学习闭环，否则只能算“底座有能力”，不能算“A3 功能已完成”。**

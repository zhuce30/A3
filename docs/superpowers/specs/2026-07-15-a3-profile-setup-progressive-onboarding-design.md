# A3 学习设置页首次使用引导优化设计

日期：2026-07-16

状态：已确认，轻量优化现有页面

页面：`/a3/profile-setup`

## 1. 目标与赛题对应

本页面继续承担“对话式学习画像自主构建”：学生用自然语言说明专业、目标、学习经历等，后端自动抽取不少于 6 个维度，并由诊断、错题和学习行为持续更新。

本次不重做页面结构。当前页面已经同时具备自然语言对话和下方手动填写能力，主要问题是上半部分信息太多、术语太重、首次用户不知道先做什么。

本次目标：

- 保留现有对话区和下方手动填写区。
- 首屏只突出一个动作：先回答当前问题。
- 明确告诉用户“不用一次说全，系统会逐项追问”。
- 用正常学习语言代替“画像、Agent、trace、规划输入”等内部术语。
- 访谈结果仍由真实后端自动抽取，前端不编造完成状态。
- 确认后进入入学诊断，诊断完成后再生成正式路径和计划。

## 2. 明确不做

- 不新增“四步逐项确认”入口或模式切换。
- 不新增一套独立的首次访问页面。
- 不删除下方现有手动填写区。
- 不重写 `AgentKernel`、画像 schema 或数据库模型。
- 不修改现有 API 路径、请求体、Cookie、CSRF 或 Next API 代理。
- 不把技术审计信息继续堆在学生首屏。

## 3. 页面结构保持不变

继续使用现有单页结构：

```text
页面标题与当前课程
-> 上半部分：自然语言对话与系统已整理的信息
-> 下半部分：可展开的手动填写区
-> 保存结果与前往入学诊断
```

不再实现新的 `ProfileSetupWizard`、模式切换器或另一套路由状态机。前端主要在现有 `ProfileSetupPage` 内调整布局和文案，必要时只拆出小型展示组件。

## 4. 上半部分改造

### 4.1 页面标题

删除或替换：

- `Learner profile`
- `画像与规划输入`
- “完善目标、基础与偏好，系统将据此生成……”等技术化说明

改为：

```text
告诉我们你的学习情况
不用一次说全。可以先说学习目标、以前学过什么或每天能学多久，
系统会根据你的回答逐项追问，并把信息整理在右侧。
```

当前课程保留，但缩小为标题旁的普通信息，不使用“已同步”等系统状态吸引注意力。

### 4.2 简明三步提示

原来的四张“规划阶段”卡片信息重复且像系统工作流，改成紧凑的三步提示：

```text
1 说说情况  ->  2 回答追问  ->  3 确认并开始诊断
```

这只是操作提示，不是新的向导状态机，不控制路由或 API。

### 4.3 对话区

首次进入显示一个具体问题：

```text
先说说你学习这门课最想解决什么问题？
```

辅助说明：

```text
可以只回答一个方面，不需要一次把所有信息写完整。
```

输入框保留，按钮调整为：

- 主按钮：`发送并整理`
- 次按钮：`查看示例`
- 完成后按钮：`确认并开始入学诊断`

不再使用：

- `对话生成画像`
- `确认画像并生成诊断任务`
- `画像助手`
- `Agent 抽取结果`

后端每轮只返回一个生活化追问。消息区保持可滚动；发送失败时保留用户输入和历史消息。

### 4.4 系统已整理的信息

右侧保留摘要功能，但标题改为：

```text
系统已了解
```

只展示学生能理解的信息，例如专业、年级、目标、当前基础、每天时间、容易卡住的内容和资料偏好。状态使用：

- `已记录`
- `待补充`
- `诊断后确认`

首屏不展示：

- Agent 决策证据
- traceId
- provider/schema version
- 认知风格、动机风险等内部字段名
- 路径/计划“已生成、待生成”的技术状态

技术证据继续留在 `/a3/capabilities`。动态画像变化和待确认记录可以保留在页面后部或再次访问区域，但不抢占首次操作首屏。

## 5. 下方手动填写区

保留现有可展开表单，不新增“逐项确认”入口。

折叠标题改为：

```text
想自己修改？展开手动填写
```

说明改为：

```text
可以补充或修改系统刚才整理的信息。
```

字段、选项来源和保存接口保持不变。生产选项仍全部来自 `GET /api/profiles/options/`。

## 6. 后端与 Agent 契约

自然语言访谈保持：

```text
POST /api/profile/interview/
SafetyAgent
-> ProfileInterviewAgent
-> LearnerModelAgent
-> MemoryCommitAgent
-> PlannerAgent
```

请求保持：

```json
{"message": "学生回答"}
```

确认保持：

```json
{"action": "confirm"}
```

会话恢复保持：

```text
GET /api/profile/interview/session/
```

`profile`、`profileReadiness`、`missingDimensions`、`askFields`、`nextQuestion`、`interviewComplete`、`profileCommitted`、`interviewSession`、`generated` 和 `traceId` 核心字段不重命名。

访谈阶段保留 PlannerAgent step，但不提前生成正式路径和计划，返回 `awaiting_admission_diagnostic`。旧 session 已有生成证据时必须原样保留，不能被恢复逻辑改写。

## 7. 确认与诊断

- 只有服务端 `interviewComplete=true` 时，确认按钮才可用。
- 只有确认响应 `profileCommitted=true` 时，前端才进入入学诊断。
- 前端不得本地设置 `interviewComplete`、`profileCommitted` 或伪造生成结果。
- 确认成功文案改为“学习情况已保存，接下来通过几道题确认你的学习起点”。
- 诊断提交后继续运行：

```text
DiagnosticAgent
-> ProfileUpdateAgent
-> PlannerAgent
-> StudyPlanAgent
```

正式路径和计划只在这里生成。

## 8. 随学随新

保留现有动态画像机制：

```text
画像访谈 / 入学诊断 / 错题 / 任务完成 / 学习偏好行为
-> profile signal / profile update
-> LearnerProfile + extraProfile.dynamicProfile
-> 报告、推荐和学习计划重新聚合
```

本批次至少验证：访谈抽取、诊断写回和一种后续学习信号。学生首屏不需要理解这些内部链路。

## 9. 响应式与可访问性

- 桌面端保留对话主栏和摘要侧栏。
- 小于 960 像素改为单栏，摘要移到对话下方。
- 消息区设置稳定最大高度和 `overflow-y-auto`。
- 输入框、消息、按钮和底部手动填写区不能相互覆盖。
- 390、768、1100、1440 像素不得横向滚动。
- 新追问和错误反馈使用可访问状态提示。
- 所有按钮支持键盘操作，尊重 `prefers-reduced-motion`。

## 10. 验收标准

- 页面上半部分没有新增向导或模式切换。
- 用户第一眼能看到当前问题、输入框和“发送并整理”。
- 页面明确说明“不用一次说全，系统会逐项追问”。
- 下方手动填写区仍可展开使用。
- 上半部分不展示 Agent、trace、认知风格、动机风险等术语。
- 一条自然语言可通过真实后端提取并持久化多个画像维度。
- 每轮只追问一个问题，会话刷新后可恢复。
- 只有真实服务端完成/提交状态才能进入诊断。
- 访谈阶段不提前生成正式路径和计划，旧 session 历史证据不被覆盖。
- 移动端和桌面端均无遮挡、溢出或无法滚动区域。

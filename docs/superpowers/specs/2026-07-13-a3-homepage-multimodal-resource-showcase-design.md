# A3 首页多模态资源展示设计

日期：2026-07-13

状态：已确认设计，待实施

## 1. 背景与目标

公开首页 `/a3` 已展示学习画像、入学诊断、本地知识库、AI 课堂、面对面辅导、证据回流和教师干预，但知识库与课堂之间缺少“个性化资源如何被生成并进入课堂”的产品证据。

本次改动在保留现有暗色、荧光绿和完整产品截图语言的前提下，新增“多模态资源包”章节，使首页叙事形成：

```text
本地知识库
-> 个性化多模态资源包
-> AI 课堂与 PPTX / 视频产物
-> 面对面辅导
```

目标用户是学生和赛事评审。章节必须让匿名访问者看懂系统能生成哪些资源，同时不泄露真实用户数据，也不伪造资源生成结果。

## 2. 设计方向

设计模式：保留现有品牌的定向升级。

设计语言：暗色编辑式产品展示，真实界面证据为主，荧光绿为唯一强调色。

设计参数：`DESIGN_VARIANCE 7`、`MOTION_INTENSITY 4`、`VISUAL_DENSITY 4`。

采用“真实界面截图 + 资源类型索引”方案，不采用七张同权功能卡，也不采用需要公开业务数据的实时资源流。

## 3. 信息架构

新增章节位于知识库章节之后、AI 课堂章节之前。首页故事顺序调整为：

1. 学习画像
2. 入学诊断
3. 本地知识库
4. 多模态资源包
5. AI 课堂
6. 面对面辅导
7. 真实证据
8. 教师干预

现有路由、主导航标签和锚点保持不变。`#learning-loop` 继续覆盖知识库到课堂的完整学习闭环。

## 4. 章节内容

章节标题表达“同一个目标，生成不同学习资源”，避免平台内部术语和无法验证的智能化描述。

资源类型索引严格来自 Django `RESOURCE_TYPES` 和 `RESOURCE_TYPE_LABELS`：

| 类型 | 首页名称 |
|---|---|
| `lecture_doc` | 课程讲解文档 |
| `knowledge_card` | 知识点速记卡 |
| `mind_map` | 知识点思维导图 |
| `practice_set` | 专项练习题 |
| `case_study` | 工程实践案例 |
| `code_lab` | 代码类实操案例 |
| `micro_video_script` | 短视频/动画脚本 |

资源索引采用紧凑的纵向或横向编号列表，不使用七张等尺寸卡片。每项只显示名称和简短用途，不显示虚构分数、进度或成功状态。

主视觉使用登录演示账号中真实生成或已存在的资源包界面截图。截图需展示资源包内容、引用或产物区域中的至少一项，并移除手机号、邮箱、绝对路径、API key、signed URL 和其他用户标识。

章节 CTA 使用“查看个性化资源”，指向 `/a3/recommendations`。匿名用户继续由现有认证边界处理，不新增绕过登录的业务接口。

## 5. 组件与数据边界

### 内容模型

在 `a3-homepage-content.ts` 中增加资源展示项，包含固定的公开文案、真实资源类型键、截图路径和替代文本。该数据仅用于营销展示，不代表生成成功状态。

### 页面组件

在首页故事组件中加入独立的资源展示章节。组件负责：

- 渲染标题、说明、七类资源索引和真实产品截图。
- 提供清晰 CTA。
- 保持服务端可输出的主要内容；若加入索引切换，只使用局部客户端状态。
- 不调用 `/api/resources/generate/`，不读取匿名用户资源包。

### 截图管线

扩展现有 `capture-a3-homepage-assets.mjs`：

- 使用学生演示账号打开 `/a3/recommendations` 或 `/a3/resources/[packId]`。
- 等待真实资源包区域完成加载。
- 仅执行 GET 和页面读取，不发送生成、收藏、反馈等业务写请求。
- 输出 `public/a3/assets/homepage/multimodal-resources.webp`。
- 复用敏感文本扫描、失败响应监控、原子替换和 WebP 校验。

若演示数据中没有可验证资源包，截图任务应明确失败，不使用前端 mock 或手工伪造成功界面。

## 6. 响应式与交互

桌面端采用不对称双栏：资源索引约占三分之一，真实界面截图占三分之二。截图保持完整可辨认，不使用覆盖关键内容的标签。

移动端改为标题、资源索引、截图、CTA 的单列顺序。截图使用稳定宽高比和 `object-fit: contain`，最长资源名称不得溢出。

动效仅用于章节进入和当前索引的轻量反馈，服务于阅读顺序。`prefers-reduced-motion` 下取消位移和过渡，不影响内容可见性。

## 7. 错误与退化策略

公开首页不依赖运行时资源 API，因此不会因用户未登录或后端暂时不可用而出现空白章节。

构建时必须保证截图文件存在、可解码、尺寸合理且非空白。图片加载失败时保留可读标题、资源索引和 CTA，不能用“生成成功”等状态占位。

## 8. 测试与验收

### 单元与内容契约

- 首页故事顺序包含 `resources`，且位于 `knowledge` 和 `classroom` 之间。
- 七种资源类型与后端 canonical 列表一致。
- 首页组件不调用资源生成 API，也不出现本地路径、signed URL 或平台内部实现名。
- CTA 指向真实 `/a3/recommendations` 路由。
- 新截图存在、可解码、尺寸合格且非空白。

### 浏览器验收

- 桌面和移动端均能看到完整标题、七类资源和真实截图。
- 不发生水平溢出、文字遮挡、CTA 换行或图片区布局跳动。
- 匿名访问 CTA 后进入现有登录流程；已登录访问进入推荐页。
- `prefers-reduced-motion` 下内容保持完整可见。

## 9. 非目标

- 不新增公开资源包 API。
- 不在匿名首页展示登录用户的实时资源。
- 不触发资源、课堂、PPTX 或视频生成。
- 不修改首页路由、主导航标签、品牌标识或认证流程。
- 不把 Django 生成结果伪装成 OpenMAIC PPTX 导出结果。
- 不部署服务器；实现验证完成后单独推送当前集成分支，再按部署流程更新线上环境。

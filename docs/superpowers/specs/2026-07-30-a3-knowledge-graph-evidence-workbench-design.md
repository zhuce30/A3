# A3 知识图谱证据导航工作台设计

> 状态：待用户审阅
> 日期：2026-07-30
> 页面：`/a3/knowledge-graph`
> 范围：重组现有资料图谱与课程路径图的前端体验，保留真实接口、真实图数据、证据链和学习闭环

## 1. 结论

知识图谱页应从“图谱展示与质量监控面板”改为“证据导航工作台”。学生进入页面后的核心任务只有四步：

```text
定位一个知识点
-> 看清它与哪些知识点相关
-> 核验关系和资料来源
-> 进入辅导、测评或原始资料继续学习
```

现有 `GET /api/kb/graph/`、`GET /api/learning/graph/` 和 `POST /api/learning/paths/generate/` 继续作为真实数据来源。第一批不重做图谱算法，不引入新图数据库，不把技术指标伪装成学生学习结果。

## 2. 截图审计

2026-07-30 的真实页面截图确认了以下问题。

### 2.1 首屏竞争

- 搜索、当前实体摘要、图谱质量、跳数切换和右侧实体详情同时出现，至少有五个视觉焦点。
- 画布内左、右两个浮层遮挡节点，中心关系区被压缩成狭窄通道。
- 图谱质量面板使用接近主内容的对比度，但它服务构建审计，不是学生的首要任务。
- 选中节点已具备高亮，但其余节点和边仍然过密，关系标签在中心区域堆叠。

### 2.2 纵向断裂

- 左侧主内容在“构建状态”后结束，右侧详情继续展示大量路径和来源证据。
- 页面滚动到第二屏时，中央出现大面积空白，用户只能在最右侧窄栏继续阅读。
- 详情栏依赖页面整体滚动，切换节点后难以保持图谱上下文。

### 2.3 信息层级错位

- `schemaVersion`、构建时间、Agent 说明、实体数量、关系密度和补抽轮次长期展示给学生。
- “标准解释”“路径证据”“来源证据”是真正有学习价值的内容，却被放进过长的常驻侧栏。
- 搜索当前只匹配已经加载到前端的节点，但界面没有说明搜索范围。

## 3. 设计目标与非目标

### 3.1 目标

1. 首屏只保留一个主工作区，并让画布成为最大可用区域。
2. 选择节点后，学生能在不离开图谱上下文的情况下理解关系和核验来源。
3. 详情内容在固定工作区内独立滚动，不能再次制造主栏空白、侧栏超长的问题。
4. 资料图谱与课程路径图在视觉和动作上明确区分。
5. loading、empty、error、partial、degraded、verified 和 unverified 状态均有可见反馈。
6. 所有学习动作进入真实路由，所有图谱信息继续来自真实 API。

### 3.2 非目标

- 第一批不增加图谱编辑、手工连边、批量合并实体或教师审核工作流。
- 第一批不替换 React Flow 或 D3 Force。
- 第一批不新增“AI 自动生成关系”按钮。
- 第一批不承诺全知识库实体搜索；现有搜索必须明确标注“搜索当前视图”。
- 第一批不改变 `a3.material-knowledge-graph.v1` 数据契约。

## 4. 推荐结构

页面由四个稳定区域组成：页头、工作区工具栏、图谱画布、上下文详情。

```text
┌────────────────────────────────────────────────────────────────────┐
│ 知识关系                                  刷新  数据状态  全屏     │
│ 从资料证据理解知识点之间的关系，并进入下一步学习                   │
├────────────────────────────────────────────────────────────────────┤
│ [资料图谱 | 课程路径] [搜索当前视图……] [一跳|二跳|全部] [重置]    │
├──────────────────────────────────────────────┬─────────────────────┤
│                                              │ 操作系统       已验证│
│                                              │ 系统 · 置信度 95%   │
│                 图谱画布                     │                     │
│                                              │ 标准解释            │
│        选中节点高亮，其他内容降噪            │ 相关关系            │
│                                              │ 支持断言            │
│                                              │ 来源证据            │
│                                              │                     │
│                                              │ [打开资料] [去辅导] │
├──────────────────────────────────────────────┴─────────────────────┤
│ 当前加载 38 个实体 · 51 条关系 · 二跳 · 数据已更新                 │
└────────────────────────────────────────────────────────────────────┘
```

### 4.1 页头

- 标题统一为“知识关系”，不再把技术实现“资料知识图谱”作为一级标题。
- 副标题为“从资料证据理解知识点之间的关系，并进入下一步学习”。
- 右侧保留刷新、数据状态和全屏三个动作。
- “数据状态”是次要按钮，点击后打开轻量浮层，展示 schema、构建状态、最近构建、质量指标和降级原因。
- 页面不再渲染独立的“构建状态”卡片。

### 4.2 工作区工具栏

- 工具栏位于画布上方，不悬浮遮挡节点。
- 左侧使用分段控制切换“资料图谱”和“课程路径”。
- 资料图谱显示搜索框、跳数控制和重置按钮。
- 课程路径显示课程名称、状态筛选和“根据画像重排路径”。
- 第一批搜索框占位文案固定为“搜索当前视图中的实体”，不得写成“搜索全部知识”。
- 搜索结果以工具栏下方的紧凑候选菜单出现，最多展示 8 项；键盘上下键移动、Enter 选择、Esc 关闭。

### 4.3 图谱画布

- 画布不再包裹于 `A3Card` 的正文卡片中，采用单一边界的工作区表面。
- 桌面端最小高度 `560px`，理想高度为 `calc(100dvh - A3 shell header - page header - toolbar - page padding)`。
- 画布内部只保留 React Flow Controls；搜索、实体摘要和质量面板全部移出画布。
- 默认聚焦最高连接度实体，或使用路由/当前学习上下文传入的中心实体。
- 选中节点保持高对比描边和名称；一跳邻居正常显示；其余节点降低到约 12% 至 18% 不透明度。
- 关系标签仅在边被选中、端点被选中或键盘聚焦时出现。
- 节点点击继续触发以该节点为中心的真实邻域加载，并合并到当前图数据。
- 双击节点不绑定额外动作，避免与拖动画布冲突。
- 全屏模式保留相同工具栏和详情结构，不能只放大裸画布。

### 4.4 上下文详情

桌面宽屏下，详情作为工作区右侧 `360px` 至 `400px` 的上下文栏；它与画布同高并拥有独立滚动容器。没有选中节点时，该区域收起，画布使用全部宽度。

信息顺序固定为：

1. 实体名称、类型、置信度和验证状态。
2. 标准解释或摘要。
3. 与当前学习目标的关系；第一批若接口没有该字段，则不显示空占位。
4. 可读关系路径。
5. 支持断言及其验证状态。
6. 来源证据，按资源和页码聚合。
7. 固定底部动作区。

固定底部动作区：

- “打开资料”：仅在证据能够映射到真实知识库资源时启用；链接到真实资料详情或知识库页并携带资源定位信息。
- “去辅导”：链接到 `/a3/coaching?knowledgePointId=<nodeId>`。
- “专项测评”：链接到 `/a3/assessment?knowledgePointId=<nodeId>`。
- 不生成没有真实路由或后端行为的按钮。

关系被选中时，详情栏切换为关系模式：

```text
源实体 -> 中文关系名称 -> 目标实体
关系类型
置信度与降级状态
支持该关系的断言
来源证据
```

关闭详情不会清除已加载图数据；只清除当前 `selectedNodeId` 和 `selectedEdgeId`。重置才恢复默认中心实体、默认跳数和空搜索。

### 4.5 底部状态栏

状态栏使用低对比度文本，不使用卡片：

```text
当前加载 38 个实体 · 51 条关系 · 二跳 · 数据已更新
```

- `focus.partial` 或 `focus.hasMore` 为真时追加“当前为局部视图”。
- `build.degraded` 为真时追加可点击的“部分内容为降级抽取”。
- 实体总数、关系总数等全图指标放入“数据状态”，状态栏只显示当前加载范围。

## 5. 两种图谱的职责

### 5.1 资料图谱

回答“教材和资料中，这些概念如何关联，证据在哪里”。

- 节点颜色表达实体类型。
- 详情以定义、关系、断言和来源为主。
- 主动作是打开资料、去辅导、专项测评。
- 数据来自 `GET /api/kb/graph/`。

### 5.2 课程路径

回答“我应该按什么顺序学习，当前进展如何”。

- 节点颜色只表达学习状态，不复用资料实体类型颜色。
- 使用从左到右的先修关系布局，不使用资料图谱的自由力导向视觉。
- 详情以章节、掌握状态、进度和下一步动作为主。
- 主动作是今日任务、针对性辅导、针对性测评、重排路径。
- 数据来自 `GET /api/learning/graph/`；重排使用 `POST /api/learning/paths/generate/`。

## 6. 状态模型

页面状态应被显式建模，避免由多个布尔值产生互相冲突的界面。

```text
activeView: material | course
loadState: idle | loading | ready | empty | error
selection: none | node(nodeId) | edge(edgeId)
detailState: closed | open
depth: one | two | all
searchState: idle | typing | results | noResults
dataHealth: verified | partial | degraded
```

关键转换：

```text
进入资料图谱 -> loading -> ready/empty/error
选择节点 -> node selection -> 加载邻域 -> 合并节点与边 -> 打开详情
选择关系 -> edge selection -> 打开关系详情
关闭详情 -> selection none -> 保留画布位置与已加载数据
改变跳数 -> 保留中心节点 -> 重新加载对应邻域
切换图谱 -> 保存各自最后选择和视口 -> 恢复目标图谱状态
重置 -> 默认中心 + 一跳 + 空搜索 + fitView
```

## 7. 加载、空、错误和降级状态

### 7.1 加载

- 首次加载显示与工作区结构一致的骨架，不使用遮住整个画布的白色旋转层。
- 邻域增量加载时保留当前图，只在中心节点附近和状态栏显示加载反馈。
- 详情切换使用 150 至 220ms 的透明度/位移动画，不改变工作区总宽高。

### 7.2 空状态

- 资料图谱为空：说明需要上传并完成解析，主动作链接 `/a3/knowledge-base`。
- 课程路径为空：说明需要完成诊断或生成路径，提供真实生成动作或诊断入口。
- 搜索无结果：显示“当前视图没有匹配实体”，同时提供“清除搜索”；不得暗示全知识库没有结果。

### 7.3 错误状态

- 首次请求失败时在工作区中央显示中文错误、重试按钮和返回知识库入口。
- 邻域请求失败时保留现有图，使用行内提示“未能展开该知识点，已保留当前视图”。
- 路径重排失败时保留原路径和当前选择。
- 不展示 traceback、请求地址或内部异常名称。

### 7.4 证据状态

- `verified=true` 且证据非空：显示“已验证”。
- `verified=false`：显示“待验证”，不得使用绿色可信标识。
- `degraded=true`：显示“降级抽取”，并在证据项中展示可读 warning。
- 证据为空：显示“暂无可核验来源”，不渲染空白证据列表。

## 8. 响应式规则

### 8.1 宽屏：`>= 1280px`

- 详情打开时使用 `minmax(0, 1fr) 380px`。
- 详情关闭时画布占满工作区。
- 详情栏内部滚动，页面主体不因证据数量继续增长。

### 8.2 中等屏幕：`768px - 1279px`

- 详情使用覆盖画布右侧的抽屉，宽度为 `min(400px, 44vw)`。
- 抽屉有明确关闭按钮和焦点管理。
- 工具栏允许搜索独占一行，分段控制和动作保持第二行。

### 8.3 移动端：`< 768px`

- 默认进入“关系列表”而非力导向画布；用户可通过 `[列表 | 图谱]` 切换。
- 列表按“与中心实体直接相关”和“其他已加载关系”分组。
- 图谱模式维持稳定 `min-height: 480px`，隐藏 MiniMap，仅保留缩放与适配按钮。
- 详情使用底部抽屉，最大高度 `82dvh`，标题和底部动作固定，正文独立滚动。
- 所有按钮最小点击区域 `40px`，320px 宽度下不得产生页面级横向滚动。

## 9. 可访问性与键盘交互

- 分段控制使用 `role="tablist"`、`role="tab"` 和 `aria-selected`。
- 详情栏使用 `aside`；覆盖式抽屉使用 `role="dialog"` 和可读标题。
- 节点需要可聚焦，并提供“名称、类型、置信度、关系数量”的无障碍名称。
- 搜索候选使用 combobox/listbox 语义。
- Escape 优先关闭搜索候选，再关闭详情抽屉。
- 焦点不能只靠颜色表达；选中节点保留描边、尺寸或图标差异。
- 正文对比度至少 4.5:1，状态标签不能只依赖红绿颜色。

## 10. 组件边界

第一批建议将现有大组件收敛为以下边界：

```text
KnowledgeGraphView
├── KnowledgeGraphHeader
├── KnowledgeGraphToolbar
│   ├── GraphViewTabs
│   ├── MaterialGraphSearch
│   └── GraphDepthControl
├── KnowledgeGraphWorkspace
│   ├── MaterialGraphCanvas
│   ├── CoursePathCanvas
│   ├── MobileRelationList
│   └── KnowledgeGraphDetailDrawer
├── KnowledgeGraphStatusBar
└── GraphDataStatusPopover
```

文件级建议：

- `knowledge-graph-view.tsx`：只负责请求、状态编排和图谱切换。
- `material-focused-flow.tsx`：只负责资料图谱的可见子图、布局和视觉状态。
- `material-detail-panel.tsx`：拆出实体模式、关系模式、证据列表和底部动作。
- `material-graph-panels.tsx`：移除画布浮层职责，保留为工具栏与数据状态组件，或重命名后拆分。
- 新增 `knowledge-graph-workspace.tsx`：管理同高画布与详情抽屉布局。
- 新增 `knowledge-graph-status-bar.tsx`：管理局部视图、加载和降级提示。
- 新增 `material-relation-list.tsx`：移动端默认列表视图。

## 11. 数据流和接口边界

### 11.1 第一批保持不变

```http
GET /api/kb/graph/?depth=1&limit=<n>
GET /api/kb/graph/?centerId=<id>&depth=<1|2|all>&limit=<n>
GET /api/learning/graph/
POST /api/learning/paths/generate/
```

当前资料图谱请求继续返回：

```text
nodes, edges, claims, summary, focus, build, quality, nextAction
```

### 11.2 第二批可选扩展

若要实现真正的全图实体搜索，建议扩展同一接口：

```http
GET /api/kb/graph/?q=<query>&limit=8&mode=search
```

建议响应增加：

```json
{
  "success": true,
  "results": [
    {
      "id": "entity-id",
      "label": "操作系统",
      "type": "system",
      "summary": "...",
      "confidence": 0.95,
      "resourceCount": 2
    }
  ]
}
```

选择搜索结果后，再调用现有 `centerId + depth` 邻域接口。这样搜索与图加载职责清晰，也不会一次返回完整图。

## 12. 测试策略

实施必须遵循测试先行。

### 12.1 静态契约测试

- 保留真实 API、D3 Force、React Flow、增量邻域加载和证据类型测试。
- 新增工作区、工具栏、状态栏、详情抽屉和移动端列表的组件存在性测试。
- 删除要求质量面板必须悬浮在画布内的旧断言。
- 断言页面不再包含固定 `h-[680px]` 和底部独立“构建状态”卡片。

### 12.2 组件行为测试

- 详情关闭时画布占满工作区。
- 选中节点后详情打开，关闭详情不丢失已加载图数据。
- 搜索文案明确为当前视图，搜索无结果状态可恢复。
- `verified`、`unverified`、`degraded` 和无证据状态分别渲染正确。
- 资料图谱与课程路径切换后恢复各自选择。

### 12.3 E2E

- 桌面：选择“操作系统”，验证详情、路径证据和来源；详情正文滚动时画布不滚走。
- 桌面：关闭详情，验证画布扩展到完整工作区宽度。
- 中屏：详情作为覆盖抽屉出现，关闭后焦点返回被选节点。
- 移动端：默认关系列表，可切换图谱，底部详情不产生横向溢出。
- 错误：拦截邻域请求失败，确认当前图仍保留且出现行内重试反馈。

### 12.4 视觉验收视口

```text
1440 x 900
1280 x 800
768 x 1024
390 x 844
320 x 720
```

每个视口检查：无页面级横向滚动、文本不遮挡、按钮不截断、画布非空、详情可关闭、固定动作不覆盖正文。

## 13. 分批实施

### P0：结构和阅读体验

- 重组为页头、工具栏、工作区、状态栏。
- 移除画布内搜索、迷你实体卡和质量浮层。
- 移除底部独立构建状态卡。
- 详情改为按选择出现、与画布同高且内部滚动。
- 画布改用响应式高度。
- 保留现有接口和数据契约。

### P1：任务闭环和移动端

- 补充打开资料、去辅导和专项测评的真实动作。
- 增加移动端关系列表和底部详情抽屉。
- 完成键盘搜索和焦点恢复。
- 补齐局部加载失败、无证据和降级状态。

### P2：全图搜索和教师审计

- 增加后端全图实体搜索。
- 教师或管理员可进入图谱质量审计视图。
- 将 schema、批处理、补抽轮次和失败批次接入能力页 trace，而不是回到学生主视图。

## 14. 验收标准

满足以下条件才算完成：

1. 首屏画布内不存在搜索卡、实体摘要卡或质量卡。
2. 未选择实体时没有空白常驻详情栏。
3. 详情打开后与画布同高，证据数量不会拉长整页。
4. 选择实体仍调用真实邻域接口并保留增量合并。
5. 所有断言和来源继续展示验证、降级及页码/幻灯片定位信息。
6. 资料图谱和课程路径图具有不同的信息与动作层级。
7. 移动端默认可用列表，不要求用户在小屏操作密集图谱。
8. loading、empty、error、partial、degraded、verified、unverified 均有明确中文反馈。
9. 320px 至 1440px 验收视口无页面级横向滚动或内容遮挡。
10. `tsc`、lint、知识图谱 Vitest、后端 graph API 测试和 Playwright 交互测试通过。

## 15. 风险与控制

- **详情收起导致可发现性下降**：首次进入时默认选择中心实体并打开详情；用户主动关闭后尊重其选择。
- **抽屉覆盖图谱上下文**：中屏抽屉半透明遮罩仅覆盖非交互区域，关闭后恢复原视口和焦点。
- **搜索范围被误解**：第一批在占位文案和无结果文案中明确“当前视图”。
- **移动列表与图谱逻辑重复**：两者共用同一个可见子图结果和选择状态，不复制数据加载逻辑。
- **旧静态测试绑定实现字符串**：先将测试改为面向行为和组件职责，再实施结构调整。
- **视觉降噪破坏图谱语义**：保留类型颜色和验证状态；只减少非焦点内容的不透明度和常驻标签。

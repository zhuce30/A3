# A3 错题导出与薄弱点复习讲义设计

## 1. 目标

为 `/a3/wrong-notebook` 增加真实的错题文件导出和个性化复习讲义生成能力：

- 错题可按复习状态导出为 Word、Excel、PDF。
- 复习讲义依据学生真实错题、错因、复习状态和画像薄弱点生成。
- 讲义章节必须有本地知识库证据、来源位置和验证状态。
- 讲义生成是可追踪、可取消、可重试的后台任务，不阻塞页面请求。
- 所有下载和任务接口只允许访问当前登录用户的数据。

## 2. 范围与筛选

导出和讲义生成共用四种范围：

| 范围 | 条件 | 默认值 |
|---|---|---|
| `active` | 未掌握错题 | 是 |
| `due` | 未掌握且今天或已到期 | 否 |
| `mastered` | 已掌握错题 | 否 |
| `all` | 当前用户全部错题 | 否 |

请求创建时保存错题快照。文件和讲义只使用该快照，不因生成期间用户重练导致内容前后不一致。

## 3. 用户体验

错题本顶部提供两个真实操作：

1. `导出错题`
   - 选择范围和格式：Word、Excel、PDF。
   - 单格式直接下载；多格式请求返回一个 ZIP，文件名包含范围和日期。
   - 显示生成中、成功、失败和重试状态。
2. `生成复习讲义`
   - 使用当前范围创建后台讲义任务。
   - 任务历史显示排队、生成中、成功、失败、已取消。
   - 成功后提供 Word 和 PDF 下载，失败可重试，生成中可取消。

移动端使用底部操作区或折叠菜单，不能让三个下载按钮挤压错题内容。空错题集、无薄弱点、无可用资料和任务失败都显示明确的下一步。

## 4. 文件内容

### 4.1 Word 与 PDF 错题文件

- 标题、学生可见姓名、导出范围和生成时间。
- 复习摘要：错题数、待巩固数、已掌握数、重点知识点。
- 按知识点分组的目录。
- 每题包含题干、选项、上次错误答案、正确答案、错误次数、错因、解析和下次复习时间。
- 页脚包含“由智学引擎生成”的产品标识，不写入本地绝对路径、API key 或内部 trace。

### 4.2 Excel 错题文件

一题一行，包含：

`错题ID、知识点、章节、题干、选项、上次错误答案、正确答案、错因、错误次数、连续答对次数、掌握状态、上次错误时间、下次复习时间、题目来源`。

Excel 使用 UTF-8/Unicode 正确写入中文，日期使用统一时区格式，并对题干和选项做单元格长度限制，防止生成异常大文件。

### 4.3 复习讲义

按薄弱知识点分章，每章包含：

1. 核心概念和先修知识。
2. 该知识点对应的错题与错因归纳。
3. 易混淆点和解题检查清单。
4. 变式练习与答案解析。
5. 下一步复习建议。
6. 引用资料标题、页码或位置、证据片段和验证状态。

答案与解析集中在文末，避免阅读讲义时直接看到答案。讲义以 Word 和 PDF 为下载格式，Excel 只服务于错题明细统计。

## 5. 薄弱点排序与生成链路

薄弱点优先级由服务端计算，不由模型自由猜测：

```text
待巩固错题数量
+ 累计错误次数
+ 最近错误时间
+ 到期/逾期程度
+ 学习画像 weakPoints 命中
-> 薄弱点优先级
```

生成流程：

```text
筛选错题
-> 锁定错题/画像快照
-> 计算薄弱点排序
-> RetrieverAgent 检索本地知识库
-> 生成结构化章节草稿
-> VerifierAgent 验证引用、claims 和安全状态
-> 生成 Word/PDF
-> 保存 artifact 与 trace
```

大模型只负责有证据约束的解释、归纳和变式题表达；算法计算、错题统计、排序、答案和复习时间由后端确定。模型不可用或证据不足时，降级为“基于错题与题目解析的复习提纲”，并明确标注资料不足，不能伪造教材页码或来源。

相同用户、相同范围、相同快照在任务仍排队或运行时复用现有任务，避免重复消耗。取消任务后，迟到的 worker 不得写回 succeeded artifact。

## 6. 接口契约

### 6.1 错题导出

```http
POST /api/assessments/wrong-questions/export/
```

请求：

```json
{
  "scope": "active",
  "format": "docx"
}
```

`scope` 为 `active|due|mastered|all`，`format` 为 `docx|xlsx|pdf`。成功响应为文件流，设置正确的 `Content-Type`、`Content-Disposition` 和安全文件名。多格式下载使用显式的 ZIP 请求，不接受任意扩展名。

### 6.2 复习讲义任务

```http
POST /api/assessments/wrong-questions/review-handouts/
GET  /api/assessments/wrong-questions/review-handouts/
GET  /api/assessments/wrong-questions/review-handouts/<job_id>/
POST /api/assessments/wrong-questions/review-handouts/<job_id>/cancel/
```

创建请求：

```json
{
  "scope": "active"
}
```

任务响应至少包含 `jobId、scope、status、progress、stage、createdAt、updatedAt、snapshotId`。成功任务增加 `docxDownloadUrl、pdfDownloadUrl、traceId、citations、verified`；失败响应只返回用户可读错误，不暴露 traceback。所有接口校验登录用户和任务所有权。

## 7. 后端边界

- 使用独立的讲义任务/产物记录，不把生成结果塞入用户画像 JSON。
- 导出服务只读取经过权限过滤的 `WrongQuestion`、`Question`、`KnowledgePoint` 和必要的画像薄弱点。
- 生成任务进入资源生成专用 Celery 队列，遵循现有取消、重试、终态保护和 trace 规则。
- 任务和产物保存结构化状态，文件生成失败时清理不完整文件并保留失败原因。
- 设置错题数量、章节数量、讲义长度和单文件大小上限。
- 下载接口再次校验用户所有权，禁止通过 job ID 横向访问其他用户文件。

## 8. 验证计划

后端测试覆盖：

- 四种范围筛选和空数据返回。
- Word/Excel/PDF 内容、中文编码、Content-Type 和安全文件名。
- 用户隔离、无效范围/格式、超限输入和失败错误信息。
- 薄弱点排序、快照一致性、引用验证和模型不可用降级。
- 任务幂等、取消、重试、迟到 worker 不覆盖取消状态。

前端测试覆盖：

- 导出面板的范围/格式选择和真实下载调用。
- 讲义任务的 loading、success、error、empty、cancel 和 retry 状态。
- 移动端操作区不遮挡错题列表。

文件验收必须实际打开生成物：使用 Word/PDF 解析或渲染检查页面结构，使用 Excel 解析库检查工作表、表头和中文内容，不能只断言 HTTP 200。

## 9. 非目标

- 不新增在线协作文档编辑器。
- 不把 Excel 作为复习讲义格式。
- 不允许模型直接决定正确答案、错题统计或复习间隔。
- 不在前端生成伪造的 Word/PDF/Excel 文件。

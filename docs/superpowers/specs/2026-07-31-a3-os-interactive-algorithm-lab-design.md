# A3 操作系统交互式算法实验室设计

> 状态：待用户审阅
> 日期：2026-07-31
> 页面：`/a3/labs`、`/a3/labs/[labId]`
> P0 范围：CPU 调度对比、页面置换对比
> 参考：小红书“算法可视化开发”视频的工作台布局和逐步演示交互；不复制其品牌、代码或具体视觉资产

## 1. 结论

A3 应新增“操作系统交互式算法实验室”，把当前“阅读代码 -> 运行 -> 看输出”的实操体验扩展为：

```text
画像或诊断定位薄弱点
-> 推荐对应实验
-> 学生配置输入并先做预测
-> 算法确定性逐步运行
-> 观察关键状态与多算法指标
-> 回答步骤检查题
-> 写回学习事件和错误证据
-> 更新推荐、专项练习与学习报告
```

算法本体必须在浏览器中以确定性的 TypeScript 纯函数和状态机运行，不依赖大模型，不需要 GPU，也不新增模型 API Key。现有模型能力仅作为可选增强，用于生成个性化解释、实验总结和后续建议；模型不可决定算法状态、正确答案或评分。

P0 只实现两个高价值实验：

1. CPU 调度对比：FCFS、SJF、非抢占优先级、时间片轮转 RR。
2. 页面置换对比：FIFO、LRU、OPT。

这两个实验覆盖 A3 当前画像中的“处理机调度算法”和“虚拟内存与页面置换”薄弱点，也是操作系统课程中最适合逐步可视化、并排对比和客观判分的内容。

## 2. 当前基础与缺口

### 2.1 可复用能力

- `CodeLabWorkbench` 已提供代码预览、编辑、运行、判题、测试用例、检查点和学习反馈。
- `/a3/resources/[packId]/[resourceType]` 已具备资源独立页面和资源包上下文。
- `LearningEvent` 已支持资源打开、完成、跳过、收藏、练习开始和提交等事件，并能进入学习效果统计。
- 画像、诊断、学习路径、今日任务、推荐、错题本和报告已经形成真实后端闭环。
- A3 已有统一页面壳、侧边导航、卡片、状态组件、Markdown 和暗色模式基础。

### 2.2 现有缺口

- 代码实验只能证明程序能运行，不能展示算法内部状态为什么发生变化。
- 学生无法把 CPU 就绪队列、页框内容、安全序列或磁头轨迹与代码执行建立稳定映射。
- 没有“先预测、再运行、定位错误步骤”的学习过程证据。
- 同一输入下缺少多算法并排对比，学生难以理解算法之间的真实代价。
- 推荐系统可以推荐“代码实验”，但不能精确推荐某个可交互算法、预设输入和难度。
- 教师和报告端看不到学生具体在哪一步形成误解。

## 3. 方案比较

### 3.1 方案 A：嵌入现有代码实验

在 `CodeLabWorkbench` 中增加一个可视化标签页。

优点：入口集中，能把代码和动画直接放在同一资源中。

缺点：现有页面已经包含代码、stdin、stdout、测试用例、检查点和学习栏，再加入大型画布会造成信息拥挤；算法实验也不一定需要学生编辑代码。

结论：不作为主方案。后续可以从代码实验链接到对应交互实验。

### 3.2 方案 B：独立交互实验室，接入现有学习闭环

新增 `/a3/labs` 和 `/a3/labs/[labId]`，同时允许资源包、今日任务、学习路径和测评结果链接到实验。

优点：画布空间稳定；输入、动画、指标和日志可以形成专业实验工作台；不破坏现有代码实验；适合持续扩展银行家算法、磁盘调度和同步互斥。

缺点：需要新增路由、实验定义注册表、模拟器内核和实验事件契约。

结论：采用该方案。

### 3.3 方案 C：由大模型实时生成算法动画

让模型根据主题输出场景或前端动画代码。

优点：主题扩展快。

缺点：算法状态不可验证、结果不稳定、延迟和成本高、容易产生教学错误，不符合可复现测评要求。

结论：禁止作为核心算法实现，仅允许模型生成自然语言辅导内容。

## 4. 产品定位与页面分工

### 4.1 `/a3/labs`

实验目录页承担四个任务：

1. 展示“为你推荐”，根据画像薄弱点、当前路径和最近错题排序。
2. 展示操作系统实验分类和掌握状态。
3. 恢复最近一次未完成的实验。
4. 进入具体实验，不在目录页堆放动画预览。

P0 分类：

```text
处理机调度
└── CPU 调度算法对比

存储管理
└── 页面置换算法对比
```

后续分类：

```text
死锁处理 -> 银行家算法
设备管理 -> 磁盘调度
进程同步 -> 生产者消费者与信号量
```

### 4.2 `/a3/labs/[labId]`

实验详情页是单一主工作区，负责输入、预测、执行、观察、检查和提交。

P0 `labId`：

```text
cpu-scheduling
page-replacement
```

### 4.3 现有页面接入

- 今日任务：任务类型可指向具体实验和预设难度。
- 学习路径：知识点节点可显示“进入交互实验”。
- 推荐：新增真实动作 `interactive_lab`，包含 `labId`、推荐原因和预设参数。
- 资源包：`code_lab` 可以附带 `relatedLab`，但不改变原有代码实验契约。
- 测评和错题本：调度或页面置换错误可推荐对应实验。
- 报告：展示实验完成数、预测准确率、错误步骤类型和实验后测评变化。
- 教师工作台：P1 展示班级常见错误步骤和实验完成情况。

## 5. 视觉与布局

### 5.1 视觉方向

参考视频的专业实验台结构，但适配 A3 现有浅黄色、深绿色和金色品牌体系：

- 页面底色使用克制的暖白或浅米色，不使用纯黑大面积背景。
- 主操作使用 A3 深绿色；运行中的关键状态使用金色；错误或被淘汰状态使用暗红色。
- 画布和数据面板使用单层边界，不在大卡片内继续嵌套装饰卡片。
- 标题保持学习软件尺度，不使用营销页大标题。
- 播放、暂停、上一步、下一步、重置和全屏使用 Lucide 图标按钮并提供 tooltip。
- 算法选择使用复选框或分段控制；速度和时间片使用滑块或数值输入。
- 动画以状态变化为核心，不加入与教学无关的粒子、漂浮和持续弹跳效果。

### 5.2 桌面布局

```text
┌─────────────────────────────────────────────────────────────────────┐
│ CPU 调度算法对比                         学习目标  进度  退出实验   │
├───────────────┬───────────────────────────────────┬─────────────────┤
│ 输入与案例    │                                   │ 关键状态        │
│               │                                   │                 │
│ 进程参数      │          主可视化画布             │ 当前时间        │
│ 算法选择      │   甘特图 / 页框 / 队列 / 访问序列 │ 当前进程/页面   │
│ 时间片        │                                   │ 指标与结果      │
│ 预设案例      │                                   │                 │
├───────────────┴───────────────────────────────────┴─────────────────┤
│  上一步  播放/暂停  下一步  重置    速度      时间轴  18 / 42       │
├───────────────────────────────────────┬─────────────────────────────┤
│ 当前步骤解释 / 执行日志 / 代码映射    │ 预测与检查问题              │
└───────────────────────────────────────┴─────────────────────────────┘
```

稳定尺寸：

- 工作区宽度使用 A3 主内容最大宽度，不突破侧边导航边界。
- 主画布桌面端最小高度 `430px`，优先使用 `calc(100dvh - header - controls)`。
- 左栏建议 `260px` 至 `300px`，右栏建议 `280px` 至 `320px`。
- 控制栏高度固定，播放状态、标签和提示不能改变布局高度。
- 日志区默认折叠为一行摘要，展开后在固定高度内独立滚动。

### 5.3 CPU 调度画布

画布由三个稳定区域组成：

1. 顶部时间标尺。
2. 每种算法一条甘特图轨道。
3. 当前算法的就绪队列和运行进程详情。

并排对比最多同时启用四种算法。每种进程拥有稳定颜色，颜色在所有算法轨道中保持一致。切换步骤时只移动时间指示线和更新当前状态，不重排整张图。

指标区展示：

```text
平均等待时间
平均周转时间
平均响应时间
上下文切换次数
完成顺序
```

### 5.4 页面置换画布

画布由访问序列、页框矩阵和算法对比轨道组成：

- 当前访问页面有明显焦点环。
- 每一步展示命中或缺页。
- 被淘汰页、调入页和保持页使用不同颜色与图标，不只依靠红绿。
- 点击任一步可查看 FIFO 队列、LRU 最近使用次序或 OPT 下一次访问依据。

指标区展示：

```text
缺页次数
命中次数
缺页率
淘汰次数
当前页框
```

### 5.5 响应式规则

`>= 1280px`：使用左输入、中画布、右状态三栏。

`768px - 1279px`：输入和状态变为画布上方两个可折叠面板；画布保持全宽。

`< 768px`：按“输入 -> 运行 -> 结果”分段呈现；默认只显示单个算法，算法对比改为指标表；控制栏固定在画布下方而不是粘在视口底部。

移动端画布最小高度 `360px`，页面不得出现横向滚动；甘特图和访问序列自身可以横向平移，并提供“回到当前步骤”按钮。

## 6. 交互流程

### 6.1 实验状态机

```text
idle
-> configured
-> predicted
-> running | paused
-> completed
-> submitted
```

附加状态：

```text
invalid_input
simulation_error
event_sync_pending
event_sync_failed
```

页面刷新时，P0 从 `sessionStorage` 恢复未提交的输入、算法选择和当前步骤；已经提交的实验结果从后端学习事件或实验记录恢复。P1 再增加跨设备恢复。

### 6.2 输入与预设

CPU 调度输入：

```text
processId
arrivalTime
burstTime
priority
timeQuantum
```

页面置换输入：

```text
referenceString
frameCount
```

每个实验至少提供三个确定性预设：基础、易错、对比明显。预设保存在代码注册表中并有固定版本，不能由模型临时生成后直接参与评分。

### 6.3 预测优先

学生点击运行前，页面提出一个不阻塞使用的预测问题：

- CPU 调度：“你认为哪种算法的平均等待时间最低？”
- 页面置换：“你认为哪种算法的缺页次数最少？”

学生可以选择答案或明确跳过。预测结果在实验完成前不显示对错，避免答案泄露。实验结束后同时展示预测、真实指标和原因。

### 6.4 播放控制

必须支持：

- 播放/暂停。
- 上一步/下一步。
- 速度 `0.5x / 1x / 1.5x / 2x`。
- 时间轴点击和拖动。
- 重置到第 0 步。
- 跳到第一个差异步骤。
- 全屏画布。

拖动时间轴只改变 `currentStepIndex`，不能重新运行算法，也不能产生新的学习事件。算法输入或算法选择变化时才重新计算步骤数组。

### 6.5 完成与提交

只有满足以下条件才允许标记完成：

1. 至少完整运行到最后一步一次。
2. 完成实验后的两个检查问题。
3. 结果契约校验通过。

提交后显示：

- 预测是否正确。
- 检查题得分。
- 最常停留或回看的步骤。
- 本次掌握证据。
- 下一步真实动作：专项练习、相关代码实验或返回今日任务。

### 7.2 统一实验契约

```ts
type AlgorithmLabDefinition<TInput, TState, TMetrics> = {
  id: string
  version: string
  title: string
  knowledgePointCodes: string[]
  presets: AlgorithmLabPreset<TInput>[]
  validateInput: (input: TInput) => ValidationResult
  simulate: (input: TInput, algorithms: string[]) => SimulationRun<TState, TMetrics>
  checkpoints: LabCheckpoint[]
}

type SimulationStep<TState> = {
  index: number
  clock: number
  action: string
  activeAlgorithmIds: string[]
  state: TState
  changed: string[]
  explanationKey: string
}

type SimulationRun<TState, TMetrics> = {
  schemaVersion: 'a3.algorithm-lab-run.v1'
  labId: string
  labVersion: string
  inputHash: string
  steps: SimulationStep<TState>[]
  metrics: Record<string, TMetrics>
  invariants: InvariantResult[]
}
```

`explanationKey` 映射到经过审核的本地中文模板。P0 不把模型输出写进 `SimulationStep`，确保同一输入得到同一结果和同一核心解释。

### 7.3 动画机制

- 算法先同步计算完整 `SimulationRun`，再由播放器消费步骤。
- 播放器使用 `requestAnimationFrame` 或受控计时器推进索引，不在每帧重新运行算法。
- 页面隐藏时自动暂停，恢复后不补播遗漏步骤。
- `prefers-reduced-motion` 下取消位移动画，只更新颜色、文本和焦点环。
- React key 必须由稳定的进程、页和步骤标识组成，不使用随机数或当前时间。

### 7.4 算法正确性

核心算法不手工散落在 React 组件中。每个算法是独立纯函数，并使用示例测试、性质测试和不变量校验：

- 所有进程最终完成且 CPU 不会同时运行两个进程。
- 甘特图总执行时间与 burst、空闲和上下文规则一致。
- 等待时间、周转时间和响应时间满足定义。
- 页框数量从不超过 `frameCount`。
- 命中不增加缺页数，缺页必然产生调入；满页框时产生合法淘汰。
- OPT 淘汰的是未来最晚使用或不再使用的页面。

### 8.2 专用学习事件

完成接口内部写入 `LearningEvent`，而不是由前端分别调用多个事件接口。建议事件：

```text
algorithm_lab_started
algorithm_lab_completed
algorithm_lab_checkpoint_submitted
```

P0 必须扩展现有事件白名单并使用上述专用类型，同时固定 `targetType=algorithm_lab`、`targetId=labId` 和 `metadata.labVersion`。不得把交互实验长期伪装成普通资源或普通练习事件。资源包和今日任务的完成联动由后端在专用实验事件成功写入后执行。

### 8.3 保存范围

后端只保存：

- 实验与版本。
- 输入哈希和预设标识。
- 算法选择。
- 预测和检查题结果。
- 汇总指标。
- 总时长、回放次数和重点复查步骤。
- 资源包、今日任务和知识点关联。

后端不保存每一帧的完整 UI 状态，避免事件数据膨胀。P1 教师回放需要时，再增加经过压缩的操作轨迹或关键步骤序列。

### 8.4 画像和报告回流

一次完成不直接把薄弱点标记为“已掌握”。画像更新规则至少需要：

- 完成实验。
- 检查题达到阈值。
- 后续专项测评有正确作答证据。

报告增加：

```text
交互实验完成数
预测准确率
检查题正确率
高频复查步骤
实验前后专项测评变化
数据不足提示
```

## 9. 大模型边界

### 9.1 不调用模型的能力

- 算法执行和步骤生成。
- 输入校验。
- 指标计算。
- 正确答案和评分。
- 基础步骤解释。
- 预设案例。
- 完成判定。

### 9.2 可选模型增强

- 根据画像在已验证参数范围内选择预设和难度。
- 将本地步骤证据改写成适合学生基础的解释。
- 根据检查题和回看步骤生成学习总结。
- 推荐下一项实验、代码实验或专项题。

### 9.3 降级规则

- 模型不可用时，实验全部核心功能继续运行。
- 页面显示经过审核的本地解释和规则建议。
- 不显示“AI 分析成功”等虚假状态。
- 模型解释必须携带 `labId`、`labVersion`、步骤指标和知识库来源，并通过现有 Verifier/Safety 能力。
- 模型不得修改模拟器输出、学生分数或完成状态。

## 10. 错误、空状态与安全

### 10.1 输入错误

- 进程 ID 重复、到达时间或运行时间非法时，在对应行显示错误，不启动模拟。
- RR 未设置合法时间片时禁用运行，并说明允许范围。
- 页面序列为空、页号非法或页框数量超限时显示正常中文错误。
- 输入行数和序列长度设置上限，避免浏览器生成过大的步骤数组。

P0 建议上限：

```text
进程数：1 至 20
arrivalTime / burstTime：0 至 999
时间片：1 至 100
页面访问序列：1 至 100
页框数：1 至 10
```

### 10.2 模拟错误

算法不变量校验失败时停止提交，保留输入并显示“实验计算未通过校验，请重置后重试”。前端不得把异常堆栈显示给学生。

### 10.3 事件同步错误

实验已经在本地完成但后端写回失败时：

- 保留本地结果。
- 显示“实验已完成，学习记录尚未同步”。
- 提供单独重试同步按钮。
- 使用 `eventId` 保证重复提交幂等。
- 不能因为同步失败要求学生重新运行实验。

### 10.4 安全与隐私

- 模拟器不执行学生提交的任意代码。
- 输入只接受结构化数字、短标识和受控枚举。
- 学习事件不记录自由文本、API Key、本地路径或完整逐帧状态。
- 教师查看学生实验证据继续遵守现有角色权限和审计要求。

## 11. 性能目标

P0 目标基于普通学生笔记本和手机，不依赖独立 GPU：

- 合法上限输入下，模拟计算主线程耗时目标 `< 50ms`；超出时考虑 Web Worker。
- 首次进入实验页不加载大模型或 3D 资产。
- 动画目标 60 FPS，低性能设备允许降级为 30 FPS。
- 时间轴拖动后的可见更新目标 `< 100ms`。
- 单个实验前端新增首屏 JavaScript 预算应独立分包，未进入实验页时不加载。
- 后端只接收完成结果，不承担逐步轮询和动画状态同步。

## 12. 可访问性

- 所有播放控制均有 `aria-label` 和 tooltip。
- 键盘支持 Space 播放/暂停、左右方向键单步、Home/End 跳转首尾。
- 当前步骤变化通过节制的 `aria-live="polite"` 摘要播报，不逐帧轰炸读屏。
- 进程和页面状态同时使用颜色、文字、图标或纹理表达。
- `prefers-reduced-motion` 下关闭位移动画。
- 指标表和日志提供与画布等价的文本信息，画布不是唯一信息来源。
- 320px 宽度下按钮不截断、不重叠，最小点击区域 `40px`。

## 13. 测试策略

### 13.1 算法单元测试

CPU 调度：

- 固定案例验证每种算法的甘特图、完成时间和指标。
- 同到达时间、CPU 空闲、优先级相同、时间片大于 burst 等边界。
- RR 队列进入顺序和上下文切换。
- 随机合法输入的守恒和完成性质。

页面置换：

- 固定案例验证 FIFO、LRU、OPT 每一步页框和淘汰页。
- 重复页面、页框大于不同页面数、单页框等边界。
- FIFO Belady 异常演示案例。
- OPT 缺页数不高于同输入下 FIFO 和 LRU 的性质检查。

### 13.2 组件测试

- 输入非法时不能运行。
- 预测可以回答或跳过，完成前不泄露结果。
- 播放、暂停、单步、拖动、速度和重置状态正确。
- 输入不变时拖动时间轴不重新模拟。
- 完整运行和检查题完成后才能提交。
- 后端同步失败保留本地结果并可重试。
- 模型增强不可用时本地解释仍正常。

### 13.3 后端测试

- 未登录返回 `401`。
- 请求字段、长度、算法白名单和版本受控。
- 重复 `eventId` 幂等。
- 完成事件写入正确知识点、资源包和任务关联。
- 客户端提交的总分和指标需要由后端根据受控答案或摘要规则复核，不能完全信任前端。
- 响应不暴露异常、路径或环境变量。

### 13.4 E2E

```text
登录学生账号
-> 画像显示“处理机调度算法”薄弱
-> 今日任务进入 CPU 调度实验
-> 选择预设并预测 SJF
-> 播放、暂停、回看差异步骤
-> 完成检查题并提交
-> 返回今日任务显示已完成
-> 报告或近期学习记录出现实验证据
```

### 13.5 视觉验收视口

```text
1440 x 900
1280 x 800
768 x 1024
390 x 844
320 x 720
```

检查：画布非空、控制不跳动、文本不遮挡、三栏比例合理、移动端无页面级横向滚动、暗色模式不是硬反色。

## 15. 验收标准

满足以下条件才算 P0 完成：

1. `/a3/labs` 和两个实验详情页都使用真实路由、真实状态和真实学习事件。
2. 同一输入和实验版本每次产生完全一致的步骤和指标。
3. CPU 调度四种算法和页面置换三种算法均可并排比较。
4. 播放、暂停、单步、速度、时间轴、重置和全屏可用。
5. 学生可以先预测，完成后看到预测与真实结果差异。
6. 完成结果写回后能进入今日任务或学习记录闭环。
7. 大模型或网络不可用时，算法、解释、评分和提交仍可正常工作；只有可选总结降级。
8. 非法输入、模拟错误和同步错误均有可读中文状态且不会丢失用户输入。
9. 算法单测、前端组件测试、后端接口测试和端到端闭环通过。
10. 320px 至 1440px 无页面级横向滚动、控件重叠或动画导致的布局跳动。

## 16. 非目标

- P0 不允许用户提交任意算法代码并驱动画布。
- P0 不使用大模型实时生成算法步骤。
- P0 不增加 3D 场景、YOLO、数字人或视频生成依赖。
- P0 不一次实现全部操作系统实验。
- P0 不复制参考视频的名称、Logo、源码、配色数值或视觉资产。
- P0 不为了展示效果创建无法写回学习闭环的静态动画。

## 17. 风险与控制

- **算法正确但步骤解释错误**：核心解释使用版本化本地模板，并针对固定案例测试步骤文案的关键字段。
- **对比模式信息过密**：桌面最多四个 CPU 算法或三个置换算法；移动端默认单算法，指标表承担对比。
- **事件数据过大**：只上传汇总和重点步骤，不上传完整 `SimulationStep[]`。
- **前端结果可被篡改**：完成接口复核实验版本、检查题和摘要范围；学习掌握不能只依赖一次前端提交。
- **新增入口加重导航**：学生侧边栏只新增“交互实验”一个入口，具体算法通过目录和推荐进入。
- **模型解释产生幻觉**：模型只解释已有步骤和指标，必须经过验证；失败时回退本地模板。
- **低性能设备掉帧**：步骤预计算、稳定 DOM、减少布局测量，必要时使用 Web Worker 和降帧模式。

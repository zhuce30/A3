# 智学引擎 ER 图设计说明

## 1. 目标与用途

本次输出用于《系统开发说明书》第六章“数据库与数据模型设计”。图组以当前 Django 模型为事实依据，说明核心学习闭环、知识库解析与知识图谱、Agent 运行及多模态产物之间的数据关系。

最终交付包含 Mermaid 源码、SVG 矢量图和 PNG 位图。SVG 作为 Word 插图的首选格式，PNG 用于兼容不支持 SVG 的编辑或展示环境，Mermaid 源码用于后续维护。

## 2. 设计原则

图组采用 Crow's Foot 基数表达。实体显示中文业务名称、Django 模型名称和数据库表名，字段仅保留主键、外键、唯一业务标识、状态字段及能够解释业务闭环的关键属性。

真实 `ForeignKey`、`OneToOneField` 和 `ManyToManyField` 使用实体关系线表达。`trace_id`、`resource_pack_id`等字符串关联不视为数据库外键，使用虚线或注释标记为“逻辑关联”。JSON 字段内部保存的任务、计划和产物结构不拆成虚构的数据表。

## 3. 图组范围

### 3.1 图 6-1 核心学习闭环 ER 图

核心图围绕用户、画像、课程组织、学习路径、辅导、测评和反馈数据展开。主要实体包括：

- 用户、学习画像、课程教学分配、课程选修；
- 课程、章节、知识点、知识点先修关系；
- 学习路径、路径节点、资源包记录、学习事件；
- 题目、测评会话、答题记录、错题、知识点掌握度；
- 辅导会话、辅导消息、学习总结文档；
- 收藏与通知。

课程到章节、章节到知识点、学习路径到路径节点、测评会话到答题记录、辅导会话到辅导消息均表达为一对多。用户与学习画像为一对一。用户和课程通过课程选修形成多对多业务关系；教师和课程通过课程教学分配形成多对多业务关系。知识点先修关系使用关联实体表达自关联。

### 3.2 图 6-2 知识库与知识图谱 ER 图

知识库子图展示资料从上传到解析、索引、图谱和知识条目的持久化链路。主要实体包括：

- 知识索引任务、知识资源、精选学习资源；
- 知识解析任务、页面、媒体资产、内容块、索引条目；
- 图谱实体、图谱关系、知识声明；
- 知识概念、定义、别名、摘要；
- 课程和知识点的跨模块引用。

知识资源是解析链路的聚合根。图谱关系通过来源实体和目标实体两条外键形成实体自关联。精选学习资源与知识资源为可选一对一关系，与课程为多对一关系，与知识点为多对多关系。

### 3.3 图 6-3 Agent 运行与多模态产物 ER 图

Agent 子图展示工作流执行、步骤追踪、资源生成和 OpenMAIC 产物写回。主要实体包括：

- Agent 运行、Agent 步骤、Agent Span；
- 资源生成任务、题目生成任务；
- 资源包记录、OpenMAIC 产物；
- 用户、知识点、知识资源和题目等跨模块实体。

Agent 运行与步骤、Span 为真实一对多关系。资源生成任务通过字符串 `trace_id`与 Agent 运行逻辑关联；资源生成任务、资源包记录和 OpenMAIC 产物通过 `resource_pack_id`或资源包载荷逻辑关联。题目生成任务通过真实外键关联用户、知识点和知识资源，并由题目表反向关联生成任务。

## 4. 视觉与版式

三张图均采用横向画布。实体按照“主体与课程”“学习过程”“测评反馈”“知识解析”“Agent 运行”“产物写回”分区，避免跨越整张图的长关系线。主实体使用深色标题栏，课程学习、知识库、测评和 Agent 模块使用不同但克制的识别色。

正文插图保持白色背景和深色文字，保证打印可读性。PNG 输出宽度不低于 2400 像素，SVG 保留矢量文字和关系线。中文字体优先使用微软雅黑，并提供常见无衬线字体回退。

## 5. 准确性与验收

生成前从项目模型重新提取实体、表名、字段和关系。每条关系必须能够追溯到 Django 模型字段；逻辑关联必须明确区分于数据库外键。

验收时检查 Mermaid 可以成功渲染，SVG 可正常打开且无文字截断，PNG 非空并与 SVG 内容一致。图中不得出现本地绝对路径、账号信息、密钥、接口令牌或运行环境敏感信息。

交付文件统一放入：


每张图分别输出 `.mmd`、`.svg`和`.png`，并提供一份简短的图注与插入位置说明。

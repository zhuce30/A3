# A3 学生学习报告重构设计

日期：2026-07-15

## 1. 背景与问题

`/a3/report` 已接入真实测评、错题、学习计划、画像、资源包和学习效果数据，但当前页面把学生结论、执行入口、图表分析和系统审计连续平铺。线上演示账号的桌面页面高度约为 5050-5980px，移动端约为 9000-11300px，核心模块达到 16-17 个。

当前问题不是缺少数据，而是缺少面向学生的解释层：

- 同一条“先复盘错题”建议在首屏、薄弱点队列、学习处方、下一阶段建议和连续学习闭环中重复出现。
- 30 天统计周期与“本周目标”“下周处方”“本周摘要”混在同一层级，用户难以理解口径。
- 正确率、路径进度、学习时长和能力均值缺少明确分母、对比基线和可信度说明。
- 学习效果数据晚于主报告返回时，会在页面中部追加整个模块，导致页面高度和阅读位置变化。
- `v2 事件`、`decisionHistory`、策略候选数等内部字段会在有数据时暴露给学生。
- 图表、画像、资源转化和 AI 总结都占据较高视觉权重，但没有共同回答“我怎么样、为什么、接下来做什么”。

## 2. 目标

把学习报告从数据看板重构为学生可理解、可执行、可验证的阶段复盘工具。

学生进入页面后 30 秒内应能回答：

1. 我最近有没有进步？
2. 我主要卡在哪里？
3. 系统为什么这样判断？
4. 我今天应该先做什么？
5. 做完以后怎样判断是否改善？

页面必须保留真实数据、真实接口和数据回流，不新增前端 mock，不删除现有报告、资源效果、画像和策略证据。

## 3. 设计原则

### 3.1 先结论，后证据

首屏先给出一句阶段判断，再展示支持判断的关键数据。图表和历史记录不承担首屏解释职责。

### 3.2 一个首要行动

首屏只允许一个主行动。其他动作按顺序放入 7 天行动计划，不再以多个同权重快捷入口竞争注意力。

### 3.3 同一事实只解释一次

错题、计划完成和正确率分别由一个主模块负责。其他模块引用结论时只提供链接，不重复完整文案。

### 3.4 统计周期一致

周期切换控制报告证据和变化比较。7 天行动计划始终明确标记为“从今天开始的未来 7 天”，避免与 30 天或本学期历史统计混淆。

### 3.5 不伪造对比

上一周期没有有效样本时显示“暂无可比数据”，不把 0 次作答当成 0% 正确率，也不输出“提升 67%”一类虚假增幅。

### 3.6 渐进披露

核心报告只保留学生决策所需内容。趋势图、画像变化、AI 总结、导出和计算依据放入可展开区域。系统策略和事件采集证据迁移到 `/a3/capabilities`。

## 4. 页面信息架构

页面从当前 16-17 个主要模块收敛为 5 个核心区块和 1 个详细区块。

### 4.1 阶段结论

首屏结构：

```text
报告周期与更新时间
一句阶段判断
进步信号 | 主要风险 | 判断原因
唯一主行动：动作名称 + 预计时间 + 完成后变化
```

演示数据对应的文案应接近：

```text
答题表现正在改善，但学习计划执行中断。
近 30 天完成 84 道题，正确率 66.7%；当前最影响进步的是 3 道未巩固错题。
今天先完成一次错题复盘，预计 12 分钟。完成后重新测评，报告会更新掌握状态。
```

首屏保留周期切换和 PDF 导出。CSV 移入详细工具。头像只保留紧凑尺寸，不与结论争夺空间。

### 4.2 本周期的变化

最多展示三条变化：

- 进步：有有效前后周期对比的指标。
- 保持：稳定但值得继续维持的行为或能力。
- 风险：最影响学习结果的问题。

每条变化必须包含：

```text
结论 + 当前值 + 对比值或样本不足 + 一句解释
```

不再单独展示四张没有解释关系的指标卡。原始指标可作为变化卡证据或进入详细数据。

### 4.3 需要优先掌握的知识点

将“错题巩固”和“薄弱点处理队列”合并。最多展示 3 个知识点，每项包含：

- 知识点名称。
- 作答次数、错误次数、最近一次结果或错题数量。
- 当前判断：待巩固、改善中、已稳定、证据不足。
- 推荐动作和预计时间。
- 跳转到对应错题、测评或专项练习的真实链接。

没有知识点级证据时展示正常空状态，引导完成一次测评，不生成笼统的“基础测评加重”卡片。

### 4.4 从今天开始的 7 天行动

将“学习处方”“快捷动作”“下一阶段建议”“连续学习闭环”和“本周摘要”合并为一个执行模块。

模块包含：

- 一个未来 7 天核心目标。
- 最多 3 个按顺序排列的动作。
- 每个动作的预计时间、完成标准和完成后的数据回流。
- 最近一次计划调整及原因。
- 一个主按钮，执行当前第一步。

历史周期为 30 天或本学期时，标题仍为“从今天开始的 7 天行动”，避免把未来计划误认为历史统计。

### 4.5 哪些学习方式对我有效

将“资源包转化”和“学习效果评估”合并为学生语言的效果模块，仅在存在有效前后证据时下结论。

优先回答：

- 看完讲解后，相关知识点正确率是否提高。
- 完成专项练习后，错题数量是否下降。
- 哪类资源完成率较高。
- 哪类资源证据不足，暂时不能判断。

不向学生展示整体效果模型分、事件版本、策略候选数和决策分。证据不足时明确写“还需要一次测评才能判断”，不显示 0 分效果卡。

### 4.6 详细分析与报告工具

默认折叠，包含：

- 作答量与正确率趋势图。
- 能力雷达图及文字说明。
- 动态画像变化和待确认项。
- AI 学习总结生成与历史。
- CSV、PDF 导出。
- 数据覆盖范围、更新时间和计算口径。

展开状态由当前页面会话维护，不写入后端。移动端各子区块使用独立折叠项，避免一次展开产生超长页面。

## 6. 数据与接口设计

### 6.1 第一阶段：前端适配现有数据

第一阶段不修改现有接口契约。新增纯函数适配层，把 `LearningReport`、`LearningEffectReport` 和 `StudyPlan` 转换为学生视图模型：

```ts
type StudentReportViewModel = {
  period: {
    key: '7d' | '30d' | 'term';
    label: string;
    start: string;
    end: string;
  };
  overview: {
    headline: string;
    summary: string;
    progressSignal: string;
    primaryRisk: string;
    primaryAction: ReportAction;
  };
  changes: ReportChange[];
  weakKnowledgePoints: WeakKnowledgePointInsight[];
  sevenDayPlan: SevenDayReportPlan;
  effectiveMethods: LearningMethodEffect[];
  evidenceState: 'ready' | 'partial' | 'insufficient';
};
```

适配层必须对缺失字段、无作答周期、无学习效果和无计划数据提供确定性降级文案，不直接把 `undefined`、英文枚举或内部 schema 输出到页面。

### 6.2 第二阶段：后端补充学生摘要

在 `GET /api/assessments/report/?period=<period>` 的 `report` 中新增可选字段，不移除现有字段：

```json
{
  "studentSummary": {
    "schemaVersion": "a3.student-report-summary.v1",
    "headline": "答题表现正在改善，但学习计划执行中断",
    "summary": "近 30 天完成 84 道题，正确率 66.7%；当前最影响进步的是 3 道未巩固错题。",
    "progressSignal": "本周期完成 84 道题",
    "primaryRisk": "3 道错题尚未巩固",
    "primaryAction": {
      "label": "复盘 3 道错题",
      "href": "/a3/wrong-notebook",
      "estimatedMinutes": 12,
      "expectedOutcome": "完成后重新测评，更新掌握状态"
    },
    "evidence": [
      { "label": "作答", "value": "84 道", "source": "assessment" },
      { "label": "正确率", "value": "66.7%", "source": "assessment" },
      { "label": "待巩固", "value": "3 道", "source": "wrong_notebook" }
    ]
  }
}
```

同时新增：

- `comparisons`：当前周期和上一有效周期的样本量、值、百分点变化和可比较状态。
- `knowledgePointInsights`：知识点级作答、错误、掌握趋势、证据和动作。
- `dataQuality`：数据覆盖、缺失原因和最后更新时间。

旧前端忽略新增字段仍可工作，部署不要求数据库迁移。

### 6.3 比较规则

- 当前周期和上一周期都至少有 3 次作答，才计算正确率变化。
- 正确率变化使用“百分点”，不使用含义不清的百分比增长。
- 上一周期无作答时显示“上一周期暂无作答”，不显示上升或下降。
- 学习时长、学习天数和计划完成率必须显示单位与统计范围。
- 能力雷达轴少于 3 个或证据不足时隐藏雷达图，显示文字说明。

## 7. 前端组件边界

保留 `ReportView` 作为数据加载和页面编排入口，将展示职责拆分为：

```text
report-view.tsx                       页面加载、周期切换、错误边界
report-view-model.ts                 现有接口到学生视图模型的纯函数适配
report-overview-panel.tsx            阶段结论和唯一主行动
report-change-summary.tsx            进步、保持、风险
report-weak-points.tsx               知识点证据和专项动作
report-seven-day-plan.tsx            有顺序的未来 7 天行动
report-method-effect.tsx             学习方式效果和证据不足状态
report-details.tsx                   图表、画像、总结、导出和口径折叠区
```

图表组件可以继续使用 ECharts，但必须接收已经整理好的数据，不在组件内部重新判断业务含义。

## 8. 加载、错误和空状态

### 8.1 主报告

- 主报告加载时显示与首屏高度接近的骨架，避免内容跳动。
- 主报告失败时显示可读中文错误和“重新加载”按钮。
- 周期切换只更新报告内容，不清空整页，不把旧周期数据误标为新周期。

### 8.2 补充数据

- 学习效果、画像、总结历史分别拥有局部加载和局部错误状态。
- 补充接口晚返回时只更新已经预留高度的详细区域，不在核心报告中间插入新模块。
- 学习效果失败不影响阶段结论、知识点和 7 天行动。

### 8.3 数据不足

- 无作答：引导完成一次基础测评。
- 无错题：显示“当前没有待巩固错题”，主行动转为今日任务或迁移测评。
- 无计划：引导生成学习计划。
- 无资源效果：显示“完成一次推荐资源学习后再评估”，不显示 0% 转化率。
- 无画像变化：不占据核心报告空间，只在详细区显示空状态。

## 9. 响应式与可访问性

- 桌面端核心报告目标为 3-5 个视口，详细区默认折叠。
- 移动端核心报告目标不超过约 6 个视口；主行动保持在首屏可见范围内。
- 不出现横向滚动，表格式知识点信息在移动端改为纵向列表。
- 所有点击图表同时提供键盘可访问的文字列表入口。
- 颜色不单独表达进步和风险，必须同时显示图标、标签和文字。
- 折叠控件使用原生 `details/summary` 或具备正确 `aria-expanded` 的按钮。
- 动态加载后不主动抢夺焦点；错误提示使用可感知的状态区域。

## 10. 技术审计证据迁移

以下内容不从后端删除，但不再由学生报告渲染：

- LearningEvent v2 数量与来源页。
- ingest 接收数量。
- 优化策略候选、决策分和探索模式。
- `decisionHistory` 和策略评估窗口。
- schemaVersion 与内部 API 名称。

这些内容在 `/a3/capabilities` 增加“学习报告计算与策略证据”折叠区，供答辩、测试和教师技术审查使用。

## 11. 测试与验收

### 11.1 单元测试

- 有完整数据时生成阶段结论、三类变化和唯一主行动。
- 上一周期样本不足时不生成虚假增幅。
- 无错题时主行动正确降级。
- 无学习效果时不生成 0 分效果结论。
- 英文枚举、schema 和内部策略字段不会进入学生视图模型。
- 30 天报告中的未来计划明确标记为“从今天开始的 7 天行动”。

### 11.2 后端测试

- `studentSummary` 只基于当前用户的真实数据生成。
- 比较样本门槛和百分点计算正确。
- 知识点洞察返回真实题目和错题证据。
- 新字段向后兼容，现有 `metrics`、`weeklyPrescription` 和 `actionLoop` 保持可用。

### 11.3 端到端测试

```text
学生登录
-> 打开 /a3/report
-> 30 秒内首屏看到阶段结论和唯一主行动
-> 点击主行动进入对应错题、测评或今日任务
-> 切换 7 天/30 天/本学期，结论和证据同步更新
-> 展开详细分析，图表、画像和 AI 总结按需出现
-> 移动端无横向溢出，核心内容无需滚动超过约 6 屏
```

### 11.4 文案验收

学生主页面不得出现：

```text
eventStream
decisionHistory
schemaVersion
v2 事件
候选数
决策分
assessment
pending
```

## 12. 实施边界

本次重构包括：

- 学生报告信息架构和响应式布局。
- 现有数据的学生视图适配。
- 报告接口的向后兼容摘要与比较字段。
- 技术审计证据迁移到能力总览。
- 对应单元、后端和端到端测试。

本次不包括：

- 新建独立教师报告页面。
- 修改学习效果评分模型本身。
- 新增模型 provider 或新的 AI Agent。
- 删除现有历史报告、策略或事件数据。
- 重做学习计划、错题本和测评页面。

## 13. 发布策略

按两批发布：

1. 第一批重构前端信息架构和视图适配层，复用现有接口，先解决可读性、重复和移动端长度问题。
2. 第二批增加后端 `studentSummary`、有效周期比较和知识点级证据，并让前端优先使用后端摘要、适配层作为兼容降级。

每批均使用固定 Git SHA 构建前后端镜像。第一批只需重新构建前端；第二批重新构建 backend、celery、celery-beat 和 frontend。发布后验证学生登录、三个周期、主行动跳转、详细区折叠和移动端页面高度。

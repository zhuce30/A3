# A3 AI 课堂渐进式上下文与紧凑输入区设计

## 1. 背景

当前 `/a3/classroom` 在桌面端采用固定视口工作区。课堂标题位于对话滚动区之外，输入区又把检索模式、资料范围和快捷操作单独占成一行。导师方式和 OpenMAIC 资源课堂虽然已经进入滚动区，但展开高度仍较大。

结果是：

- 标题区始终占用顶部空间，阅读长回答时无法让位。
- 导师方式和 OpenMAIC 信息滚走后完全不可见，用户难以确认当前上下文。
- 输入区空闲时也占用较大高度，进一步压缩课件和对话。
- 单纯固定顶部信息会继续压缩对话，单纯让它滚走又会失去上下文。

本次设计采用“正常滚动的完整上下文、可手动收起的摘要、滚动后的紧凑吸顶栏、ChatGPT 式浮动输入区”解决这组冲突。

## 2. 目标

1. 首屏仍能说明当前课程、学习目标、导师方式和 OpenMAIC 课堂状态。
2. 用户可以主动收起课堂信息，为长内容腾出空间。
3. 用户滚动到长回答中段后，仍能以最低高度确认当前课堂上下文。
4. 输入区始终可用，但空闲状态不持续占用大块高度。
5. 保留现有真实接口、消息数据、检索模式、资料范围和侧面板能力。
6. 保证长 Markdown、公式、表格、课件和最后一条消息不被输入区覆盖。

## 3. 非目标

- 不修改 Agent、Django、检索、课堂历史或 OpenMAIC artifact 接口。
- 不重做消息气泡、Markdown 渲染和右侧练习业务。
- 不新增前端 mock，不改变消息提交和引用验证流程。
- 不模仿 ChatGPT 的品牌样式，只借鉴其空间分配和输入交互。

## 4. 总体结构

课堂主工作区只保留一个垂直滚动所有者：`ClassroomDialogueViewport`。

```text
ClassroomWorkspace
├─ ClassroomDialogueViewport（唯一滚动区）
│  ├─ ContextSentinel
│  ├─ ClassroomContextRegion
│  │  ├─ ExpandedContext
│  │  └─ CollapsedContextSummary
│  ├─ StickyContextBar（滚出上下文后显示）
│  ├─ ResourceGenerationActions
│  ├─ LessonRunway
│  ├─ MessageList
│  └─ ComposerClearance
└─ FloatingComposer（底部浮动）
```

完整上下文、收起摘要和吸顶栏读取同一份课堂状态，不维护三套业务数据。

## 5. 课堂上下文区

### 5.1 默认展开状态

首次进入当前课堂时默认展开，内容按以下顺序呈现：

1. 课程标签、当前知识点标题和学习目标。
2. 学习路径、刷新上下文、侧面板三个操作。
3. 导师方式选择器。
4. OpenMAIC 资源课堂状态与打开入口。

标题、目标、导师和 OpenMAIC 信息全部位于正常滚动内容中，不再作为工作区外的固定头部。

展开区右上角提供图标加“收起”操作，触控区域不小于 44×44px。

### 5.2 手动收起状态

点击“收起”后，完整内容压缩为高度约 48 至 56px 的摘要栏，显示：

- 当前知识点标题，超长时单行省略。
- 当前导师方式。
- OpenMAIC 状态或场景数量。
- “展开”图标按钮。

课程说明、导师描述、试听按钮和 OpenMAIC 提示文案在收起状态隐藏。摘要栏仍处于正常文档流中，因此不会覆盖第一条消息。

用户手动选择的展开状态使用 `sessionStorage` 按当前课堂目标保存，只在当前浏览器标签页和当前课堂中生效。新目标首次进入仍默认展开，避免用户错过上下文变化。

### 5.3 滚动吸顶状态

使用 `IntersectionObserver` 观察 `ContextSentinel`，不在每个滚动事件中触发 React 状态更新。

当完整上下文或手动收起摘要滚出视口后，在对话滚动区顶部显示 44 至 48px 的 `StickyContextBar`。内容包括：

- 当前知识点标题。
- 当前导师方式短标签。
- 来源数量或 OpenMAIC 状态。
- 展开课堂信息、刷新上下文、侧面板三个图标操作。

吸顶栏不显示学习目标长文、四张导师卡和 OpenMAIC 说明。返回顶部后吸顶栏消失，恢复原上下文区，页面不会同时出现两个标题。

吸顶栏使用不透明实色背景和底部分隔线，不使用玻璃模糊。出现与消失采用 160 至 200ms 的透明度和纵向位移动画，并尊重 `prefers-reduced-motion`。

### 5.4 展开入口

用户在吸顶栏点击“课堂信息”时：

1. 滚动到上下文区顶部。
2. 将手动状态切换为展开。
3. 将焦点移到上下文区标题，方便键盘用户继续操作。

不在吸顶栏内直接向下展开四张导师卡，避免长回答阅读位置突然跳动。

## 6. 导师方式与 OpenMAIC 信息压缩

导师选择器保留现有四种方式和音色试听，但减少重复文案：

- 展开态继续显示名称、短描述和试听按钮。
- 当前选中项有明确选中状态。
- 收起态和吸顶态只显示当前导师名称，不复制四个选项。

OpenMAIC 区域在展开态压缩为单行状态条，显示图标、状态、场景数和主操作。PPTX 说明进入 tooltip 或辅助说明区域，不持续占用两行高度。

## 7. ChatGPT 式浮动输入区

### 7.1 空闲状态

输入区脱离现有 `grid-rows-[minmax(0,1fr)_auto]` 的大块底栏，改为工作区底部浮动容器。桌面端空闲总高度目标为 76 至 88px。

输入框单行起步，内部结构为：

```text
问题输入区域
附件  语音  快速/深度  资料范围                发送
```

检索模式继续使用二元分段控件，资料范围继续使用菜单，不改变请求字段。来源数量以简短文本或 tooltip 展示。

“新对话”移动到历史侧栏顶部；“练习”和“行动”由右侧面板入口承载，不再常驻输入区上方。

### 7.2 自动增高

- 输入框初始为一行。
- 随内容向上增长，最高不超过工作区高度的 35%。
- 达到上限后输入框内部滚动，不继续压缩消息区。
- `Enter` 提交，`Shift+Enter` 换行，输入法组合阶段不提交。

### 7.3 动态状态

附件预览、录音状态、转写状态和错误提示显示在输入框内部上缘或输入框正上方的紧凑状态条中。状态消失后自动恢复空闲高度。

消息提示不再作为普通布局块永久推高输入区；成功反馈使用短时、可访问的状态提示。

### 7.4 防覆盖机制

`FloatingComposer` 使用 `ResizeObserver` 测量实际高度，并把高度写入工作区 CSS 变量。消息列表底部的 `ComposerClearance` 和 `scroll-padding-bottom` 使用该变量加 16px 安全距离。

因此输入区增高、出现附件或语音状态时，最后一条消息仍能完整滚动到输入区上方，不依赖固定猜测高度。

当用户距离底部超过阈值时，在输入区上方显示“回到最新消息”按钮。新回答生成时不强制抢走用户当前阅读位置。

## 8. 侧栏与响应式规则

### 大桌面，宽度不小于 1600px

- 历史侧栏、主课堂、右侧面板可同时显示。
- 主对话列仍保持可读宽度，正文建议控制在 65 至 75ch。

### 普通桌面，宽度 1280 至 1599px

- 默认只常驻一个侧栏。
- 另一侧通过抽屉打开，避免主对话过窄。
- 上下文收起和输入区紧凑规则不变。

### 平板与移动端，宽度小于 1280px

- 历史和课堂侧面板均改为抽屉。
- 吸顶栏仅保留标题、导师短标签和更多菜单。
- 输入区工具允许换成图标菜单，但发送和附件入口始终可见。
- 使用 `100dvh` 和安全区内边距，软键盘弹出后输入区仍处于可视区域。

## 9. 状态模型

前端新增的布局状态仅包括：

```text
contextExpanded: boolean
contextInView: boolean
composerHeight: number
isNearDialogueBottom: boolean
```

派生规则：

```text
显示完整上下文 = contextExpanded
显示流内摘要 = !contextExpanded
显示吸顶栏 = !contextInView
显示回到底部 = !isNearDialogueBottom
```

现有 `historyOpen`、`drawerOpen`、`retrievalMode`、`retrievalScope`、导师和 OpenMAIC 数据保持原契约。

## 10. 加载、错误和空状态

- 上下文加载时显示与最终摘要等高的骨架，不使用居中大转圈。
- 导师加载或保存失败时，错误保留在展开区；摘要栏显示警告状态和重试入口。
- OpenMAIC 未生成时显示“生成资源课堂”操作，不伪造成功状态。
- 没有学习目标时，摘要栏显示“等待学习目标”，输入区保持禁用并提供前往学习路径的下一步。
- 查看历史对话时，输入区保持只读状态并明确显示“正在查看历史对话”。

## 11. 可访问性

- 收起、展开、回到底部、侧面板按钮均有中文 `aria-label`。
- 展开和收起按钮使用 `aria-expanded`、`aria-controls`。
- 吸顶栏出现不自动移动焦点。
- 手动从吸顶栏打开课堂信息时才移动焦点。
- 键盘焦点不能落到被折叠隐藏的导师选项中。
- 状态反馈使用 `aria-live="polite"`，错误使用 `role="alert"`。
- 所有图标按钮提供 tooltip，触控目标不小于 44×44px。

## 12. 验收标准

### 布局

- 1366×768 下，输入区空闲高度不超过 96px。
- 课堂上下文手动收起后高度不超过 56px。
- 滚动长回答时吸顶栏高度不超过 48px。
- 最后一条消息、公式和表格不被输入区覆盖。
- 页面不存在窗口级和对话区双重滚动条。

### 交互

- 新课堂首次进入默认展开。
- 手动收起后刷新当前标签页仍保持收起。
- 新学习目标首次进入恢复默认展开。
- 滚出上下文后显示吸顶栏，返回顶部后不重复显示。
- 从吸顶栏打开课堂信息会回到顶部并展开。
- 输入区可以自动增高、提交、换行、上传图片和语音输入。
- 离开底部后可以一键回到最新消息。

### 回归

- `POST /api/a3/coaching/respond` 的 `mode` 和 `scope` 不变。
- 课堂历史、新对话、收藏、练习、计划回写和 OpenMAIC 入口保持可用。
- Markdown、KaTeX、表格、引用和长代码块正常滚动。
- 现有历史侧栏和右侧面板展开、收起不改变消息数据。

- 输入区保留检索模式、资料范围、图片、语音和发送能力。

## 15. 成功结果

用户第一次进入时能看懂当前课堂；需要长时间阅读和对话时，可以主动收起上下文。滚动到任意位置仍能确认课程、导师和资源状态。输入区像成熟聊天产品一样保持可用，但不再成为页面中最大的固定区域。

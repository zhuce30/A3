# A3 本地知识库检索区改版设计思路

## 目标

将 `/a3/knowledge-base` 页面下方的“知识库检索”从当前的简化卡片，改成类似参考图的 RAG 检索测试台：左侧负责输入问题、展示召回摘要和排序结果，右侧负责检索配置。改版后仍然使用真实知识库接口和真实检索结果，不新增前端假数据。

本计划只覆盖前端信息架构、交互和接口映射，不处理资料提取、向量构建、实体抽取质量问题。

## 当前问题

当前检索区把输入框、检索质量指标、路由解释、Wiki 证据、图谱证据和结果列表放在同一个纵向卡片里，信息层级较弱：

- 查询输入区太小，更像普通搜索框，不像可以复测问题的检索控制台。
- 检索配置不可见，用户不知道当前是混合检索、知识图谱检索还是普通向量召回。
- “上传证据、索引证据、检索证据、课堂引用”与一次检索结果混在一起，容易打断结果阅读。
- 结果卡片缺少稳定的排名、分数、来源、块索引等检索调试信息的视觉分层。
- 参考图里的参数面板包含很多字段，但当前接口并不全部支持，需要区分“现在可接入”和“后端后续支持”。

## 参考图拆解

参考图的有效结构是：

- 顶部为模块导航，当前选中“检索测试”。
- 主区域为左右两栏。
- 左栏顶部是大号查询输入框，右下角放检索按钮。
- 左栏结果区先展示“检索到 N 个相关文档块”和清空按钮。
- 每条结果用排名、相似度、重排序分数、正文片段、来源元数据组成。
- 右栏是“检索配置”面板，包含检索模式、返回 chunk 数、相似度阈值、BM25 候选数、向量权重、BM25 权重等字段。

这套布局适合 A3 的本地知识库页，因为它让教师或演示者能看到“为什么检索到这些内容”，而不是只看到一个结果列表。

## 设计原则

- 保持产品工具感：界面应接近学习平台后台里的检索调试台，避免营销化大卡片和装饰性视觉。
- 参数诚实：接口未支持的参数不伪造成已生效，可以先显示为禁用、实验中，或放入后续任务。
- 结果优先：检索完成后，第一眼应看到召回数量、排序依据和第一条结果正文。
- 证据可追踪：每条结果必须保留来源、位置、分数、块索引等字段。
- 右侧详情保留密度：配置面板可以信息密集，但控件形态要稳定，避免把说明文字堆满。
- 移动端可用：窄屏下配置面板折叠到查询框下方，不遮挡结果。

## 信息架构

建议将“知识库检索”改成一个完整的检索工作台模块：

```text
知识库检索
├─ 左侧：检索执行区
│  ├─ 查询输入框
│  ├─ 检索/清空/示例问题
│  ├─ 本次检索摘要
│  ├─ 路由解释
│  ├─ Wiki / 图谱证据折叠区
│  └─ 排名结果列表
└─ 右侧：检索配置
   ├─ 检索模式
   ├─ 返回 Chunk 数
   ├─ 快速检索开关
   ├─ 包含多模态资产开关
   ├─ 相似度阈值
   ├─ BM25 召回数量
   ├─ 向量 / BM25 权重
   └─ 保存或恢复默认
```

## 桌面布局

桌面端采用 `lg:grid-cols-[minmax(0,1fr)_360px]` 左右布局。

左侧：

- 顶部使用大号查询框，高度约 120 到 140px。
- 查询框内部右下角放搜索按钮，左下角放 placeholder 或示例问题。
- 查询框下方用浅色信息条展示“检索到 X 个相关文档块”“检索耗时”“当前模式”“清空”。
- 路由解释、Wiki 证据、图谱证据放在结果摘要和结果列表之间，默认紧凑展示，数量多时可折叠。
- 结果列表使用单列，卡片之间保持清晰间距。

右侧：

- “检索配置”作为 sticky 面板，顶部与查询框对齐。
- 每个配置项包含 label、控件、短帮助文字。
- 支持的字段正常可编辑，不支持的字段用 disabled 状态并标注“后端参数待接入”。
- 保存按钮只有在未来支持持久化配置时启用；当前阶段可以改成“恢复默认”或不显示保存。

## 移动端布局

移动端不做固定右栏：

- 查询框在最上方。
- 检索配置折叠成“检索配置”按钮或 accordion，默认收起。
- 结果摘要紧跟查询框。
- 证据区默认折叠，避免挤占结果列表。
- 结果卡片中的分数和来源元数据允许换行，不使用横向滚动。

## 检索配置字段分级

### 第一阶段可以真实接入

基于当前前端调用，已知接口形态为：

```text
GET /api/kb/search/?q=<keyword>&top_k=5&include_assets=1
```

第一阶段建议真实接入：

| 字段 | UI 控件 | 接口映射 | 说明 |
|---|---|---|---|
| 检索问题 | textarea | `q` | 现有参数 |
| 返回 Chunk 数 | number input / stepper | `top_k` | 当前固定为 5，可改成用户配置 |
| 包含多模态资产 | switch | `include_assets` | 当前固定为 1，可改成开关 |
| 清空结果 | button | 前端状态 | 不调用后端 |

### 第二阶段需要确认或补后端

这些字段参考图里有，但当前页面调用未体现。实现时不能只在前端展示后假装生效。

| 字段 | 建议 UI | 后端要求 |
|---|---|---|
| 检索模式 | select / segmented control | 支持 `hybrid`、`vector`、`bm25`、`wiki`、`graph` 或返回降级说明 |
| 快速检索 | switch | 若后端已有 `fast=1`，需要确认 Next API 和 Django 是否完整透传 |
| 相似度阈值 | number input | 后端按阈值过滤结果，并返回实际阈值 |
| BM25 召回数量 | number input | 后端支持候选数量配置 |
| 向量检索权重 | number input / slider | 后端混合排序使用并返回排序依据 |
| BM25 权重 | number input / slider | 与向量权重一起校验总和或自动归一 |
| 保存配置 | button | 需要用户级或全局配置持久化接口 |

## 结果卡片设计

每条结果建议分为四层：

1. 排名层：`#1`、相似度、重排序分数、来源类型。
2. 正文层：展示命中的 chunk 内容，支持 Markdown，但默认限制最大高度，提供展开。
3. 来源层：文件名、页码或位置、文件 ID、块索引、距离或 score。
4. 操作层：复制引用、用于课堂提问、查看资源详情。若没有现成接口，先不放可点击按钮。

视觉上不要把每条结果做成很重的卡片。建议使用浅边框、紧凑 padding、排名数字和分数胶囊作为主要识别点。

## 状态设计

- 初始状态：展示 2 到 3 个示例问题按钮，提示用户可以检索已构建资料。
- 加载状态：结果区用 skeleton，搜索按钮显示 loading。
- 空结果：说明没有召回内容，并提示调整关键词、降低阈值或确认资料已构建。
- 错误状态：展示后端返回的中文错误，不暴露 traceback。
- 降级状态：如果检索路由 fallback，保留橙色提示，说明降级原因。
- 未构建状态：如果 indexed chunk 为 0，应引导去上传或重新解析已有资料，而不是展示空白结果。

## 数据与接口映射

当前前端已有状态可继续复用：

- `results`：结果列表。
- `retrieval`：检索路由、意图、降级原因、子问题。
- `wikiEvidence`：结构化 Wiki 证据。
- `graphEvidence`：图谱路径证据。
- `searching`：加载状态。
- `query`：查询文本。

建议新增前端状态：

```ts
type SearchConfig = {
  topK: number;
  includeAssets: boolean;
  mode: 'hybrid' | 'vector' | 'bm25' | 'wiki' | 'graph';
  fast: boolean;
  similarityThreshold?: number;
  bm25Candidates?: number;
  vectorWeight?: number;
  bm25Weight?: number;
};
```

第一阶段只把 `topK` 和 `includeAssets` 拼入实际请求。其他字段先作为禁用或待接入项，避免误导用户。

## 实施任务

1. 重构 `knowledge-base-view.tsx` 中“知识库检索”卡片为左右两栏检索工作台。
2. 将固定 `top_k=5&include_assets=1` 改为读取 `SearchConfig`。
3. 增加配置面板组件，先接入 `topK` 和 `includeAssets`。
4. 结果列表增加排名、分数、来源、块索引的稳定视觉层级。
5. Wiki 证据和图谱证据改成紧凑 evidence 区块，避免抢占结果列表。
6. 补齐初始、加载、空结果、错误、降级、未构建状态。
7. 增加或更新测试，覆盖请求参数、配置控件和结果渲染。

## 风险与边界

- 当前参考图里的“保存配置”如果没有持久化接口，不建议第一阶段做成真实保存按钮。
- 相似度阈值、BM25 数量、权重等字段必须等后端支持后再启用。
- 这次改版不改变资料清理、重建、上传、解析逻辑。
- 这次改版不解决实体详情抽取格式混乱问题，那属于知识图谱和抽取 schema 的后续工作。
- 不新增 mock 检索结果，不把未构建资料伪装成已检索资料。

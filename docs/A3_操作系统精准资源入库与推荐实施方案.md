## 1. 结论

首期不新增在线子智能体。

当前 A3 已有完整的推荐工作流：

```text
LearningStateAgent
-> RetrieverAgent
-> RankerAgent
-> VerifierAgent
-> ResourcePackAgent
```

本批资源真正缺少的不是一个新的大模型角色，而是以下基础能力：

1. 将讲解文档、实操案例和外部视频统一登记为结构化资源。
2. 为资源绑定课程、知识点、难度、时长、适用画像和薄弱点触发条件。
3. 让 `RetrieverAgent` 能同时召回知识库证据和结构化资源目录。
4. 让 `RankerAgent` 根据画像、错题、路径节点、每日时间和历史效果进行可解释排序。
5. 记录展示、打开、收藏、完成、跳过和后测结果，形成下一轮推荐依据。

如果未来需要自动从互联网发现数百或数千条资源，再增加离线 `ResourceCuratorAgent`，负责链接核验、去重、版权状态检查、标签抽取和人工审核队列。该 Agent 不参与每次学生请求的在线推荐，避免不稳定、延迟增加和不可解释排序。

## 3. 已解决的工程缺口

### 3.1 DOCX 知识库支持

已补充 DOCX 文件类型校验、结构化解析和多模态解析入口。平台导入命令将 7 份文档复制到受管课程资料目录，并创建全局 `KnowledgeResource`；这属于平台资料入库，不是学生或教师个人上传。

### 3.2 视频 Excel 独立解析

视频清单由 `import_os_curated_resources` 按固定列 schema 独立读取，不经过问答题库解析器。导入会校验 HTTPS、重复 URL、知识点映射和核验状态。

### 3.3 独立推荐目录

`CuratedLearningResource` 已承担结构化推荐目录职责，`KnowledgeResource` 继续只负责文件、解析任务和索引状态。二者通过可空的一对一关系关联，避免把目录字段临时塞入检索文本。

### 3.4 确定性推荐评分

`CuratedResourceMatcher` 已将知识点映射、薄弱点触发条件、难度、预计时长和历史完成/跳过行为纳入规则评分。推荐理由和 `rankingBasis` 直接来自命中信号，不由模型自由编造。

## 4. 目标架构

```text
本地 DOCX / 视频 XLSX
-> 幂等导入命令
-> CuratedLearningResource 结构化资源目录
   -> 本地文档关联 KnowledgeResource
   -> 外部视频保留 URL 与核验信息
-> DOCX 解析为标题、段落、表格和 Markdown 块
-> KnowledgeBlock + 向量索引 + 关键词索引
-> RetrieverAgent 合并两类候选
   1. 可引用的知识库内容
   2. 可执行的学习资源目录
-> RankerAgent 按画像与学习状态排序
-> VerifierAgent 区分“知识引用”与“资源推荐证据”
-> 推荐页 / 今日任务 / AI 课堂展示
-> LearningEvent 记录使用反馈
-> 后测、错题和完成行为回流下一次排序
```

核心原则：

- 文档内容进入 RAG，资源元数据进入目录，两者通过外键关联。
- 外部视频可以推荐，但不能在没有字幕证据时参与回答引用。
- 推荐理由必须来自真实命中信号，不能让模型自由编造。
- 点击不等于学完；外部视频必须由用户主动“标记完成”或完成后测才能记录完成。

建议字段：

```text

external_url             外部视频 URL，可空

estimated_minutes        预计学习时间
```

约束：

- `verification_status != verified` 或 `is_active = false` 的资源不进入推荐。
- URL 只返回给已登录用户，前端使用安全的新窗口打开方式。

## 6. 导入与索引流程

新增管理命令：

```powershell
python backend/manage.py import_os_curated_resources `
  --source-dir "data/操作系统/资料" `
  --owner-phone 13800000002 `
  --scope global `
  --enqueue-index
```

导入必须幂等：

1. 检查目录和 8 个预期源文件。
2. 读取 DOCX 第一张元数据表，校验资源编号、课程编号、类型、难度、时长和关键词。
3. 根据资源编号建立知识点映射；无法映射时失败并给出中文错误，不静默跳过。
4. 将 DOCX 复制到 `KNOWLEDGE_UPLOAD_ROOT/course-materials/OS-001/curated/`。
5. 创建或更新 `KnowledgeResource`，范围设为 `global`，可见性设为 `shared`。
6. 创建或更新 `CuratedLearningResource`，并关联 `KnowledgeResource`。
7. 读取 Excel 的“视频资源清单”，为 12 行生成稳定编号并创建外部资源。
8. 对新增或内容哈希变化的 DOCX 创建索引任务。
9. 输出新增、更新、未变化、失败和待索引数量。

DOCX 解析应保留：

- 标题层级和章节名。
- 普通段落、编号列表和代码块。
- 表格结构，并转换为 Markdown 表格。
- 原始段落序号、表格序号和所属章节，作为引用位置。
- 资源元数据表不与正文混成一个超长 chunk。

推荐 chunk 粒度为“一个标题下的若干段落”或“一个完整表格”，单块过长时按 800-1200 中文字符切分，并保留 100-150 字重叠。代码块和表格不得从中间截断。

## 7. 精准推荐规则

### 7.1 候选生成

候选资源至少来自五类信号：

1. 当前学习路径节点和课程知识点。
2. 画像中的学习目标、薄弱点、基础水平、每日时间和资源偏好。
3. 最近错题的知识点、错误次数和错误原因。
4. 诊断与后测的知识点正确率。
5. 知识库混合检索的语义与关键词结果。

### 7.2 首版确定性评分

首版使用可复现规则，不让大模型直接决定分数：

| 信号 | 最高分 | 说明 |
|---|---:|---|
| 知识点直接匹配 | 35 | 与当前节点或错题知识点一致 |
| 薄弱点触发命中 | 25 | 命中资源内维护的具体错误条件 |
| 资源偏好匹配 | 10 | 讲解文档、实操或视频偏好 |
| 难度适配 | 10 | 基础水平与资源难度一致 |
| 时间适配 | 10 | 可在每日可用时间内完成或合理拆分 |
| 历史有效性 | 10 | 完成率、收藏率、跳过率和后测增益 |

必要的降权：

- 最近已完成且未到复习时间：降低 20 分。
- 连续展示 3 次未打开：降低 8 分。
- 同一类型最近连续跳过：降低 10 分。
- 核验过期或链接异常：直接排除，不只降分。

### 7.3 推荐理由格式

每条推荐必须说明：

```text
为什么推荐：你最近在“时间片轮转重新入队”连续出错 2 次。
为什么是这个资源：该视频专门覆盖 RR 重新入队和多级反馈队列，难度与你当前基础匹配。
预计投入：18 分钟。
学完如何确认：完成 3 道调度推演题，至少答对 2 道。
```

推荐响应新增但保持兼容的字段：

```json
{
  "resourceCode": "OS-VIDEO-004",
  "resourceType": "video",
  "deliveryMode": "external_link",
  "difficulty": "intermediate",
  "estimatedMinutes": 18,
  "matchedKnowledgePoints": ["OS-SCHEDULING"],
  "matchedTriggers": ["RR 重新入队顺序错误"],
  "completionCriteria": ["完成 3 道调度推演题，至少答对 2 道"],
  "verification": {
    "status": "verified",
    "verifiedAt": "2026-07-15"
  }
}
```

## 8. 页面与学习闭环

### 8.1 推荐页

`/a3/recommendations` 的真实推荐卡显示：

- 资源类型、难度、预计时间、来源平台。
- 命中的知识点和具体薄弱点。
- 推荐理由和完成判据。
- 文档使用“开始学习”，视频使用“打开视频”。
- 收藏、暂不需要和标记完成操作。

### 8.2 资源详情页

新增 `/a3/library/[resourceCode]`：

- 文档展示结构化内容、目录、知识库引用位置和下载入口。
- 实操案例突出环境、步骤、检查点、常见错误和完成判据。
- 视频展示标题、平台、时长、关键时间段、推荐原因和外部链接。
- 页面底部给出后测或错题复盘入口。

### 8.3 今日任务和 AI 课堂

- 今日任务可以接收指定资源，但必须带推荐原因和预计时间。
- AI 课堂可引用已索引 DOCX 的知识块。
- AI 课堂可以建议外部视频，但不得把视频作为已验证的回答引用。
- 文档、课堂和后测通过 `resourceCode` 关联，便于统计使用效果。

### 8.4 行为回流

复用 `LearningEvent`，新增或统一以下事件：

```text
recommendation_shown
recommendation_clicked
resource_opened
resource_favorited
resource_skipped
resource_completed
resource_post_assessment_submitted
```

事件至少记录 `resourceCode`、`knowledgePointId`、`resourceType`、`durationSec`、来源页面和 `traceId`。外部视频点击只记录 `opened`，不能自动记录 `completed`。

## 10. 生产数据交付

`data/操作系统/` 已被 `.gitignore` 排除，原始 DOCX 和 XLSX 不应通过普通 Git 提交。代码与资源文件分开交付：

1. 代码、迁移、测试和小型资源清单 schema 通过 GitHub/GHCR 部署。
2. 原始资料通过 `scp`、对象存储或教师端上传进入服务器的 `/opt/A3/data/操作系统/资料/`。
3. `docker-compose.yml` 已将宿主机 `./data` 映射到容器 `/app/data`，无需把资料打进后端镜像。
4. 部署新后端镜像并完成迁移后，在 backend 容器内执行幂等导入命令。
5. Celery 单并发执行 DOCX 索引，逐个观察任务状态，避免 4 GB 服务器因并行解析再次出现内存峰值。

生产执行顺序：

```text
上传资料到宿主机 data 目录
-> 部署包含迁移和 DOCX 解析的新后端镜像
-> migrate
-> import_os_curated_resources --enqueue-index
-> 检查 7 个索引任务
-> evaluate_curated_recommendations
-> 学生账号完成端到端验收
```

## 11. 风险与边界

1. B 站链接可能要求登录或发生分 P 调整，需要保留人工核验状态和下线开关。
2. 外部视频版权和公开状态可能变化，A3 只提供链接，不镜像或重新分发视频文件。
3. DOCX 页码不稳定，首版引用位置使用“章节标题 + 段落/表格序号”，不伪造页码。
4. 文档内的推荐规则是候选信号，不直接覆盖学生实时数据。
5. 资源完成不能直接等同于知识掌握，必须结合后测、错题和复习结果更新掌握度。
6. 资源较少时规则排序更可靠；在资源规模扩大前，不引入额外在线 LLM Agent。

## 12. 最终验收路径

```text
教师导入 7 份 DOCX 和 12 个视频
-> 资源目录显示 19 项且状态正确
-> 学生画像命中具体薄弱点
-> 推荐页出现对应文档、实操和视频
-> 每条推荐说明理由、时间和完成标准
-> 文档内容可在 AI 课堂被检索和引用
-> 视频只作为推荐资源，不冒充知识引用
-> 学生打开、收藏、完成并参加后测
-> 学习事件写回
-> 下一次推荐排序和理由发生可解释变化
```

该路径全部通过后，才能认定“资源汇总和按需精准推荐”完成，而不是仅把文件上传到知识库页面。

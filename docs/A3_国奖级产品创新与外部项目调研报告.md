# A3“智学引擎”国奖级产品创新与外部项目调研报告

版本：v1.0  
调研日期：2026-07-28  
适用范围：产品创新定位、后续研发取舍、比赛答辩与实证设计  
说明：本报告只做设计研究，不代表相关能力已经实现。外部项目、视频热度和许可证状态均以调研当日为准。

## 1. 执行结论

### 1.1 最重要的判断

A3 当前不缺功能数量，缺的是一个评委能在 30 秒内听懂、在 3 分钟内看到、在追问时能拿数据证明的核心创新机制。

不建议把“接入 Coze”“多智能体数量”“数字人”“RAG”“生成六类资源”“浏览器目标检测”单独作为核心创新。这些都可以提升产品完整度，但容易被判断为现成能力集成或功能堆叠。

建议把 A3 的核心创新统一为：

> **基于双证据闭环与可执行操作系统实验的自适应学习引擎。系统不是只根据画像生成资料，而是估计学生在每个知识点上的掌握概率和不确定性，选择最合适的学习干预，让学生通过可执行实验产生新的学习证据，再用等价后测与延迟复习验证真实学习增益，持续更新下一次推荐。**

其差异不在“能生成什么”，而在以下闭环：

```text
学生知识状态（掌握概率 + 不确定性 + 错误模式）
-> 选择一次教学干预（讲解 / 动画 / 例题 / 代码实验 / 辅导）
-> 学生预测、操作、运行、解释
-> 采集过程证据与后测结果
-> 估计本次干预带来的学习增益与保持度
-> 更新学生状态、资源效果和下一次推荐
```

### 1.2 推荐的创新组合

| 层级 | 推荐创新 | 作用 | 是否作为核心答辩点 |
| --- | --- | --- | --- |
| 核心算法 | 证据驱动的动态知识状态模型 | 把静态画像升级为知识点级、带置信度的动态状态 | 是 |
| 核心策略 | 学习干预效果推荐 | 推荐“预计最有效的干预”，并用后测验证 | 是 |
| 学科特色 | 可执行操作系统概念实验 | 将调度、内存、同步等抽象知识变成可操作证据 | 是 |
| 可信底座 | 内容引用、声明验证与安全过滤 | 证明生成内容有来源、可审计、可降级 | 重要支撑 |
| 教师能力 | 干预效果矩阵与可回滚策略 | 教师能看见哪些资源对哪些学生有效 | 重要支撑 |
| 外部编排 | Coze 工作流 | 供教师快速编排外部流程或做原型 | 可选，不是核心 |

### 1.3 一句话答辩口径

不建议说：

> 我们使用多智能体、Coze、RAG 和数字人，为学生生成个性化资源。

建议说：

> 其他系统通常停留在“根据画像生成内容”，A3 进一步验证“这份内容是否真的让这个学生学会了”。系统用知识点级状态估计选择教学干预，通过可执行操作系统实验和前后测采集证据，再把真实学习增益回流到画像、计划和推荐中。

## 2. A3 当前基础与真实缺口

### 2.1 已有基础

根据当前仓库和项目文档，A3 已具备以下真实基础：

- 注册、画像、诊断、路径、周期计划、今日任务、测评、错题、报告和教师干预闭环。
- `LearningEvent` 学习事件及任务、资源、测评、辅导等行为写回。
- 知识点级 `learningGain`、趋势和置信度展示。
- 按资源类型与知识点统计打开、完成、跳过、收藏、后测增益。
- 固定策略候选、效果评分、回滚状态和低证据探索标记。
- 多模态知识库、向量检索、引用证据、Verifier 和 Safety。
- 多种资源生成、OpenMAIC 课堂、PPTX 与视频 artifact 写回。
- 操作系统资料目录、文档和视频的结构化入库与可解释推荐。

相关实现包括：

```text
backend/apps/learning/effect_metrics.py
backend/apps/learning/resource_attribution.py
backend/apps/learning/optimization_policy.py
backend/apps/profiles/profile_aggregator.py
backend/apps/compat/recommendations.py
```

### 2.2 当前机制为什么还不足以成为国奖级创新

当前学习效果能力是真实的，但主要仍是确定性统计与启发式规则：

1. `preScore` 主要取首次作答，`postScore` 主要取末两次作答，未控制题目难度和题型差异。
2. 知识点置信度主要由作答次数决定，尚不是经过校准的概率不确定性。
3. 资源效果按“资源类型 + 知识点”聚合，前后时间相关不能自动解释为该资源造成的提升。
4. 策略引擎使用固定加分规则，尚未学习“哪类学生在什么状态下更适合哪种干预”。
5. 自历史基线会受到自然熟练、题目重复、教师帮助和时间变化影响。
6. 画像信号已经有来源和置信度，但“基础水平”“薄弱点”“偏好”与知识状态仍是两个相对独立的表示。
7. 推荐能够解释命中规则，但还不能给出经过验证的“预计学习增益”和误差范围。

因此，下一阶段不应重复建设事件流或再加一批 Agent 名称，而应升级“状态估计、干预选择、结果验证”三件事。

## 3. Coze 能不能放进 A3

### 3.1 可以，但不应作为核心运行链路

Coze Studio 官方开源版提供 Prompt、RAG、插件、工作流、知识库、数据库、OpenAPI 和 Chat SDK，采用 Apache-2.0 许可证。它适合快速搭建和调试低代码 Agent 工作流。

但是，直接把 A3 的画像、诊断、推荐和学习效果判断交给 Coze，会带来四个问题：

- **创新归属弱**：评委容易认为工作流能力来自第三方平台。
- **可复现性下降**：云端工作流版本、模型、插件和密钥不一定随源码交付。
- **数据边界复杂**：学生画像、错题、聊天和成绩属于敏感教育数据，不宜默认发送到外部工作流。
- **运维成本增加**：Coze Studio 自托管官方最低要求为 2 核 4 GB，且还需模型服务、数据库和插件配置；不适合与当前 A3 在同一台资源紧张的服务器上叠加运行。

### 3.2 三种接入方式对比

| 方案 | 做法 | 优点 | 缺点 | 建议 |
| --- | --- | --- | --- | --- |
| A. Coze 云端主编排 | A3 调 Coze 工作流完成画像、推荐和生成 | 开发快、画布直观 | 平台依赖强、隐私与复现风险高 | 不采用 |
| B. 自托管 Coze Studio | 独立服务器部署，A3 调用其工作流 API | 可控性高、可二次开发 | 重复建设 Agent/RAG，资源和运维成本高 | 赛后再评估 |
| C. A3 主链路 + Coze 可选插件 | A3 保留状态、策略、验证和写回；Coze 只承接非关键外部工作流 | 保留产品主权，可展示开放生态 | 需要严格 schema 和降级边界 | 推荐 |

### 3.3 推荐定位：教师可编排教学插件

如果要使用 Coze，最合适的创新不是“我们用了 Coze”，而是：

> A3 提供可插拔教学策略接口，教师可用 Coze 编排课外答疑、资料摘要或通知流程；所有输出必须回到 A3 经过 schema 校验、引用验证、权限检查和效果评估后才能进入学生闭环。

推荐只允许 Coze 承接：

- 教师创建的非关键资料摘要或课前导学流程。
- 公开信息检索、外部工具调用和通知编排。
- 不包含完整学生隐私的匿名化资源生成任务。
- 比赛演示之外的快速教学流程原型。

必须留在 A3 的能力：

- 用户身份、角色和权限。
- 原始画像、错题、成绩和学习事件。
- 动态知识状态与置信度。
- 推荐策略、资源分配和效果归因。
- Verifier、Safety、写回和审计。
- 比赛核心演示所需的全部降级能力。

## 4. 三条创新路线比较

评分采用 1-5 分，5 分最好；实施风险一列 5 分表示风险最高。

| 路线 | 创新性 | 学科特色 | 可验证性 | 近期可落地 | 实施风险 | 结论 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| Coze 可视化多智能体工作流 | 2 | 2 | 2 | 4 | 3 | 只能作为生态能力 |
| 动态学生知识状态 + 干预效果推荐 | 5 | 3 | 5 | 4 | 3 | 核心算法主线 |
| 可执行操作系统实验 + 过程证据诊断 | 4 | 5 | 5 | 4 | 3 | 核心学科主线 |
| 完全依赖大模型自主规划 | 3 | 2 | 1 | 2 | 5 | 不采用 |
| 继续增加资源类型和页面数量 | 1 | 2 | 2 | 5 | 2 | 停止堆叠 |

最终选择不是二选一，而是把第二、第三条组合：

```text
动态知识状态负责“理解学生现在会什么、还不确定什么”
干预策略负责“下一步给什么最可能有效”
操作系统实验负责“让学习过程产生高质量、可验证证据”
```

## 5. 旗舰创新：证据驱动的动态学习状态

### 5.1 从“画像标签”升级为“知识状态”

静态画像仍然保留，但不再直接等同于学习能力。每个知识点应维护一个随时间变化的状态：

```json
{
  "knowledgePointId": "OS-SCHEDULING",
  "masteryProbability": 0.62,
  "uncertainty": 0.18,
  "retentionRisk": 0.31,
  "evidenceCount": 7,
  "misconceptions": [
    {"code": "RR_RESPONSE_WAIT_CONFUSION", "probability": 0.71}
  ],
  "lastEvidenceAt": "2026-07-28T10:30:00+08:00",
  "evidenceSources": ["diagnostic", "quiz", "code_trace"]
}
```

不同证据权重应不同：

| 证据 | 建议可靠度 | 原因 |
| --- | --- | --- |
| 等价题后测 | 高 | 直接测量知识掌握 |
| 代码实验检查点与运行轨迹 | 高 | 能证明学生完成了关键操作 |
| 错题重练与延迟复习 | 高 | 能检验纠错和保持 |
| 辅导对话中的解释题 | 中 | 有信息但可能受提示影响 |
| 任务完成、阅读时长 | 中低 | 只能证明行为，不能证明学会 |
| 收藏、偏好、自述 | 低 | 适合表达偏好，不适合作为掌握证据 |

### 5.2 推荐技术路线

第一阶段采用可解释的小数据模型，不急于直接上深度知识追踪：

1. 使用 BKT 或 IRT/DINA 类模型建立可解释基线。
2. 将题目难度、知识点映射和是否受提示纳入观测。
3. 对掌握概率做校准，报告 Brier Score 或 Expected Calibration Error。
4. 当数据量达到要求后，再用 pyKT 对 DKT、DKVMN、GKT 等模型做离线对比。
5. 线上仍保留轻量模型和确定性降级，不把重模型放进每个 HTTP 请求。

不建议一开始就把神经知识追踪模型部署为线上唯一真相。比赛样本量较小，深度模型容易成为“引用论文但没有足够数据验证”的薄弱点。

## 6. 旗舰创新：学习干预效果推荐

### 6.1 推荐对象不再只是“内容”

A3 应把资源视为一次教学干预：

```text
同一个知识点
-> 概念讲解
-> 动画演示
-> worked example
-> 对比辨析题
-> 代码实验
-> AI 苏格拉底式追问
-> 错题间隔复习
```

推荐目标从“匹配度最高”升级为：

```text
预计学习增益
- 时间成本
- 认知负荷风险
- 重复内容惩罚
+ 低置信度下的安全探索价值
```

### 6.2 必须形成一次完整干预记录

```json
{
  "interventionId": "uuid",
  "studentStateVersion": 18,
  "knowledgePointId": "OS-VIRTUAL-MEMORY",
  "resourceId": "OS-LAB-002",
  "interventionType": "code_lab",
  "selectionPolicy": "a3-safe-bandit-v1",
  "selectionProbability": 0.64,
  "predictedGain": 0.12,
  "preTestForm": "VM-A-03",
  "postTestForm": "VM-B-02",
  "observedGain": 0.09,
  "delayedRetention": null,
  "completedAt": "..."
}
```

保存 `selectionProbability` 很重要，它使后续离线策略评估成为可能。没有选择概率和对照条件，只能说“相关”，不能轻易说“因果”。

### 6.3 安全探索，而不是拿学生做无约束实验

可以使用 contextual bandit 或 Thompson Sampling 的思想，但必须设置边界：

- 只在同一知识点、同一难度且均经过教师审核的资源中探索。
- 必修核心内容、考试前任务和高风险学生不随机。
- 每次探索都有默认优质资源兜底。
- 学生可跳过，教师可关闭探索。
- 数据不足时显示“探索性推荐”，不能伪装成精准结论。

## 7. 旗舰创新：可执行操作系统概念实验

### 7.1 为什么这是 A3 最有竞争力的学科差异

通用 AI 学习产品可以生成文档、题目和视频，但很难证明学生真正理解了操作系统中的动态过程。操作系统课程天然适合产生结构化过程证据：调度序列、页框变化、信号量状态、资源分配图、系统调用轨迹和内核源码执行路径。

建议把每个实验统一成五段式：

```text
先预测
-> 改参数或补代码
-> 运行模拟器 / 沙箱
-> 对照关键轨迹解释原因
-> 完成等价后测
```

### 7.2 优先建设的四个“概念显微镜”

| 实验 | 学生操作 | 自动采集证据 | 可诊断错误模式 |
| --- | --- | --- | --- |
| CPU 调度 | 配置到达、服务时间与时间片，预测甘特图 | 调度序列、等待/周转/响应时间 | 混淆等待时间与响应时间；错误理解抢占 |
| 页面置换 | 配置页框和访问串，预测缺页 | 页框快照、缺页次数、替换选择 | 把 FIFO 当 LRU；不了解 Belady 异常 |
| 同步与死锁 | 调整 P/V 顺序或资源请求 | 信号量、阻塞队列、资源分配图 | P/V 次序错误；混淆死锁与饥饿 |
| 系统调用/源码 | 阅读 xv6/Linux 片段并补检查点 | 编译结果、测试输出、调用轨迹 | 用户态/内核态边界错误；遗漏状态重置 |

### 7.3 与外部课程项目的正确关系

- 从 xv6、OSTEP、rCore、ProjectN 学习“逐步实验、最小内核、运行轨迹和测试驱动”的课程设计。
- 从 OS Simulator 类项目学习交互表达，但不复制其静态动画卡片。
- 从 `OS_course` 学习“源码片段 + 浏览器运行 + 进度写回”的组织方式。
- A3 的差异必须是：实验结果会更新知识状态、触发针对性解释并影响下一次推荐。

## 8. 双证据闭环

A3 可以把原有 Verifier 能力与新学习效果机制统一成“双证据闭环”。

### 8.1 内容证据闭环

```text
教材 / 讲义 / 实验文档
-> 多模态解析与检索
-> 生成资源
-> claim / citation / safety 验证
-> 有证据内容交付
```

解决的问题：系统讲的内容是否可信、是否有来源、是否泄露隐私或越权。

### 8.2 学习证据闭环

```text
诊断 / 行为 / 作答 / 实验轨迹
-> 知识状态估计
-> 教学干预选择
-> 等价后测与延迟复习
-> 学习增益和保持度
-> 下一轮状态与策略更新
```

解决的问题：这份资源是否真的帮助这个学生学会。

这两条闭环一起构成 A3 比普通 RAG 学习助手更强的答辩逻辑：既验证“内容对不对”，也验证“学生学没学会”。

## 9. GitCode 目标项目深度拆解

调研项目：[`trocedge/OS_course`](https://gitcode.com/trocedge/OS_course.git)  
调研快照：提交 `5f5f971a169689bf1b77aaf214ed855aa3ea3c53`，2026-07-20。

### 9.1 值得吸收的部分

| 机制 | 观察 | A3 可吸收方式 |
| --- | --- | --- |
| Linux 0.11 源码导学 | 对调度、fork、COW、路径解析等源码片段配置实验 | 建立受许可的源码实验目录，并映射 A3 知识点 |
| 浏览器代码实验 | C/C++ WASI Worker 与远程 Rust Playground | 优先支持轻量、安全、可复现的用户态模拟实验 |
| 可视化课件 | 按章节维护大量独立 HTML 可视化页面 | 转化为结构化实验组件，不把静态 HTML 数量当创新 |
| 混合检索 | Qwen Embedding、Qdrant、BM25、RRF | 与 A3 现有向量 + 关键词降级思路一致，可作为工程对照 |
| Artifact 审校 | 生成草稿先禁用，规则与 AI 审核后启用 | A3 可强化“生成后验证再交付”证据 |
| 测评写回 | Quiz 更新掌握度、画像、路径和推荐 | A3 已有同类闭环，应继续升级状态估计而不是照搬 |
| 教师与学生双端 | 班级、题库、作业和薄弱点统计 | A3 应进一步展示干预效果与置信度 |

### 9.2 不应吸收的部分

1. 仓库根目录未发现明确 `LICENSE`、`COPYING` 或 `NOTICE`，不能默认复制代码。
2. 仓库包含完整教材 PDF、习题解析和实验指导书，存在明显版权合规风险；不能复制到 A3 或比赛源码。
3. 其源码实验主要是人工精选片段和确定性输出检查，不等于自动学习诊断。
4. 掌握度更新仍以正确率、固定难度权重和作答次数置信度为主，适合作为工程基线，不是最终学习建模创新。
5. 大量独立静态 HTML 可视化页面维护成本高，容易形成“页面多但数据不回流”的问题。
6. 外部模型和基础设施较多，不应为了技术栈数量复制其部署复杂度。

### 9.3 结论

该项目最值得借鉴的是“源码实验与课程知识点结合”的产品形态；最需要避开的是许可证不明、教材直接入库和静态资源堆叠。A3 应重新实现机制，并用自己的数据闭环形成差异。

## 13. 可验证的评测体系

### 13.1 学生状态模型

| 指标 | 说明 |
| --- | --- |
| AUC / RMSE | 预测下一题正确率 |
| Brier Score | 概率预测误差，适合判断掌握概率是否可信 |
| ECE | 置信度校准情况 |
| Cold-start performance | 仅少量诊断数据时的表现 |
| Delayed prediction | 预测 7 天后保持情况 |

基线至少包括：

```text
全局正确率
当前 A3 固定加权正确率
BKT
IRT 或 DINA
候选深度 KT（仅离线）
```

### 13.2 推荐与干预

| 指标 | 说明 |
| --- | --- |
| Immediate gain | 等价前后测差值 |
| Normalized gain | 控制不同起点的增益指标 |
| Delayed retention | 3/7 天后复习正确率 |
| Time-to-mastery | 达到掌握阈值所需时间 |
| Completion / skip | 行为指标，只作为辅助 |
| Calibration by resource | 预计增益与实际增益的偏差 |

### 13.3 系统可信度

- 引用精确率与 citation-ready 覆盖率。
- 无证据内容被正确标记为未验证的比例。
- Agent/provider 超时后的降级成功率。
- 关键闭环接口成功率和 95 分位延迟。
- 教师干预送达率、学生响应率和后续学习效果。

### 13.4 消融实验

至少准备四组：

```text
A：通用推荐
B：仅静态画像推荐
C：画像 + 知识状态推荐
D：知识状态 + 干预效果 + 可执行实验（完整 A3）
```

对比学习增益、保持度、完成时间和推荐解释满意度。样本不足时可以做小规模用户实验并诚实报告置信区间，不应伪造大样本显著性。

## 14. 国奖答辩演示设计

### 14.1 最强的 3 分钟演示

1. 展示同一知识点下两个学生的不同状态：一个概念薄弱，一个会概念但不会运行分析。
2. A3 分别推荐短动画辨析和代码实验，并展示选择理由、预计增益和置信度。
3. 学生先预测 RR 调度结果，再运行实验；系统捕获等待时间/响应时间混淆。
4. 系统给出有教材引用的针对性解释，并推送两道等价后测。
5. 后测完成后，知识点掌握概率和不确定性变化，下一项任务随之调整。
6. 教师端看到本次干预证据、资源效果和是否需要人工介入。

### 14.2 评委追问时展示的证据

- 同一学生状态版本的输入证据。
- 推荐候选及评分依据，而不是只显示最后结果。
- 实验事件和后测记录。
- 状态更新前后差异。
- Agent trace、引用、模型/规则版本和降级状态。
- 离线评测指标与消融实验。

### 14.3 创新边界表述

可以说：

- “系统记录了资源干预后的学习增益，并用于下一轮排序。”
- “采用 BKT/IRT 等可解释模型作为知识状态估计基线。”
- “在受控资源集合中进行安全探索，并记录选择概率。”
- “在当前试验样本中观察到某项指标提升。”

不能在证据不足时说：

- “实现了严格因果推荐。”
- “全面精准预测每个学生。”
- “大模型能够自主替代教师。”
- “所有推荐都显著提升成绩。”

## 15. 分阶段实施路线

### P0：比赛主线收敛（优先级最高）

目标：先让现有能力形成一条可证明的创新演示。

- 统一操作系统知识点、资源、诊断题和实验映射。
- 建立 4 个概念实验的统一“预测-运行-解释-后测”协议。
- 为干预记录补齐学生状态版本、资源、前后测和结果字段。
- 准备 20-30 个等价题组，避免直接用重复题计算增益。
- 把“学习增益”明确标注为观察性或实验性证据。
- 完成 3 分钟主演示和技术追问证据链。

### P1：形成真正差异化机制

- 实现轻量 BKT 状态估计和置信度校准。
- 将当前固定规则与 BKT/IRT 基线做离线对比。
- 按知识点、学生状态和干预类型保存效果。
- 在审核资源中启用安全探索与默认优质资源兜底。
- 加入 3/7 天延迟复习，测保持度而非只测即时记忆。
- 教师端展示“学生状态不确定性”和“干预效果矩阵”。

### P2：研究型扩展

- 使用 pyKT 做 DKT、DKVMN、GKT 等离线基准。
- 研究知识图谱冷启动和跨章节迁移。
- 使用逆倾向加权等方法做离线策略评估。
- 扩展到跨课程，但保留操作系统完整样板课程。
- 评估 Coze 教师插件市场，不与核心运行时耦合。

## 16. 研发优先级与停止清单

未来一段时间优先投入：

```text
40% 状态估计、实验事件与效果评测
30% 操作系统可执行实验
20% 数据质量、等价题和教师审核
10% 答辩证据与交互打磨
```

暂缓：

- 新增更多大而全页面。
- 再增加一批职责重叠的 Agent。
- 把 Coze/Dify 部署到当前生产服务器。
- 继续扩充未标注知识点和版权状态的视频链接。
- 为“看起来高级”而接入深度模型，但没有训练集和基线。
- 继续把静态雷达图当作学生画像的主要创新证明。

## 17. 最终建议

A3 冲击国奖最稳妥的路径不是增加一个 Coze 工作流，也不是继续追求“什么都能生成”，而是把现有完整产品闭环压缩成一个更有研究和产品价值的问题：

> **系统如何知道一个学生下一步最需要哪种教学干预，并证明这次干预真的有效？**

动态知识状态给出“学生现在在哪里”，干预策略给出“下一步做什么”，可执行操作系统实验提供“高质量过程证据”，前后测与延迟复习回答“是否真的学会”。A3 已有事件、推荐、RAG、Agent 和教师端，可以在现有基础上完成这次升级，不需要推翻重做。

Coze 可以作为开放生态和教师插件能力出现，但核心状态、策略、验证和学习效果必须由 A3 自己掌握。这样既能保留工程完整度，也能形成评委难以用“套壳”反驳的创新证据。
